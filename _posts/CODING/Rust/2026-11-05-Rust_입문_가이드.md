# Rust 입문 가이드

> 업데이트: 2026-11-05 · 대상: Rust를 처음 접하는 개발자

## Rust란?

Rust는 성능과 메모리 안전성을 함께 추구하는 범용 프로그래밍 언어입니다. 시스템 도구, 서버 프로그램, 명령줄 앱, 임베디드 소프트웨어처럼 빠르고 안정적인 실행이 중요한 곳에서 사용됩니다. 컴파일러가 소유권(ownership)과 타입 규칙을 검사해 많은 메모리 오류를 실행 전에 찾아냅니다. 대신 처음에는 소유권과 빌림(borrowing) 개념을 익히는 데 시간이 듭니다.

## 왜 요즘 자주 이야기될까?

Rust의 안정판은 정기적으로 개선되고, 2025년 2월 Rust 1.85에서 Rust 2024 에디션이 정식 안정화되었습니다. Rust 2024는 새 언어 버전 이름이며, 프로젝트의 `Cargo.toml`에서 선택합니다. 최근 Rust가 주목받는 배경에는 성능, 메모리 안전성, Cargo 기반의 편리한 빌드·의존성 관리가 있습니다. 다만 “유행”은 분야와 조직마다 다르므로 모든 프로젝트에 Rust가 최선이라는 뜻은 아닙니다.

많이 살펴보는 분야:

- **시스템·인프라**: 빠른 런타임, 네트워크 도구, 파일 처리
- **명령줄 도구**: 단일 실행 파일로 배포하기 쉬운 개발 도구
- **서버·웹 백엔드**: 처리량과 자원 사용량이 중요한 서비스
- **임베디드**: 자원이 제한된 기기와 마이크로컨트롤러
- **WebAssembly**: 브라우저나 WASM 런타임에서 실행할 모듈

## 설치와 버전 확인

Windows에서는 [Rust 공식 설치 안내](https://rust-lang.org/tools/install/)에 따라 `rustup-init.exe`를 설치합니다. `rustup`은 Rust 도구 체인을 관리하고, Cargo도 함께 설치합니다. 설치 후 터미널을 새로 열고 확인합니다.

```powershell
rustc --version
cargo --version
rustup --version
```

`rustc`는 컴파일러, `cargo`는 빌드·패키지 관리 도구, `rustup`은 버전/컴포넌트 관리 도구입니다.

## 자주 쓰는 명령어

| 명령어 | 용도 |
|---|---|
| `cargo new hello_rust` | 새 실행 프로그램 프로젝트 생성 |
| `cargo new my_lib --lib` | 새 라이브러리 프로젝트 생성 |
| `cargo run` | 컴파일하고 실행 |
| `cargo check` | 실행 파일을 만들지 않고 빠르게 오류 확인 |
| `cargo build` | 개발용 빌드 (`target/debug`) |
| `cargo build --release` | 최적화 빌드 (`target/release`) |
| `cargo test` | 테스트 실행 |
| `cargo fmt` | 코드 서식 정리 (`rustfmt` 필요) |
| `cargo clippy` | 흔한 실수와 개선점 점검 (`clippy` 필요) |
| `cargo add serde` | 의존성 추가 (Cargo 버전에 따라 제공) |
| `cargo doc --open` | 문서 생성 후 브라우저에서 열기 |
| `rustup update` | 설치된 도구 체인 업데이트 |
| `rustup doc` | 로컬 문서 열기 |

도구가 없다면 `rustup component add rustfmt clippy`로 추가할 수 있습니다. 자세한 옵션은 `cargo help run` 또는 `cargo --help`로 확인합니다.

## 첫 프로그램 실행

```powershell
cargo new hello_rust
cd hello_rust
cargo run
```

Cargo가 만든 `src/main.rs`의 기본 코드는 다음과 같습니다.

```rust
fn main() {
    println!("안녕하세요, Rust!");
}
```

`Cargo.toml`은 프로젝트 설정과 의존성을 기록합니다. `src/main.rs`는 실행 프로그램의 시작점입니다. 라이브러리를 만들면 보통 `src/lib.rs`를 사용합니다.

## 핵심 문법 한눈에 보기

```rust
fn greet(name: &str) -> String {
    format!("안녕하세요, {name}!")
}

fn main() {
    let language = "Rust";       // 기본은 불변
    let mut count = 0;            // 변경하려면 mut
    count += 1;

    let message = greet(language);
    println!("{message} ({count})");

    let score = 87;
    let grade = if score >= 80 { "통과" } else { "다시 도전" };
    println!("결과: {grade}");
}
```

- `let`은 기본적으로 값을 바꾸지 못하게 합니다. 바꿔야 할 때만 `mut`를 붙입니다.
- 함수 인자와 반환값의 타입을 명시합니다. `-> String`은 반환 타입입니다.
- `String`은 소유 가능한 문자열이고, `&str`은 문자열을 빌려 읽는 타입으로 자주 사용합니다.
- `if`는 표현식이므로 각 갈래가 같은 타입의 값을 만들 수 있습니다.

## 소유권과 빌림: Rust의 핵심

값은 한 시점에 소유자가 하나입니다. 소유자가 범위를 벗어나면 자원이 정리됩니다. 값을 넘겨주면 소유권이 이동할 수 있습니다. 읽기만 할 때는 참조로 빌려주면 소유권을 넘기지 않습니다.

```rust
fn print_length(text: &str) {
    println!("길이: {}", text.len());
}

fn main() {
    let message = String::from("Rust");
    print_length(&message); // 빌려주므로 message를 계속 사용할 수 있음
    println!("{message}");
}
```

컴파일러가 빌림 규칙을 검사합니다. 처음에는 “값을 누가 소유하는가?”, “이 함수는 소유권이 필요한가, 참조만 필요한가?”를 따라가면 도움이 됩니다.

## 오류와 컬렉션의 기본 패턴

Rust는 실패 가능성을 `Option<T>`(값이 있을 수도 없음)와 `Result<T, E>`(성공 또는 오류)로 표현합니다. 오류를 무시하지 말고 `match`, `?`, 또는 적절한 처리로 다룹니다.

```rust
use std::fs;

fn read_config() -> Result<String, std::io::Error> {
    let contents = fs::read_to_string("config.txt")?;
    Ok(contents)
}

fn main() {
    match read_config() {
        Ok(text) => println!("{text}"),
        Err(error) => eprintln!("파일을 읽지 못했습니다: {error}"),
    }
}
```

자주 쓰는 컬렉션은 `Vec<T>`(목록), `String`(변경 가능한 UTF-8 문자열), `HashMap<K, V>`(키-값 맵)입니다. 외부 라이브러리는 crates.io에서 찾고, 프로젝트의 `Cargo.toml`에 선언합니다.

## 패키지, 크레이트, 모듈의 차이

세 용어는 코드의 크기와 역할을 나누어 생각하면 쉽습니다.

| 개념 | 의미 | 비유 |
|---|---|---|
| **패키지 (package)** | Cargo가 빌드·테스트·배포하는 단위. 루트에 `Cargo.toml`이 있습니다. | 프로젝트 상자 |
| **크레이트 (crate)** | 컴파일러가 한 번에 컴파일하는 단위. 실행 파일(binary) 또는 라이브러리(library)를 만듭니다. | 상자 안의 프로그램/라이브러리 |
| **모듈 (module)** | 크레이트 내부 코드를 이름 공간과 공개 범위에 따라 나누는 단위입니다. | 코드의 폴더/구획 |

패키지 하나에는 여러 바이너리 크레이트와 라이브러리 크레이트 하나(선택 사항)를 둘 수 있습니다. `src/main.rs`는 기본 바이너리 크레이트의 시작점이고, `src/lib.rs`가 있으면 라이브러리 크레이트의 루트가 됩니다. `src/bin/` 아래에 실행 파일을 추가할 수도 있습니다. 즉, 패키지와 크레이트는 같은 뜻이 아닙니다.

### 모듈로 파일 나누기

간단한 프로젝트 구조 예시입니다.

```text
my_app/
├── Cargo.toml
└── src/
    ├── main.rs
    └── front_of_house.rs
```

`src/main.rs`에서 모듈을 선언하고 사용합니다.

```rust
mod front_of_house; // front_of_house.rs 파일의 모듈을 연결

fn main() {
    crate::front_of_house::hosting::seat_at_table();
}
```

`src/front_of_house.rs`의 내용입니다.

```rust
pub mod hosting {
    pub fn seat_at_table() {
        println!("자리에 안내합니다.");
    }
}
```

`mod`는 모듈을 선언하고, `pub`는 부모 모듈 바깥에서도 쓸 수 있도록 공개합니다. `crate::`는 현재 크레이트의 루트에서 시작하는 경로입니다. 기본 항목은 비공개이므로 다른 모듈에서 접근해야 하는 모듈·함수에는 필요한 위치마다 `pub`를 붙입니다.

긴 경로는 `use`로 가져와 짧게 쓸 수 있습니다.

```rust
mod front_of_house;
use crate::front_of_house::hosting;

fn main() {
    hosting::seat_at_table();
}
```

모듈을 반드시 별도 파일로 만들 필요는 없습니다. 작은 코드는 `mod name { ... }`처럼 파일 안에 정의할 수 있고, 프로젝트가 커지면 `name.rs` 또는 `name/mod.rs` 구조로 분리할 수 있습니다.

공식 설명: [Packages and Crates](https://doc.rust-lang.org/book/ch07-01-packages-and-crates.html), [Modules](https://doc.rust-lang.org/book/ch07-02-defining-modules-to-control-scope-and-privacy.html), [Cargo 패키지 구조](https://doc.rust-lang.org/cargo/guide/project-layout.html).

## 추천 작업 흐름

1. `cargo new`로 프로젝트를 만듭니다.
2. 작은 단위로 코드를 작성하고 `cargo check`로 빠르게 확인합니다.
3. `cargo fmt`로 정리하고 `cargo clippy`로 점검합니다.
4. 동작을 `cargo run`으로 확인하고 `cargo test`로 테스트합니다.
5. 배포할 때 `cargo build --release`를 사용합니다.
