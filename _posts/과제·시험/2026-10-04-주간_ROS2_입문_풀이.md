## 1. 연속적인 센서 데이터를 퍼블리시할 때의 통신 방식

정답: 토픽(Topic)

- 퍼블리셔가 토픽에 메시지를 계속 발행하고, 서브스크라이버가 이를 구독하는 비동기 단방향 publish/subscribe 방식이다.
- 응답을 기다리지 않으므로 카메라, 라이다, IMU처럼 주기적으로 계속 나오는 데이터에 적합하다.

## 2. Action 통신의 구성 요소가 아닌 것

정답: 4) Timeout

- 액션은 Goal(목표 요청), Feedback(진행 상황), Result(최종 결과)로 이루어지며, Action Client가 목표를 보내고 Action Server가 처리한다.
- Timeout은 액션 인터페이스의 구성 요소가 아니다.

## 3. 서비스(Service)의 특징

정답: 4) 요청과 응답을 한 쌍으로 처리하는 통신 방식이다.

- 1) 지속적인 스트리밍은 토픽의 특징이다.
- 2) 비동기 단방향은 토픽의 특징이다. 서비스는 요청-응답의 양방향이다.
- 3) 오래 걸리는 작업을 피드백과 함께 처리하는 것은 액션이다.
- 5) 퍼블리셔와 서브스크라이버는 토픽의 구성이다.

## 4. ROS2가 ROS1과 다른 점

정답: 5) ROS2는 노드끼리 자동으로 서로를 찾아 통신할 수 있다.

- ROS2는 DDS 기반으로 Master(roscore) 없이 디스커버리를 통해 노드가 서로를 자동으로 찾는다.
- 1) Master가 필요한 것은 ROS1이다.
- 2), 3) ROS2는 Linux, Windows, macOS를 지원한다. 오히려 ROS1이 사실상 Linux 중심이다.
- 4) 통신 미들웨어(DDS), 구조, QoS 등에서 큰 차이가 있다.

## 5. rclpy의 구성 요소가 아닌 것

정답: 5) 라우터

- rclpy는 노드, 퍼블리셔/서브스크라이버, 서비스/클라이언트, 액션, 타이머, 실행기(Executor) 등을 제공한다.
- 라우터는 네트워크 장비 개념으로 rclpy의 구성 요소가 아니다.

## 6. ROS2 계층 구조가 아닌 것

정답: 5) ros_core

ROS2 계층 구조

```text
User code (사용자 애플리케이션)
    |
Client Library (rclpy, rclcpp)
    |
rcl (ROS Client Library, C 공통 구현)
    |
rmw (ROS Middleware Interface)
    |
Middleware (DDS 구현체: Fast DDS, Cyclone DDS 등)
```

- ros_core는 ROS2 계층에 없다. (ROS1의 roscore를 떠올리게 하는 오답 보기)

## 7. Executor 동작 과정 3가지

1. 대기(Wait): 노드에 등록된 구독, 타이머, 서비스, 클라이언트 등을 wait set에 모아 두고, 메시지 도착이나 타이머 만료 같은 이벤트가 생길 때까지 기다린다.
2. 선택(Select): 이벤트가 생겨 실행 준비가 된(ready) 항목을 확인하고, 실행할 콜백을 고른다.
3. 실행(Execute): 고른 콜백 함수를 실행한다. 실행이 끝나면 다시 1단계 대기로 돌아가며, rclpy.spin()은 이 과정을 종료될 때까지 반복한다.
