  📘 과제_ROS2입문_2차시 (인터페이스 패키지)

  1. 계약서가 정하는 것은 칸 이름과 칸 타입 두 가지입니다. 이름만 같고 타입이 다르면 같은 count를 한쪽은 정수로, 다른
  쪽은 글자로 다뤄 결국 어긋납니다.
  "leo,5.0,2.0,1.5"처럼 보내면 받는 쪽이 콤마로 자르고, 순서를 외우고, 글자를 숫자로 바꿔야 합니다. 순서를 하나만 잘못
  알아도 좌표 칸에 속도가 들어갑니다. 이 버그는 에러도 경고도 없이 거북이가 엉뚱하게 움직이기만 해서 단서가 없습니다.
  그래서 추적이 유난히 괴롭습니다.

  2. Spawn 인터페이스는 「어디에 어떤 이름으로 한 마리를 낸다」는 
  3.칸과 그 타입만 정해 둔 빈 신청서입니다. 좌표가 5.0인지
  2.0인지, 이름이 leo인지 max인지는 부를 때마다 채우는 값입니다.
  받는 쪽은 타입이 없으면 5.0이 숫자인지 글자인지 알 수 없습니다. int64·float64처럼 타입을 적어 두면 그 판단이 미리
  끝납니다. 잘못된 값(예: float64 칸에 글자)도 그 자리에서 걸러집니다.

  3.
  - ament_cmake인 까닭: 양식에서 파이썬·C++ 코드를 찍어 내는 rosidl 코드 생성은 CMake 빌드 단계 안에서만 돕니다.
    ament_python 패키지에 넣으면 빌드는 통과해도 타입이 생성되지 않습니다.
  - 별도 패키지인 까닭: 공장을 따로 두면 파이썬 노드, C++ 노드, 나중에 만들 패키지가 모두 이 공장 하나에만 의존하면
    됩니다. 노드 패키지에 묻어 두면 양식 한 장이 필요한 쪽이 남의 노드 코드까지 통째로 끌어와야 합니다.
  - 재빌드 범위: 노드 코드를 고쳐도 양식 패키지는 다시 빌드하지 않습니다. 양식을 바꿀 때만 그 양식에 기댄 노드를 다시
    빌드하므로, 변경이 퍼지는 범위가 깔끔하게 갈립니다.

  4.

  ┌─────────┬────────────────────────┬───────────────────────────────────────────────────────────────┐
  │  양식   │         구분선         │                             비유                              │
  ├─────────┼────────────────────────┼───────────────────────────────────────────────────────────────┤
  │ .msg    │ 0개                    │ 라디오 방송: 한 방향으로, 듣는 사람이 있든 없든 계속 흘려보냄 │
  ├─────────┼────────────────────────┼───────────────────────────────────────────────────────────────┤
  │ .srv    │ 1개 (요청/응답)        │ 전화 문의: 한 번 묻고 한 번 답이 오면 끝                      │
  ├─────────┼────────────────────────┼───────────────────────────────────────────────────────────────┤
  │ .action │ 2개 (목표/결과/피드백) │ 택배 배송: 중간 알림이 오고, 도중에 취소할 수 있음            │
  └─────────┴────────────────────────┴───────────────────────────────────────────────────────────────┘

  양식을 고르는 두 물음은 ① 응답이 필요한가 → ② 즉시 끝나는가 순서입니다.

  5.
  - 필드: 통신할 때 값이 채워지는 칸입니다. float64 speed처럼 소문자와 언더스코어로 씁니다.
  - 기본값: float64 speed 1.0처럼 이름 뒤에 값을 적습니다. 비워 두면 그 값으로 채워집니다.
  - 상수: int8 STATE_IDLE=0처럼 대문자와 언더스코어로 쓰고 =로 값을 붙입니다. 양식에 못 박힌 고정 값입니다.
  - 기본값 제약: 숫자·참거짓·글자 한 줄 같은 단순한 칸에만 줄 수 있습니다. 글자 배열이나 다른 양식을 끌어다 쓴 복합 타입
    칸에는 줄 수 없습니다.
  - 상수의 원칙: 코드에 2가 박혀 있으면 뜻을 알 수 없지만 STATE_ERROR라고 적혀 있으면 한눈에 읽힙니다. 상수는 「이름이
    곧 설명서」라는 원칙을 값에까지 넓힌 것입니다.

  6.
  - CMakeLists.txt 세 묶음:
    - find_package(rosidl_default_generators REQUIRED): 코드 생성기를 꺼냅니다.
    - rosidl_generate_interfaces(${PROJECT_NAME} ...): 이 목록의 양식을 찍으라고 지시합니다.
    - ament_export_dependencies(rosidl_default_runtime): 쓰는 쪽에 런타임을 딸려 보냅니다.
  - package.xml 세 줄:
    - <buildtool_depend>rosidl_default_generators</buildtool_depend>
    - <exec_depend>rosidl_default_runtime</exec_depend>
    - <member_of_group>rosidl_interface_packages</member_of_group>
  - 줄 수가 여섯을 넘는 까닭: 「여섯」은 묶음 단위로 센 관용어입니다. rosidl_generate_interfaces(...) 하나가 양식 목록
    때문에 여러 줄을 차지합니다.
  - 양식을 한 장 더할 때 고치는 곳: rosidl_generate_interfaces 생성 목록에 새 양식 경로를 한 줄 더합니다.

  7.
  - <buildtool_depend>: 빌드할 때만 필요합니다. 예: 코드 생성기 rosidl_default_generators.
  - <exec_depend>: 실행할 때만 필요합니다. 예: 런타임 rosidl_default_runtime.
  - <depend>: 빌드할 때도 실행할 때도 필요합니다. 위 둘을 한꺼번에 적는 줄임 표기입니다.

  DEPENDENCIES를 빼면 코드를 찍는 단계가 끌어쓴 타입을 찾지 못해 빌드가 실패합니다. <depend>를 빼도 빌드가 성공하는 것은 내 컴퓨터에 그 패키지가 이미 깔려 있어 우연히 넘어간 것뿐입니다. 성공하는 쪽이 더 위험한 까닭은 빠뜨린 줄도 모르고 넘어가기 때문입니다. 그러면 양식 패키지를 받아 쓸 다음 사람의 환경이나 빌드 순서에서 문제가 터집니다.

  8. 양식을 고치면 그 양식에 기댄 노드를 전부 다시 빌드해야 합니다. 한쪽만 새로 빌드하면 두 노드가 서로 다른 모양을 기대합니다. 이름이나 타입을 바꾸면 그 칸을 읽던 코드까지 손봐야 합니다.

  안전한 변경을 위한 두 원칙:
  양식 칸을 지우거나 이름·타입을 바꾸는 일은 최대한 피합니다.
  양식칸을 더해야 한다면 있던 칸은 건드리지 말고 뒤에 새 칸을 붙입니다.

  빌드 확인 명령:
  ros2 interface show my_interfaces/msg/TurtleGoal
  ros2 interface list | grep my_interfaces

  📗 과제_ROS2입문_4차시 (실행기 · 콜백그룹 · launch)

  10. spin 한 바퀴는 ① 수집(준비된 일감 확인) → ② 선택(하나를 꺼냄) → ③ 실행(콜백 호출·완료) → ④ 반복(수집으로
  복귀)입니다.
  막힘은 ③ 실행 걸음에서 생깁니다. 콜백이 2초 동안 실행에 머물러 있으면 수집으로 돌아가지 못하므로, 다른 일감이
  준비됐는지 확인하는 일 자체가 멈춥니다.
  놓친 타이머 차례는 나중에 몰아서 처리되지 않고 사라집니다. slow가 끝난 뒤 fast tick은 한 줄만 나옵니다.

  11. 창구가 하나인 까닭은 두 가지입니다.
  12. 어느 순간에도 콜백이 하나만 실행되므로 경쟁 상태가 처음부터 없습니다.
  13. 실행 순서가 한 줄로 늘어서 동작을 예측하고 추적하기 쉽습니다.

  권장 순서: 기본값으로 옳게 만들고, 막힘이 실제로 문제가 될 때에만 창구를 늘립니다.

  14. 콜백그룹은 「이 콜백들을 동시에 돌려도 되는가」를 실행기에 알리는 표식입니다.
  callback_group을 한 번도 주지 않으면 모든 콜백이 노드의 기본 그룹 하나에 들어갑니다. 그 그룹은 배타적이라서, 실행기만
  MultiThreadedExecutor로 바꿔도 콜백이 한 번에 하나씩 돌고 여전히 막힙니다.

  15. 막힘을 푸는 두 조건은 ① 창구가 여럿(MultiThreadedExecutor)이고 ② 콜백이 서로 다른 그룹에 있는 것입니다.
  - 창구는 여럿인데 그룹은 안 나눈 경우: 두 콜백이 같은 기본(배타적) 그룹에 있어 한 줄로 세워집니다.
  - 그룹은 나눴는데 창구가 하나인 경우: 그룹이 갈려 있어도 나눠 줄 일손이 하나뿐입니다.

  5. 재진입 그룹은 같은 콜백이 자기 자신과도 겹쳐 돌게 허락합니다. 주기와 걸리는 시간이 같으면 앞 실행이 끝나기 전에 다음 실행이 시작돼 같은 함수가 겹겹이 쌓일 수 있습니다. 새 배타적 그룹으로 빼면 각 콜백 안에서는 여전히 한 번에 하나라는 안전을 지키면서 막힘만 풀립니다. 필요한 만큼만 여는 쪽이 낫습니다.

  그룹을 정하는 세 물음:
  다른 콜백과 같은 변수·파일·하드웨어를 건드리는가? 그렇다면 둘을 같은 배타적 그룹에 둡니다.
  같은 노드의 다른 콜백을 동기 방식으로 호출하는가? 그렇다면 데드락 위험이 있으니 부르는 쪽과 응답하는 쪽을 다른 그룹으로 가릅니다.
  둘 다 아니고 겹쳐 돌아도 무방한가? 그렇다면 새 배타적 그룹으로 뺍니다. 자기 자신과 겹쳐도 될 만큼 독립적이면 그때 재진입을 고려합니다.

  6 로깅을 쓰는 까닭은 두 가지입니다.
   시각·노드 이름·등급이 자동으로 붙어서, 여러 노드의 말이 섞여도 누가 한 말인지 가려집니다.
  등급 문턱으로 평소에는 일정 등급 위만 흘리다가, 문제를 쫓을 때만 아래 등급까지 열 수 있습니다. print는 전부 나오거나 전부 지우거나 둘뿐입니다.

  - 등급 (낮은 것부터): DEBUG < INFO < WARN < ERROR < FATAL
  - 기본 문턱: INFO 이상만 화면에 흐릅니다.
  - 특정 노드만 debug까지 켜는 명령:
  ros2 run my_py_pkg my_publisher --ros-args --log-level my_publisher:=debug

  7. launch 대본이 필요한 까닭은 세 가지입니다.
  노드 수가 많아지면 사람이 손으로 감당할 수 없습니다.
  어떤 노드를 어떤 차례·설정으로 켰는지 적어 두면 누가 언제 실행해도 같은 시스템이 뜹니다(재현).설정이 파일 한곳에 모입니다.

  ┌──────────────────────┬─────────────────────────┬─────────────────────┐
  │         기준         │        ros2 run         │     ros2 launch     │
  ├──────────────────────┼─────────────────────────┼─────────────────────┤
  │ 한 번에 켜는 노드 수 │ 하나                    │ 여럿                │
  ├──────────────────────┼─────────────────────────┼─────────────────────┤
  │ 설정                 │ 매번 명령어에 직접 입력 │ 파일에 미리 적어 둠 │
  └──────────────────────┴─────────────────────────┴─────────────────────┘

  ros2 launch는 소스 폴더가 아니라 install/의 share 폴더에서 launch 파일을 찾습니다. 코드가 아닌 launch 파일은 data_files에 등록해야 거기로 복사됩니다. 등록하지 않으면 colcon build는 성공하고, ros2 launch를 실행할 때 비로소 file '...' was not found in the share directory 오류가 납니다.

  8.
  - ROS_DOMAIN_ID: 망 자체를 통째로 가르는 칸막이입니다. 번호가 다르면 아예 서로를 발견하지 못합니다.
  - 리매핑: 같은 망 안에서 토픽 이름을 하나씩 갈아 끼웁니다. 서로 보이지만 이름이 달라 섞이지 않습니다.
  - 네임스페이스: 노드와 그 노드의 토픽까지 통째로 한 칸 아래로 옮깁니다.

  예를 들어 robot:=r2로 켜면 노드 이름이 /r2/my_publisher가 되고, 토픽도 /chatter에서 **/r2/chatter**로 함께 옮겨
  갑니다.
