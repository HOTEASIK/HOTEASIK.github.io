# 개인 비서 모델 파인 튜닝: 진행 방법과 데이터 준비

## 추천 구성

현재 장비가 **RTX 3060 Ti 8GB VRAM**이고 목적이 개인 문서 질의와 말투/행동 스킬 적용이므로, 다음 구조를 권합니다.

1. **Hugging Face 형식의 작은 지시형 모델 + Python 추론**을 먼저 구성합니다.
2. 말투·행동 스킬 문서는 우선 시스템 지침으로 읽어 적용합니다. 지침을 고치기 쉽고, 작은 데이터로 과하게 학습해 일반 응답 능력이 흔들리는 일을 줄일 수 있습니다.
3. 개인 문서는 검색(RAG) 인덱스에 넣고, 질문과 관련된 부분만 찾아 모델에게 함께 전달합니다. 문서가 바뀌어도 인덱스만 갱신할 수 있습니다.
4. 실제 대화에서 시스템 지침만으로 지켜지지 않는 반복 행동이 관찰되면, 그 행동을 보여주는 고품질 예시를 모아 LoRA/QLoRA SFT를 추가합니다.

- 학습은 Transformers와 TRL의 `SFTTrainer`를 중심으로 구성하고, PEFT의 LoRA/QLoRA로 학습 가능한 파라미터와 메모리 부담을 줄입니다.
- 먼저 원본 모델을 그대로 Python에서 실행해 본 뒤, 같은 질문 묶음으로 파인 튜닝 전후를 비교합니다.
- 첫 단계에서는 GGUF 변환을 하지 않습니다. Python/Transformers 실행에 성공한 다음, 필요할 때 별도 변환을 검토합니다.
- GPU에서 QLoRA 4-bit, micro-batch 1, 짧은 시퀀스 길이(예: 우선 512 토큰)로 시작하고 gradient checkpointing 등을 검토합니다. 8GB는 학습 중 모델 외에도 활성화값과 CUDA 여유 메모리가 필요하므로 실제 사용량에 따라 더 낮은 길이/더 작은 모델로 내려야 할 수 있습니다. 이는 시작점이지 보장된 설정은 아닙니다.
- 모델 후보는 우선 Qwen3-0.6B 같은 작은 모델로 설치/데이터/실행 파이프라인을 확인하고, 한국어 품질이 부족하면 1B~2B급 후보를 짧은 데이터로 시험합니다. 1.7B 모델도 8GB에서 무조건 학습된다고 보장할 수 없으므로 짧은 시퀀스와 batch 1의 메모리 시험 후 결정합니다. 모델 카드의 라이선스와 템플릿도 확인합니다.

TRL은 대화형 데이터에서 `messages` 형식을 지원하고 모델의 chat template으로 대화를 구성합니다. 사용자 입력과 assistant 응답의 역할을 일관되게 보존해야 합니다. [TRL SFTTrainer 문서](https://huggingface.co/docs/trl/sft_trainer) · [Transformers chat template 문서](https://huggingface.co/docs/transformers/main/chat_templating)

## 작업 순서

1. **Docker/WSL2 GPU 확인**: Docker Desktop의 WSL2 backend와 NVIDIA GPU passthrough가 활성인지 확인합니다. 컨테이너에서 `nvidia-smi`가 동작해야 합니다.
2. **재현 가능한 Linux 컨테이너 준비**: 프로젝트용 Dockerfile에 Python과 학습 패키지를 고정하고, 데이터/모델/출력 폴더는 컨테이너 외부에 마운트합니다.
3. **기반 모델 선정**: 한국어 품질, 대화용 여부, 사용 라이선스, 메모리 요구량을 비교합니다. 우선 0.6B급 후보로 파이프라인을 확인합니다.
4. **기준 성능 기록**: 원하는 비서 질문 20~50개를 준비해 원본 모델의 답변을 저장합니다.
5. **데이터 정리**: 개인 정보와 비밀을 제거하고, 문서용 RAG 자료와 행동 학습 예시를 분리합니다.
6. **학습/검증 분리**: 유사 예시와 같은 원문 문서에서 나온 예시가 양쪽에 섞이지 않도록 분리합니다. 검증 자료는 학습에 넣지 않습니다.
7. **소규모 시험 학습**: QLoRA, batch 1, 짧은 시퀀스로 메모리 사용과 학습 파이프라인을 확인합니다.
8. **본 학습 및 저장**: 어댑터 체크포인트, 학습 설정, 토크나이저 및 기준 모델 정보를 보존합니다.
9. **Python 추론 연결과 평가**: 모델/토크나이저, 스킬 지침, 검색된 문서 청크를 결합해 응답하고, 말투·지시 이행·근거 정확성을 비교합니다.
10. **선택 사항: 내보내기**: Python에서 품질을 확정한 뒤 별도 실행 엔진이 필요하면 변환을 검토합니다. 원본 학습 폴더는 보존합니다.

## Markdown 자료를 학습 데이터로 바꾸는 방법

### 개인 문서 여러 개를 쓰는 경우

Markdown 파일 여러 개는 기본적으로 파인 튜닝에 넣지 말고, 파일 단위로 검색 인덱스에 추가합니다. 제목/경로/출처를 메타데이터로 남기고, 검색 결과의 원문 일부를 사용자 질문과 함께 모델에 전달해 답변하게 합니다. 문서가 갱신되면 해당 문서만 재색인합니다. 답변에는 가능하면 파일명/제목 등 근거 출처를 표시하게 합니다.

문서 내용 자체를 모델의 학습 행동으로 가르치려는 경우에만 질문-답변 예시로 변환해 SFT에 넣습니다. 원문을 그대로 학습해도 모델이 문서 검색이나 출처 인용을 자동으로 수행하게 되지는 않습니다.

### 긴 개인 문서를 청크로 나누는 경우

검색에 쓸 긴 파일은 제목/문단 경계를 우선해 청크로 나누되, 문맥이 끊기지 않도록 제목과 필요한 정의를 포함합니다. 청크마다 출처 파일과 제목 경로를 보존하고 검색 시 관련 청크만 가져옵니다. 청크 길이는 문서 구조와 검색 방식에 따라 조절하며, 처음부터 한 가지 길이를 고정하지 말고 대표 질문으로 검색 결과를 확인합니다.

### 말투·행동 스킬 문서

말투/행동 규칙은 별도의 `persona.md` 또는 `skills/` 문서로 관리합니다. 예를 들어 말투, 확인 질문을 해야 하는 경우, 모르는 사실을 다루는 법, 답변 형식, 금지 행동을 짧은 규칙과 예시로 명시합니다. Python 프로그램은 시작 시 해당 지침을 system 메시지에 넣습니다. 여러 스킬을 둘 경우 질문 유형과 맞는 스킬만 선택해 주입합니다.

스킬 문서를 시스템 지침으로 적용하는 것과 파인 튜닝은 서로 대체 관계가 아닙니다. 먼저 지침을 적용해 효과를 보고, 반복해서 어기는 행동이 명확할 때 그 행동에 대한 좋은/나쁜 예시를 정리해 SFT를 검토합니다. 개인 비서가 자신의 파일 시스템이나 앱에 실제 작업을 수행하게 하려면, 문서 학습만으로는 충분하지 않고 권한을 제한한 도구 호출/실행 로직을 별도로 구현해야 합니다.

**권장 분담:** 개인 문서 지식은 RAG, 말투/행동 지침은 system/skill 문서, 지침만으로 안정화되지 않는 반복 응답 패턴은 선택적인 LoRA SFT로 나눕니다. 최신/변경 정보는 모델 가중치보다 검색 원문을 갱신하는 편이 관리하기 쉽습니다.

## 권장 데이터 형식

한 줄에 하나의 JSON 객체를 저장하는 JSONL 형식의 예입니다. 실제 메시지는 한국어로 작성하고, assistant가 원하는 최종 답을 명확히 제공합니다.

```json
{"messages":[{"role":"system","content":"너는 사용자의 개인 비서다. 모르는 내용은 추측하지 말고 확인 질문을 한다."},{"role":"user","content":"회의 내용을 요약해줘."},{"role":"assistant","content":"핵심 결정, 할 일, 담당자 순으로 정리할게요. 회의 기록을 보내주세요."}]}
{"messages":[{"role":"user","content":"내일 일정이 뭐야?"},{"role":"assistant","content":"일정표를 확인할 수 있는 자료가 아직 없어요. 캘린더 연동이나 일정 파일을 제공해 주세요."}]}
```

system 메시지는 모델/템플릿이 이를 지원하는 방식인지 확인하고 적용합니다. 답변에 불필요한 역할극, 상충하는 규칙, 실제 개인 정보가 섞이지 않게 합니다. 사람 이름·주소·계정·일정 등 민감정보는 삭제하거나 가명 처리하고, 학습 자료의 사용 권리를 확인합니다.

## 파인 튜닝과 검색(RAG) 선택 기준

| 원하는 효과 | 우선 검토할 방법 |
|---|---|
| 개인 문서 여러 개에서 근거를 찾아 답하기 | RAG/검색 |
| 자주 바뀌는 자료를 반영 | 문서 인덱스 갱신 |
| 말투, 답변 형식, 행동 규칙을 빠르게 고치기 | system/skill Markdown 지침 |
| 지침만으로 해결되지 않는 반복 응답 패턴 | 잘 작성된 대화 예시로 LoRA SFT 후 평가 |

## 실행 스크립트 작성 전 필요한 정보

- GPU 모델명과 VRAM 용량: **RTX 3060 Ti, 8GB** (확인됨)
- Windows 환경에서 WSL2 사용 가능 여부
- 학습 데이터의 대략적인 파일 수/용량과 민감정보 포함 여부
- 원하는 비서 기능: **개인 문서 질의 + 말투/행동 스킬 문서** (확인됨)

실행 경로는 **Docker Desktop + WSL2 Linux 컨테이너**로 정했습니다. 현재 세션에서 RTX 3060 Ti 8GB는 확인됐지만, `wsl --status`는 접근 거부를 반환하고 `docker` 명령을 찾지 못했습니다. 사용자가 Docker가 있다고 알려주셨으므로 현재 터미널 경로에서 CLI를 확인하지 못한 상태로 기록합니다. GPU passthrough를 확인하기 전에는 컨테이너 학습을 시작하지 않습니다. 현재 문서는 계획과 데이터 규격이며 학습을 실행하거나 모델을 내려받지 않았습니다.
