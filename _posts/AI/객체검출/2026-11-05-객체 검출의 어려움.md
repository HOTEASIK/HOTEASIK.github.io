# 객체 검출의 어려움

## 정의·핵심
- 객체 검출은 이미지에서 **여러 물체를 분류함과 동시에 위치를 찾아야** 하므로 분류보다 훨씬 어렵다 (응용 11차시 "객체 검출의 도전과제")
- **4가지 도전과제 (강의)**
  1. **다양한 크기와 유형의 객체가 섞여 있음**: 크기가 서로 다르고 생김새가 다양한 객체가 한 이미지에 공존 → 다중 스케일 처리 필요 ([[FPN·PANet]], [[Multi-scale Feature Map]])
  2. **검출 시간이 중요**: 자율주행·CCTV 같은 **실시간 영상**에서의 요구 증대 → One-Stage 검출기 등장 ([[YOLO v1]], [[SSD]])
  3. **명확하지 않은 이미지**: 객체가 흐리거나 가려짐(occlusion), 전체 이미지에서 객체가 차지하는 비중이 작고 **배경이 대부분** → 전경/배경 **클래스 불균형** ([[Hard Negative Mining]], Focal Loss)
  4. **데이터셋 부족**: 박스·클래스 **Annotation(라벨링)** 을 사람이 직접 만들어야 해 학습 데이터 구축이 어려움 → 전이학습, 증강 ([[검출용 데이터 증강]], [[라벨 오류 점검]])
- **그 밖의 어려움**
  - 출력 개수가 가변(0개~수백 개) → 고정 출력 구조로 다루기 어려움
  - 한 객체에 **중복 박스** → [[NMS(Non-Maximum Suppression)]]
  - 위치 평가 기준 필요 → [[IoU]], [[AP·mAP]]
  - **작은 객체**: 다운샘플링으로 정보가 사라짐 (stride 32면 32px 미만 객체는 특징 맵에서 1칸 미만)
  - 종횡비가 극단적인 객체(전봇대, 버스), 밀집 객체(군중)
- **해결의 역사**: Sliding Window(느림) → Region Proposal + CNN(R-CNN 계열, 정확) → 단일 네트워크(YOLO·SSD, 빠름) → Anchor-Free·NMS-Free

## 수식·원리
```
배경 vs 전경 불균형:  후보 수천~수만 개 중 객체는 수 개
예) SSD 8,732개 Default Box 중 양성은 보통 수십 개 미만
작은 객체:  feature 크기 = 객체 크기 / stride  (20px / 32 < 1칸)
```

## 코드 예시
```python
import numpy as np

H = W = 640
for stride in (8, 16, 32):
    g = H // stride
    print(f"stride {stride:2d}: {g}x{g} 격자, 20px 객체 = {20 / stride:.2f}칸")
# 2.50칸 / 1.25칸 / 0.62칸 → stride 32에서 20px 객체는 1칸도 안 됨 → 작은 객체는 얕은(고해상도) 맵이 담당

n_anchor = sum((H // s) ** 2 for s in (8, 16, 32))
n_obj = 5
print(n_anchor, f"양성 비율 {n_obj / n_anchor:.4%}")    # 8400 양성 비율 0.0595%  배경이 압도적
```
