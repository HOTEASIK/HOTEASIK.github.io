# Grid Search

## 정의·핵심
- **정의 (보충 02)**: 각 하이퍼파라미터의 **후보 값**을 정하고, 그 **모든 조합**을 격자처럼 전부 시도하는 탐색
  - 예: lr ∈ {0.001, 0.01, 0.1} × batch ∈ {32, 64} → **3 × 2 = 6가지** 조합 → 6개 모두 학습 → 검증 성능 최고 조합 채택
  - 성질: **완전 탐색** → 격자 안에서는 반드시 최고를 찾음
- **강의 예시 결과표**: (0.01, 32) = **0.971 최고** · (0.01, 64) 0.969 · (0.001, 32) 0.962 · (0.001, 64) 0.958 · (0.1, 64) 0.912 · (0.1, 32) 0.904 (lr 과대 → 불안정)
  - "표를 채우고 최고를 고르는 것이 Grid Search의 전부" — 결과 해석이 직관적, 병렬 실행·재현 쉬움
- **함정 — 차원의 저주 (강의)**: 조합 수 = **후보 수의 곱** → HP 2개(각 5후보) 25번, 3개 125번, 4개 625번, 5개 3,125번, 6개 **15,625번**
  - 지수 폭발, 많은 조합이 '비슷하게 나쁜' 영역(낭비), 후보를 촘촘히 하면 또 폭발 (해상도 딜레마)
  - **격자 사이의 좋은 값은 못 봄**
- **실습 문제 (강의)**: lr 4 × 배치 3 × 옵티마이저 2 × 드롭아웃 5 = **120 조합**, 조합당 3분이면 **360분 = 6시간** / 2_1 연습 문제 2: 5 × 4 × 3 = **60번**
- **장단점 (강의)**
  - 장점: 단순·명료, 완전 탐색, 병렬·재현 쉬움 → **HP 2~3개, 후보가 적고 명확할 때**의 정석
  - 단점: 차원의 저주, 비효율, 해상도 한계 → HP 4개 이상·넓은 연속 범위엔 부적합 → [[Random Search]]
- **도구**: `itertools.product`로 모든 조합 생성 / sklearn `GridSearchCV` / W&B Sweeps `method: grid` → [[WandB 실험 기록·Sweeps]]

## 수식·원리
```
조합 수 = Π_i |후보_i|
총 시간 = 조합 수 × 조합당 시간
예: 4 × 3 × 2 × 5 = 120 조합,  120 × 3분 = 360분
```

## 코드 예시
```python
import itertools
import math

def train_and_eval(lr, batch):                         # 가짜 검증 정확도 (lr=0.01, batch=32 근처가 최고)
    return round(0.97 - 0.02 * (math.log10(lr) + 2) ** 2 - 0.0001 * (batch - 32) / 32 * 10, 4)

grid = {"lr": [1e-3, 1e-2, 1e-1], "batch": [32, 64]}
results = []
for lr, b in itertools.product(*grid.values()):        # 강의 코드: product가 모든 조합 생성
    results.append((train_and_eval(lr=lr, batch=b), lr, b))
results.sort(reverse=True)
print(len(results), results[0])                         # 6 (0.97, 0.01, 32)  최고 조합

print(5 * 4 * 3, 4 * 3 * 2 * 5, 4 * 3 * 2 * 5 * 3 / 60)  # 60 120 6.0  조합 수·총 시간(시간)
print([5 ** k for k in range(2, 7)])                    # [25, 125, 625, 3125, 15625]  차원의 저주
```
