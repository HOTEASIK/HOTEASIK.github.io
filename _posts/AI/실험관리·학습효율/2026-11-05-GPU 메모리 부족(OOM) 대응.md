# GPU 메모리 부족(OOM) 대응

## 정의·핵심
- **OOM (Out Of Memory)**: `RuntimeError: CUDA out of memory` — 모델·활성화·그래디언트·옵티마이저 상태가 GPU 메모리(T4 약 15GB)를 넘을 때 (보충 02 "메모리 병목": 큰 모델·큰 입력·큰 배치에서 자주)
- **GPU 메모리를 쓰는 것**
  - **가중치** + **그래디언트** (파라미터와 같은 크기)
  - **옵티마이저 상태**: Adam은 모멘텀·분산 2개 → 파라미터의 **2배** 추가 (FP32)
  - **활성화 (activation)**: 역전파를 위해 저장한 순전파 중간값 — **배치 크기·입력 해상도에 비례**, 보통 가장 큼
  - 학습은 추론보다 약 8배 무거움 → [[비트와 양자화]]
- **대응 순서 (강의 + 일반)**
  1. **배치 크기 줄이기** — 가장 간단. 대신 일반화·속도 영향 → [[미니배치·배치 크기]]
  2. **AMP (혼합 정밀도)** — 활성화 메모리 약 **55%** 수준(강의 예시), 속도도 ↑ → "1순위 카드" → [[AMP(혼합 정밀도)]]
  3. **Gradient Accumulation** — 작은 물리 배치로 큰 유효 배치 (강의 연습 Q2: OOM일 때 큰 배치 효과 유지 = AMP + 누적) → [[Gradient Accumulation]]
  4. **Gradient Checkpointing** — 활성화를 일부만 저장하고 역전파 때 **다시 계산** (메모리 ↓, 계산 약 30% ↑)
  5. 평가·추론은 **`torch.no_grad()`** (그래프·활성화 저장 안 함), 입력 해상도·모델 크기 줄이기, 더 가벼운 옵티마이저
- **메모리 누수 패턴**
  - `total_loss += loss` → 그래프가 계속 연결됨 → **`loss.item()`** 으로 숫자만
  - 쓰지 않는 텐서 참조 유지 → `del` 후 `torch.cuda.empty_cache()` (캐시 반환, 단편화 완화)
- **측정**: `torch.cuda.max_memory_allocated()`, `torch.cuda.memory_summary()`, `nvidia-smi` / 실험 중 W&B 시스템 메트릭으로 OOM 직전 추이 확인 (강의) → [[WandB 실험 기록·Sweeps]]
- **배치 크기 경험칙 (강의)**: OOM이 안 나는 선에서 배치를 키우되, 배치를 2배 하면 학습률도 대략 √2~2배

## 수식·원리
```
학습 메모리 ≈ P·(w + g + opt) + Activation(batch, H, W)
Adam FP32:  P × (4 + 4 + 8) = 16P byte
활성화 ∝ batch × (층별 출력 크기 합)          → 배치 절반이면 활성화 절반
Checkpointing: 저장 활성화 O(L) → O(√L), 계산 +1회 순전파
```

## 코드 예시
```python
import torch
import torch.nn as nn
from torch.utils.checkpoint import checkpoint

def act_bytes(model, x):                              # 순전파에서 저장되는 활성화 크기 측정(hook)
    total = [0]
    hooks = [m.register_forward_hook(lambda m, i, o: total.__setitem__(0, total[0] + o.numel() * o.element_size()))
             for m in model if not isinstance(m, nn.Sequential)]
    model(x); [h.remove() for h in hooks]
    return total[0]

model = nn.Sequential(*[m for _ in range(4) for m in (nn.Linear(512, 512), nn.ReLU())])
P = sum(p.numel() for p in model.parameters())
print(P, P * 16 / 2 ** 20)                            # 1050624 16.03125  Adam FP32: 파라미터당 16바이트(MB)
a64, a32 = act_bytes(model, torch.randn(64, 512)), act_bytes(model, torch.randn(32, 512))
print(a64 / a32)                                      # 2.0  활성화는 배치에 비례 → 배치 절반이면 절반

x = torch.randn(64, 512, requires_grad=True)          # Gradient Checkpointing: 같은 기울기
y1 = model(x).sum(); g1, = torch.autograd.grad(y1, x)
y2 = checkpoint(model, x, use_reentrant=False).sum(); g2, = torch.autograd.grad(y2, x)
print(torch.allclose(g1, g2))                         # True  메모리 대신 재계산, 결과는 같음

total = 0.0                                           # 누수 패턴: loss.item()으로 숫자만 누적
for _ in range(3):
    loss = model(torch.randn(8, 512)).pow(2).mean()
    total += loss.item()
print(type(total).__name__)                           # float  그래프를 붙잡지 않음

if torch.cuda.is_available():
    torch.cuda.reset_peak_memory_stats()
    m = model.cuda(); _ = m(torch.randn(256, 512, device="cuda")).sum().backward()
    print(torch.cuda.max_memory_allocated() > 0)       # True  최대 메모리 측정
```
