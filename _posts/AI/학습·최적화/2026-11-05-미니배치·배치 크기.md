# 미니배치·배치 크기

## 정의·핵심
- **미니배치 경사하강법**: 데이터를 **작은 묶음(미니배치, 보통 32~256개)** 으로 나눠, 묶음마다 평균 기울기로 업데이트. Full Batch(정확하지만 느림)와 SGD(빠르지만 출렁임)의 **절충안**이자 **실전 표준**
- **배치 크기(batch_size)**: 한 묶음의 데이터 수. `DataLoader(dataset, batch_size=64, shuffle=True)`
- **배치 크기의 영향**

| | 작은 배치 (8~32) | 큰 배치 (256~) |
|---|---|---|
| 기울기 | 잡음 많음 | 정확·안정 |
| 1 에폭 속도 | 업데이트 많아 느림 | GPU 병렬로 빠름 |
| GPU 메모리 | 적게 | 많이 → **OOM 위험** |
| 일반화 | 넓은 최솟값 → 유리한 경향 (6차시: "작은 배치 크기: 넓은 최소값 발견") | 날카로운 최솟값 → 불리할 수 있음 |
| BatchNorm | 통계가 불안정 (너무 작으면 문제) | 안정 |

- **고르는 법**
  - GPU 메모리가 허락하는 범위에서 2의 거듭제곱(32, 64, 128) — 하이퍼파라미터 탐색 대상
  - OOM이면 줄이기 (16 → 8 → 4), 더 큰 배치 효과가 필요하면 **Gradient Accumulation** → [[Gradient Accumulation]]
  - 배치를 k배 키우면 학습률도 비례해서 키우는 경우가 많다 (선형 스케일링 규칙) + Warm-up
- 출력 텐서의 첫 차원 = 배치 차원 `(B, C, H, W)`

## 수식·원리
```
g = (1/B) Σᵢ∈batch ∇L(xᵢ, yᵢ)       B = batch_size
1 에폭 업데이트 수 = ceil(N / B)
```

## 코드 예시
```python
import torch
from torch.utils.data import DataLoader, TensorDataset

torch.manual_seed(0)
X = torch.randn(1000, 1); Y = 3 * X + 2
loader = DataLoader(TensorDataset(X, Y), batch_size=64, shuffle=True)
W = torch.zeros(1, requires_grad=True); B = torch.zeros(1, requires_grad=True)
opt = torch.optim.SGD([W, B], lr=0.1)
for epoch in range(10):
    for xb, yb in loader:                      # 미니배치마다 업데이트
        opt.zero_grad()
        loss = ((xb * W + B - yb) ** 2).mean()
        loss.backward(); opt.step()
print(len(loader), round(W.item(), 2), round(B.item(), 2))   # 16 3.0 2.0
```
