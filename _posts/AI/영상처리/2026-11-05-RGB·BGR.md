# RGB·BGR

## 정의·핵심
- **RGB**: 빛의 삼원색 **Red·Green·Blue**를 섞어 색을 표현하는 **가산 혼합** 방식. 세 값이 모두 0이면 검정, 모두 255면 흰색 (응용 1차시)
  - 모니터·카메라 등 하드웨어 장치의 기본 색공간
  - 단점: **조명 변화에 매우 민감** — 같은 물체도 밝기가 바뀌면 R·G·B 세 값이 모두 변해 색 인식이 어렵다
  - 대표 색: 빨강 (255,0,0), 초록 (0,255,0), 파랑 (0,0,255), 노랑 (255,255,0), 시안 (0,255,255), 마젠타 (255,0,255)
- **BGR**: **OpenCV의 기본 채널 순서**. 같은 RGB 정보를 **Blue, Green, Red 순서**로 저장
  - 역사적 이유: 초기 카메라·Windows BMP 형식이 BGR 순서를 사용
  - `cv2.imread` 결과 = BGR, `cv2.imshow`·`cv2.imwrite`도 BGR을 기대
- **가장 흔한 버그: 순서 혼동**
  - OpenCV(BGR) 이미지를 **matplotlib·PIL·torchvision(RGB)** 에 그대로 넘기면 **빨강↔파랑이 뒤바뀐다** (사람 피부가 파랗게)
  - 변환: `cv2.cvtColor(img, cv2.COLOR_BGR2RGB)` 또는 `img[..., ::-1]`
  - 사전학습 모델(RGB로 학습)에 BGR을 넣으면 정확도 하락 → 추론 코드에서 꼭 변환
- `img[..., ::-1]`은 **음수 stride 뷰**라 일부 함수(torch.from_numpy 등)에서 오류 → `.copy()` 또는 `np.ascontiguousarray`
- 색 지정: OpenCV 그리기 함수의 색도 BGR — `cv2.rectangle(img, p1, p2, (0, 0, 255))`는 **빨강**

## 수식·원리
```
OpenCV:      img[y, x] = [B, G, R]
matplotlib:  img[y, x] = [R, G, B]
BGR → RGB:   채널 축 뒤집기 (0 ↔ 2)
```

## 코드 예시
```python
import numpy as np
import cv2
import torch

bgr = np.zeros((2, 2, 3), np.uint8)
bgr[0, 0] = (0, 0, 255)                                    # OpenCV에서 빨강
rgb = cv2.cvtColor(bgr, cv2.COLOR_BGR2RGB)
print(bgr[0, 0].tolist(), rgb[0, 0].tolist())              # [0, 0, 255] [255, 0, 0]
print(np.array_equal(rgb, bgr[..., ::-1]))                 # True  같은 결과
try:
    torch.from_numpy(bgr[..., ::-1])
except ValueError as e:
    print("음수 stride 오류")                               # 음수 stride 오류
print(torch.from_numpy(bgr[..., ::-1].copy()).shape)       # torch.Size([2, 2, 3])
# plt.imshow(rgb)  ← matplotlib에는 RGB로
```
