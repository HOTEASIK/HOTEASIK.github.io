# GRU

## 정의·핵심
- **정의 (응용 8차시)**: Gated Recurrent Unit (Cho et al., 2014 — 뉴욕대 **조경현 교수** 제안). LSTM과 마찬가지로 바닐라 RNN보다 **장기 의존성 문제에 강건**하면서, 구조를 단순화한 RNN
- **LSTM과 차이 (강의)**: LSTM의 게이트 3개(삭제·입력·출력) → **업데이트 게이트, 리셋 게이트 2개**로 줄임
  - **셀 상태가 없음**: hidden state 하나가 장기·단기 기억을 모두 담당
  - 파라미터가 LSTM의 약 **3/4** (게이트 3묶음 vs 4묶음) → 학습 빠르고 데이터가 적을 때 유리
- **업데이트 게이트 z_t**: 이전 상태를 얼마나 유지하고 새 후보를 얼마나 받아들일지 — LSTM의 삭제+입력 게이트 역할을 하나로 (`(1 − z)`와 `z`로 보간)
- **리셋 게이트 r_t**: 후보 상태를 만들 때 **이전 hidden state를 얼마나 무시할지** — 0이면 과거를 지우고 현재 입력 위주
- **LSTM vs GRU 선택**: 성능은 과제에 따라 비슷 — 데이터가 많고 긴 의존성이면 LSTM, 가볍고 빠르게는 GRU. 실무에선 둘 다 시도해 비교
- **PyTorch `nn.GRU`**: 반환 `output, h_n` (cell 없음, nn.RNN과 같은 형태)

## 수식·원리
```
z_t = σ(W_z [h_{t−1}, x_t])               업데이트
r_t = σ(W_r [h_{t−1}, x_t])               리셋
h̃_t = tanh(W [r_t ⊙ h_{t−1}, x_t])        후보
h_t = (1 − z_t) ⊙ h_{t−1} + z_t ⊙ h̃_t     (PyTorch는 z와 1−z의 역할이 반대 표기)
```

## 코드 예시
```python
import torch
import torch.nn as nn

torch.manual_seed(0)
gru = nn.GRU(16, 32, batch_first=True)
out, h_n = gru(torch.randn(4, 10, 16))
print(tuple(out.shape), tuple(h_n.shape))              # (4, 10, 32) (1, 4, 32)  cell state 없음

n = lambda m: sum(p.numel() for p in m.parameters())
print(n(nn.RNN(16, 32)), n(nn.GRU(16, 32)), n(nn.LSTM(16, 32)))   # 1600 4800 6400  RNN×3, RNN×4

h_prev, h_cand = torch.tensor([1.0]), torch.tensor([-1.0])
for z in (0.0, 0.5, 1.0):                              # 업데이트 게이트 보간
    print(z, ((1 - z) * h_prev + z * h_cand).item())   # 0.0 1.0 (과거 유지) / 0.5 0.0 / 1.0 -1.0 (새 정보)
```
