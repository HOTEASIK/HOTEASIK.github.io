# 클래스 불균형 문제

## 정의·핵심
- **정의**: Class Imbalance. 클래스별 샘플 수가 **크게 차이 나는** 데이터. "실무에서 가장 흔한 문제" (개론 10차시)
  - 예: 스팸 필터 정상 990 / 스팸 10, 의료 정상 9,900 / 질병 100, 카드 사기 거래(8차시, 0.1~1%), 공장 불량품, 객체 검출의 배경 vs 물체
- **무엇이 문제인가**
  - **모두 다수 클래스로 예측해도 정확도 99%** → 쓸모없는 모델이 좋아 보인다
  - 손실의 대부분이 다수 클래스에서 나와 모델이 **소수 클래스를 무시**하도록 학습된다
  - 소수 클래스 예시가 적어 그 패턴을 배우기 어렵다
- **평가부터 바꾼다**: 정확도 대신 **혼동행렬, 재현율, 정밀도, F1(macro), PR-AUC** → [[혼동행렬]], [[macro·micro·weighted 평균]], 분할은 `stratify` → [[stratify]]
- **해결 전략 (강의 "불균형 대응 전략 가이드")**

| 수준 | 방법 | 파일 |
|---|---|---|
| 데이터 | 오버샘플링·언더샘플링, **WeightedRandomSampler** | [[오버샘플링·언더샘플링]] |
| 데이터 | SMOTE (합성 샘플) | [[SMOTE]] |
| 손실 | 클래스 가중치 `weight`, `pos_weight` | [[클래스 가중치]], [[Weighted Cross Entropy]] |
| 손실 | Focal Loss (극심한 불균형 1:100 이상) | [[Focal Loss]] |
| 판정 | 임계값 조정 (검증 데이터에서 F1·재현율 기준) | [[이진분류 출력과 임계값]] |
| 데이터 | 소수 클래스 증강·추가 수집 | [[데이터 증강]] |

- **강의 실무 조언**: "보통 **WeightedRandomSampler 하나로 충분**하다. 그래도 소수 Recall이 낮으면 **가중 손실**을 더하거나 **Focal loss**"
- 리샘플링은 **훈련 데이터에만**. 검증·테스트는 실제 분포 그대로 둬야 실제 성능을 알 수 있다

## 수식·원리
```
불균형 비율 = N_majority / N_minority
"모두 다수" 예측의 정확도 = N_majority / N  (← 기준선. 이보다 높아야 의미가 있음)
```

## 코드 예시
```python
import numpy as np
from sklearn.metrics import accuracy_score, recall_score, f1_score

y = np.array([0] * 990 + [1] * 10)
lazy = np.zeros(1000, dtype=int)                                     # 모두 정상
print(accuracy_score(y, lazy), recall_score(y, lazy), f1_score(y, lazy, zero_division=0))   # 0.99 0.0 0.0
print(np.bincount(y), round(np.bincount(y)[0] / np.bincount(y)[1]))  # [990  10] 99  (불균형 비율)
```
