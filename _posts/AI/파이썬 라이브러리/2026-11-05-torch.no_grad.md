# torch.no_grad

## 정의·핵심
- **정의**: `with torch.no_grad():` 블록 안에서는 **기울기 추적(계산 그래프 기록)을 끈다.**
- **쓰는 곳 두 가지**
  1. **평가·추론**: 검증·테스트 때는 기울기가 필요 없다. 끄면 메모리를 덜 쓰고 빠르다. (1차시: 평가 단계에서는 `no_grad` 블록 사용)
  2. **파라미터를 손으로 업데이트할 때**: `W -= lr * W.grad`는 기록 중인 텐서를 직접 바꾸는 것이라 그냥 하면 오류. `no_grad` 안에서 해야 한다. (4차시 코드 3-14) optimizer.step()도 내부적으로 이렇게 한다.
- **`model.eval()`과 다르다** (자주 헷갈림)
  - `model.eval()`: Dropout·BatchNorm의 **동작 방식**을 평가 모드로 바꿈. 기울기 추적은 그대로
  - `torch.no_grad()`: **기울기 추적**을 끔. 레이어 동작은 그대로
  - 평가할 때는 **둘 다** 쓴다. → [[train()·eval() 모드]]
- 비슷한 것: `torch.inference_mode()`(더 빠른 추론 전용), `t.detach()`(텐서 하나만 떼어 내기)

## 수식·원리
```
model.eval()
with torch.no_grad():
    for x, y in val_loader:
        out = model(x)      # 그래프 기록 안 함
```

## 코드 예시
```python
import torch
import torch.nn as nn

W = torch.tensor(1.0, requires_grad=True)
loss = (W * 2 - 4) ** 2
loss.backward()
lr = 0.1
with torch.no_grad():
    W -= lr * W.grad          # 수동 업데이트
    W.grad.zero_()            # 기울기 초기화
print(W)                      # tensor(1.8000, requires_grad=True)

net = nn.Linear(3, 1)
with torch.no_grad():
    out = net(torch.randn(2, 3))
print(out.requires_grad)      # False ← 기록 안 됨
print(net(torch.randn(2, 3)).requires_grad)   # True
```
