# 2. Docker 아키텍처

Docker는 클라이언트, Docker 호스트의 엔진·데몬, 레지스트리가 서로 요청과 이미지를 주고받는 구조입니다.

```text
사용자
  │ docker 명령 / API 요청
  ▼
Docker 클라이언트 ───── Docker 데몬(호스트)
                            ├─ 이미지 관리
                            ├─ 컨테이너 실행·관리
                            ├─ 네트워크·볼륨 관리
                            └─ 레지스트리에서 이미지 가져오기/올리기
                                      │
                                      ▼
                                 레지스트리
```

## 구성 요소

### Docker 클라이언트

`docker` 명령줄 도구나 API를 통해 사용자의 요청을 전달합니다. `docker run`, `docker build`, `docker pull` 같은 명령이 대표적입니다. 클라이언트와 데몬은 API로 통신합니다.

### Docker 호스트와 데몬

Docker 엔진이 동작하는 물리 또는 가상 시스템입니다. 데몬은 클라이언트 요청을 받아 이미지, 컨테이너, 네트워크, 볼륨을 관리합니다. 컨테이너를 실행할 때는 호스트의 운영체제 및 컨테이너 런타임을 이용합니다.

### 이미지와 컨테이너

호스트의 이미지 저장소에 이미지가 보관됩니다. 데몬은 이미지에 정의된 파일 시스템과 설정을 이용해 컨테이너를 생성하고 실행합니다.

### 레지스트리

이미지를 저장·배포합니다. `docker pull`은 레지스트리에서 이미지를 내려받고, `docker push`는 이미지를 레지스트리에 올립니다. 공개 저장소뿐 아니라 조직 내부 레지스트리도 운영할 수 있습니다.

## 명령이 처리되는 예

- `docker pull nginx`: 클라이언트 요청을 데몬이 처리하고 레지스트리에서 이미지를 받습니다.
- `docker run nginx`: 필요한 이미지가 없으면 내려받은 뒤 호스트에서 컨테이너를 생성·실행합니다.
- `docker build`: 빌드 컨텍스트와 Dockerfile을 바탕으로 이미지를 생성합니다.

즉, 클라이언트는 명령을 전달하고 실제 컨테이너 관리는 Docker 호스트의 데몬이 담당합니다.
