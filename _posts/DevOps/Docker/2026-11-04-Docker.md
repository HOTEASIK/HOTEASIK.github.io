# 정의 
가상화 기술을 활용한 컨테이너화 아키텍처

개발과 배포를 효율적으로 


# 주요 구조
## 도커 클라이언트(Client) 
도커를 사용하기 위한 명령줄 도구 또는 API를 제공하는 인터페이스 
도커 데몬과 통신하여 컨테이너 관리 작업을 수행 

컨테이너 관리 
	사용자가 컨테이너의 생성, 실행, 중지, 재시작, 삭제 등의 작업을 수행 
	도커 이미지를 기반으로 컨테이너를 생성 
	컨테이너의 상태를 모니터링 
	명령어를 수행하여 필요한 작업을 수행 

이미지 관리 
	도커 이미지의 검색, 다운로드, 빌드, 업로드, 삭제 등의 작업을 수행 
	도커 허브와 같은 이미지 레지스트리 활용 가능 

네트워크 설정 
	도커 컨테이너 간의 네트워크 연결, 포트 매핑, 네트워크 드라이버 설정 등을 구성 

데이터 볼륨 관리 
	호스트와 컨테이너 간 데이터 공유를 위한 볼륨 마운트 설정, 볼륨 생성 및 삭제 수행 
	데이터 볼륨: 애플리케이션에서 사용하는 데이터 저장 공간
## 도커 호스트(Host) 
도커 엔진이 설치되고 실행되는 물리적 또는 가상화된 시스템 
도커 엔진은 컨테이너를 실행하기 위해 컨테이너 런타임을 사용 
도커 컨테이너를 실행하고 관리하는 역할 수행
도커 이미지가 저장되고 관리됨 
	도커 이미지: 컨테이너 실행에 필요한 파일 시스템과 애플리케이션 설정을 포함

도커 데몬 
	컨테이너 생성, 실행 및 관리를 담당 
	도커 호스트에서 실행 
	REST API를 통해 도커 클라이언트와 상호 작용 
		자원을 이름으로 구분하여 해당 자원의 상태를 주고 받는 모든 것을 의미함 
		REST API: HTTP URI를 통해 자원을 명시하고, HTTP Method(POST, GET, PUT, DELETE, PATCH 등)를 통해 해당 자원 (URI)에 대한 CRUD Operation을 적용하는 것 

컨테이너 
	도커 이미지를 기반으로 생성되며, 격리된 환경에서 실행되는 프로세스 
	각 컨테이너는 각자의 애플리케이션 및 해당 종속성을 포함하여 실행함 

이미지 
	컨테이너 실행에 필요한 파일시스템과 응용프로그램 설정을 포함한 읽기전용 템플릿 
	이미지 레지스트리에서 가져오거나 사용자가 직접 만들 수 있음 

호스트 운영체제 
	도커 호스트가 실행되는 운영체제(리눅스, 윈도우, 맥OS 지원) 
	호스트 자원을 컨테이너에 할당
## 레지스트리(Registry) 
도커 이미지를 저장하고 공유하기 위한 중앙 저장소 
이미지를 레지스트리에 업로드, 다운로드 및 공유할 수 있음 
개인적으로 운영하여 독자적인 이미지 저장소를 구축 가능 
	도커 허브(Hub) » 널리 사용되는 공개 레지스트리 » 많은 도커 이미지가 업로드 되어 있음 » 고유의 개정을 통해 이미지를 업로드 및 공유 가능



# 사용 이유
환경의 일관성 
개발 환경, 테스트 환경 및 프로덕션 환경 사이의 일관성을 유지 가능 
도커 이미지를 사용하여 애플리케이션과 그 종속성을 패키징함으로써 어디서든 동일한 환경에서 실행할 수 있음  

빠른 배포 및 확장성 
컨테이너 단위로 애플리케이션을 패키징하고 배포할 때 시간을 단축하여 빠르게 생성 
필요에 따라 더 높은 확장성, 가용성 제공 (사용자가 늘어나도 컨테이너 복제 활용 가능) 

자원의 효율적 이용 
호스트 시스템의 운영체제 커널을 공유하므로 가상화된 환경보다 자원의 이용이 효율적 
컨테이너는 필요한 만큼의 자원만 사용하여 더 많은 애플리케이션을 호스트 할 수 있음 

격리된 환경 
각 컨테이너는 자체 파일 시스템, 네트워크 및 프로세스 공간을 가지며 서로 영향을 주지 않음 
애플리케이션 간의 충돌을 방지하고 보안을 강화함  

빠른 시작 시간 
필요한 자원만 할당하여 컨테이너를 빠르게 시작하며, 애플리케이션의 시작 시간을 단축함

## Docker 명령어
도커 로그인: docker login –u <사용자명>

이미지 관리:
	docker image:  컨테이너 실행에 필요한 파일과 설정을 포함한 패키지를 수행 
	docker image pull <이미지명> : 외부에 있는 도커 이미지를 자신이 운영하는 도커 호스트 머신으로 다운로드 시 사용함 » 
		예시: docker image pull ubuntu 
	docker image ls : 다운로드 이미지를 확인 
	docker image rmi <이미지명>: 이미지를 삭제
		예시: docker image rmi ubuntu

컨테이너 관리
	docker container
		이미지를 기반으로 싱행되는 격리된 환경
	docker container run <옵션> <이미지명>
		새 컨테이너를 실행(생성)하는 명령어
		미리 다운로드 받은 이미지가 없다면 이미지를 다운로드 받아 컨테이너를 생성함
			-i (interactive): 연결(attach)된 상태가 아니어도 표준 입력 유지
			-t (tty): 가상 터미널 장치 드라이버를 할당하여 컨테이너 안에서 터미널 실행이 가능
			-v (volume list): 볼륨을 마운트 하기 (윈도우 폴더와 리눅스 디렉터리 공유)
			-d (detach): 백그라운드로 실행
			예시: docker run -it -v /c/rokey:/rokey continuumio/miniconda3 /bin/bash
	docker container ps
		실행 중인 컨테이너의 목록을 표시
		-a (all) : 모든 컨테이너 목록 표시
		CONTAINER ID: 이미지를 사용하여 생성한 다양한 컨테이너를 구분
	docker container
		이미지를 기반으로 싱행되는 격리된 환경
	docker container start <컨테이너명/id>
		컨테이너 실행 시작
	docker container attach <컨테이너명/id>
		컨테이너 연결
	docker container rename <기존 컨테이너명> <새 컨테이너명>
		컨테이너 이름을 변경
	docker container stop <컨테이너명/id>
		컨테이너 실행 중지
	docker container rm <컨테이너명/id>
		컨테이너 삭제
	exit
		빠져 나가기


네트워킹
	docker network
		컨테이너 간의 통신을 위한 가상 네트워크를 제공함
		같은 네트워크에 속한 다른 컨테이너와 통신하는 것이 가능
	docker network Is
		도커엔진에서 현재 사용하고 있는 네트워크를 표시
		bridge: 사용자의 필요에 의해 생성한 별도 네트워크를 의미
	docker network create <네트워크명>
		특정 네트워크를 생성하고 싶을 때 활용
	docker network connect <네트워크명> <컨테이너명>
		해당 컨테이너를 특정 네트워크에 연결

컨테이너 내부 명령 실행
	docker exec
	실행 중인 컨테이너 내에서 새로운 프로세스를 실행하거나 이미 실행 중인 프로세스에 접속하는 명령
	컨테이너 내부에서 명령어를 실행하거나 조작할 수 있어 디버깅 등 작업 수행 가능
	docker exec` [옵션] <컨테이너명> <실행할 명령>`
		예시: my_container 내부에 Bash 셸을 실행함
			docker exec -it my_container bash
		예시: web_server 컨테이너 내부에서 /var/www 디렉터리의 내용을 나열함
			docker exec -it web_server Is /var/www
		예시: database 컨테이너 내에서 psql 데이터베이스에 'postgres' 사용자로 접속함
			docker exec -it database psql -U postgres
		-it 옵션은 뒤에 사용할 옵션들을 명기하겠다는 의미이며,사용하는 도커 컨테이너의 종류에 따라 다양한 명령어 생성이 가능

파일 복사
	docker cp
		컨테이너와 로컬 파일 시스템 간에 파일/폴더 복사
	docker cp `<host 파일경로> <컨테이너명 : 컨테이너 내부 경로>`
		호스트에서 컨테이너로 파일/폴더 복사
	docker cp `<컨테이너명 : 컨테이너 내부 경로> <host 파일경로>`
		컨테이너에서 호스트로 파일/폴더 복사
	이미지 커밋
		docker commit
		컨테이너를 이미지로 저장
	docker commit <컨테이너명/id> <이미지명/id>
		특정 컨테이너를 해당 이미지명으로 저장
