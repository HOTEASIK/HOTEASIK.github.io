# 정의
애플리케이션의 확장성과 격리를 향상시키는데 유용한 기술.
애플리케이션과 그에 필요한 종속성을 패키징하여 실행하는 방식. 대표적인 구현이 [[Docker]]다.

# 배포 환경 비교
| 구분 | 구조 | 특징 |
|---|---|---|
| 전통적 배포 | 하드웨어 → 운영체제 → App 여러 개 | 앱끼리 라이브러리가 충돌할 수 있음 |
| 가상화 | 하드웨어 → 운영체제 → **하이퍼바이저** → 가상머신(게스트 OS + 라이브러리 + App) | VM마다 OS 전체를 올려 무겁다 |
| 컨테이너 | 하드웨어 → 운영체제 → **컨테이너 런타임** → 컨테이너(라이브러리 + App) | 호스트 커널을 공유해 가볍고 빠르다 |

- **하이퍼바이저**: 물리 하드웨어에서 가상 머신의 영역을 분리하고, 그 사이에서 중간 관리자(인터페이스) 역할을 한다.
- **컨테이너 런타임**: 운영체제 위에서 [[컨테이너]]를 직접 생성·관리한다.

# 왜 쓰나
- **환경의 일관성**: 개발·테스트·운영 환경을 같은 이미지로 맞춘다
- **빠른 배포·확장성**: 컨테이너 단위로 배포하고, 사용자가 늘면 복제해서 늘린다
- **자원 효율**: OS 커널을 공유해 가상머신보다 자원을 적게 쓴다
- **격리**: 각자 파일 시스템·네트워크·프로세스 공간을 가져 서로 영향을 주지 않는다
- **빠른 시작**: 필요한 자원만 할당해 바로 뜬다
