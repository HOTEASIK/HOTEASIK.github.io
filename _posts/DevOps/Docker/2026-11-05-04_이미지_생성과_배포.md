# 4. 이미지 생성과 배포

## Dockerfile로 이미지 만들기

Dockerfile은 이미지를 만드는 과정을 코드로 적은 파일입니다. 아래는 정적 웹 파일을 Nginx 이미지에 넣는 간단한 예입니다.

```dockerfile
FROM nginx:alpine
COPY ./site /usr/share/nginx/html
EXPOSE 80
```

```bash
docker build -t my-site:1.0 .
docker run --rm -p 8080:80 my-site:1.0
```

- `FROM`: 기반 이미지 선택
- `COPY`: 빌드 컨텍스트의 파일을 이미지에 복사
- `EXPOSE`: 컨테이너가 사용하는 포트를 문서화
- `-t`: 이미지 이름과 태그 지정
- `.`: 현재 디렉터리를 빌드 컨텍스트로 전달

`.dockerignore`에 `.git`, 임시 파일, 로컬 의존성 디렉터리, 비밀 파일 등을 적어 불필요한 내용이 빌드 컨텍스트나 이미지에 들어가지 않도록 합니다.

## 이미지 태그

이미지는 보통 `저장소/이름:태그` 형태로 식별합니다. 예: `team/my-site:1.0`. 태그를 명시하면 어떤 버전을 빌드·배포했는지 추적하기 쉽습니다. 배포에서 `latest`만 사용하면 태그가 가리키는 내용이 바뀔 수 있어 재현성이 떨어질 수 있습니다.

## 레지스트리로 배포

```bash
docker login

docker tag my-site:1.0 <레지스트리주소>/<조직>/my-site:1.0
docker push <레지스트리주소>/<조직>/my-site:1.0
```

배포 서버나 다른 개발 환경에서는 해당 태그를 가져와 컨테이너를 실행합니다.

```bash
docker pull <레지스트리주소>/<조직>/my-site:1.0
docker run -d --name my-site -p 8080:80 <레지스트리주소>/<조직>/my-site:1.0
```

로그인 토큰이나 비밀번호를 Dockerfile, 이미지, 소스 저장소에 넣지 않습니다. CI/CD 환경의 비밀 변수 등으로 안전하게 전달합니다.

## `docker commit`과 Dockerfile

강의 실습은 실행 중 만든 컨테이너를 `docker commit`으로 이미지로 저장하는 방법을 소개합니다.

```bash
docker commit <컨테이너명> my-image:1.0
```

이는 빠른 실험이나 컨테이너 상태 보존에 쓸 수 있지만, 변경 과정이 파일로 드러나지 않아 재현과 협업이 어렵습니다. 지속적으로 관리할 이미지는 Dockerfile로 빌드 절차를 기록하는 편이 좋습니다.

## 배포 흐름

1. 소스와 의존성을 준비합니다.
2. Dockerfile로 이미지 빌드 후 버전 태그를 붙입니다.
3. 테스트하고 레지스트리에 푸시합니다.
4. 배포 환경에서 같은 태그의 이미지를 가져옵니다.
5. 컨테이너를 교체하고 로그·헬스 체크로 정상 동작을 확인합니다.
6. 문제가 있으면 이전에 검증한 이미지 버전으로 복구합니다.
