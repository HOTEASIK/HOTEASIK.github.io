Docker 자동화 정리
=================

1. 자동화란?
------------
사람이 매번 반복하던 빌드, 테스트, 실행, 배포 작업을 스크립트나 도구가 같은 절차로 수행하게 만드는 것이다.
Docker를 쓰면 애플리케이션과 실행 환경을 이미지로 묶어, 개발 PC와 서버에서 비슷한 방식으로 실행할 수 있다.

자동화의 효과
- 반복 작업과 수작업 실수를 줄인다.
- 실행 절차를 코드로 남겨 팀원 간 공유하기 쉽다.
- 같은 이미지와 설정을 개발, 테스트, 운영 환경에서 재사용할 수 있다.
- 문제가 생겼을 때 어떤 절차로 만들고 배포했는지 추적하기 쉽다.

2. Docker 작업 흐름
-------------------
일반적인 컨테이너 배포 흐름은 다음과 같다.

소스 코드 변경
  -> 이미지 빌드
  -> 이미지 실행 또는 테스트
  -> 이미지 레지스트리에 업로드
  -> 서버에서 새 이미지 가져오기
  -> 컨테이너 교체 및 상태 확인

이미지는 애플리케이션과 필요한 파일을 담은 실행 패키지이고, 컨테이너는 그 이미지를 실행한 인스턴스다.

3. Dockerfile로 이미지 빌드 자동화
----------------------------------
Dockerfile에 이미지를 만드는 절차를 선언한다. 아래는 Node.js 앱의 간단한 예시다.

FROM node:20-alpine
WORKDIR /app
COPY package*.json ./
RUN npm ci --omit=dev
COPY . .
EXPOSE 3000
CMD ["node", "server.js"]

빌드와 실행 예시:
  docker build -t myapp:1.0 .
  docker run --rm -p 3000:3000 myapp:1.0

주요 명령
- FROM: 기반 이미지 선택
- WORKDIR: 컨테이너 안에서 작업할 디렉터리 지정
- COPY: 빌드 컨텍스트의 파일을 이미지에 복사
- RUN: 이미지 빌드 단계에서 명령 실행
- EXPOSE: 컨테이너가 사용하는 포트를 문서화
- CMD: 컨테이너 시작 시 기본 실행 명령 지정

빌드에 불필요한 파일은 .dockerignore에 적는다. 예: .git, node_modules, 로그, 비밀 설정 파일. 이렇게 하면 빌드가 빨라지고 이미지에 불필요한 파일이 들어가는 일을 줄인다.

4. Docker Compose로 여러 컨테이너 실행 자동화
---------------------------------------------
Compose는 여러 서비스의 컨테이너, 네트워크, 볼륨 설정을 compose.yaml 한 파일에 정의하고 함께 관리하는 도구다. 개발 환경에서 웹 앱과 데이터베이스를 함께 띄울 때 유용하다.

예시:
services:
  web:
    build: .
    ports:
      - "3000:3000"
    environment:
      DB_HOST: db
    depends_on:
      - db
  db:
    image: postgres:16
    environment:
      POSTGRES_DB: app
      POSTGRES_USER: app
      POSTGRES_PASSWORD: local-dev-password
    volumes:
      - db-data:/var/lib/postgresql/data
volumes:
  db-data:

자주 쓰는 명령:
  docker compose up --build -d   # 빌드 후 백그라운드 실행
  docker compose ps              # 서비스 상태 확인
  docker compose logs -f         # 로그 따라 보기
  docker compose down            # 컨테이너와 네트워크 종료

주의: 위 암호는 로컬 예시다. 실제 운영 비밀번호나 키를 compose.yaml 또는 Dockerfile에 직접 저장하지 말고, 환경 변수 주입이나 비밀 관리 기능을 사용한다. 운영 데이터가 든 볼륨은 삭제 명령을 신중히 사용한다.

5. CI/CD 파이프라인 자동화
-------------------------
CI(지속적 통합)는 코드가 변경될 때 자동으로 빌드와 테스트를 수행하는 과정이다. CD(지속적 전달/배포)는 검증된 결과를 배포 가능한 상태로 만들거나 서버에 자동 배포하는 과정이다.

일반적인 파이프라인 단계
1) 저장소에서 코드 가져오기
2) 테스트 및 정적 검사 실행
3) Docker 이미지 빌드
4) 이미지에 버전 태그 부여
5) 컨테이너 레지스트리에 로그인하고 이미지 푸시
6) 배포 환경에서 새 이미지 적용
7) 헬스 체크 및 실패 시 이전 버전으로 복구

이미지 태그는 latest 하나에만 의존하기보다 커밋 ID나 릴리스 버전처럼 변경되지 않는 식별자를 함께 쓰는 편이 배포 이력을 추적하기 쉽다.

6. 레지스트리와 이미지 배포
---------------------------
레지스트리는 Docker 이미지를 저장하고 공유하는 저장소다. 예를 들어 Docker Hub나 클라우드 제공 레지스트리를 사용할 수 있다.

예시 흐름:
  docker build -t username/myapp:1.0 .
  docker push username/myapp:1.0
  docker pull username/myapp:1.0

푸시 전에 레지스트리 로그인과 저장소 권한이 필요하다. 인증 토큰은 소스 코드에 기록하지 말고 CI 시스템의 비밀 변수로 보관한다.

7. 자동화 스크립트 작성 원칙
----------------------------
- 같은 입력이면 가능한 한 같은 결과가 나오도록 만든다.
- 오류가 발생하면 즉시 실패하게 하고, 원인을 확인할 수 있는 로그를 남긴다.
- 빌드, 테스트, 배포 단계를 분리해 어디서 실패했는지 알 수 있게 한다.
- 비밀번호, 토큰, 인증서 같은 비밀 정보를 이미지나 저장소에 넣지 않는다.
- 의존성 버전과 이미지 태그를 명시해 예기치 않은 변경을 줄인다.
- 컨테이너가 정상 동작하는지 로그와 헬스 체크로 확인한다.
- 자동 배포 전 테스트 환경에서 검증하고, 문제가 생겼을 때 되돌릴 방법을 준비한다.

8. 핵심 용어 요약
-----------------
이미지: 컨테이너를 만들기 위한 읽기 전용 실행 패키지
컨테이너: 이미지를 실행한 격리된 프로세스 환경
Dockerfile: 이미지 빌드 절차를 정의한 파일
Compose: 여러 컨테이너 서비스의 구성을 정의하고 함께 실행하는 도구
레지스트리: 이미지를 저장하고 배포하는 저장소
CI: 코드 변경 때 빌드와 테스트를 자동 수행하는 과정
CD: 검증된 애플리케이션을 배포 가능한 상태로 만들거나 자동 배포하는 과정

한 문장으로 정리하면, Docker 자동화는 Dockerfile로 이미지 생성 절차를 표준화하고, Compose와 CI/CD로 실행·검증·배포를 반복 가능하게 만드는 것이다.
