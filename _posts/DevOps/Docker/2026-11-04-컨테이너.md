# 정의
저장소(Registry)에 보관된 특정 도커 ==🔵이미지==를 실행한 것.
컨테이너 자체가 하나의 프로그램 실행이다. 즉, [[Docker 이미지]]를 기반으로 생성되어 **격리된 환경에서 실행되는 프로세스**.

- 이미지 = 읽기 전용 템플릿 (설계도)
- 컨테이너 = 그 이미지를 실행한 인스턴스 (하나의 이미지로 여러 컨테이너 생성 가능, `CONTAINER ID`로 구분)

# 특징
격리된 환경, 즉, 호스트 시스템과 독립적으로 실행되는 자체 실행 공간을 가짐
컨테이너 내 실행 프로세스들은 호스트나 다른 컨테이너와 분리된 상태에서 동작
시작시간이 짧음
메모리와 CPU 등 리소스를 효율적으로 사용

## 컨테이너 환경
현재 운영체제가 컨테이너 런타임으로 직접관리
- 하드웨어 → 운영체제 → 컨테이너 런타임 → 컨테이너(라이브러리 + App)
- 가상머신과 달리 게스트 OS가 없다 → [[컨테이너 기술]]

# 명령어
| 명령 | 설명 |
|---|---|
| `docker run <옵션> <이미지>` | 새 컨테이너 생성·실행 (이미지가 없으면 먼저 내려받음) |
| `docker ps` / `docker ps -a` | 실행 중 / 모든 컨테이너 목록 |
| `docker start <이름>` | 멈춘 컨테이너 시작 |
| `docker attach <이름>` | 실행 중인 컨테이너 터미널에 연결 |
| `docker exec -it <이름> bash` | 실행 중인 컨테이너에서 명령 실행 |
| `docker rename <기존> <새 이름>` | 이름 변경 |
| `docker stop <이름>` | 실행 중지 |
| `docker rm <이름>` | 삭제 |
| `docker commit <컨테이너> <이미지명>` | 컨테이너를 이미지로 저장 |

`docker container run` → `docker run`처럼 `container`를 빼고 줄여 쓸 수 있다.

## run 옵션
- `-i` : 연결(attach)되지 않아도 표준 입력 유지
- `-t` : 가상 터미널 할당 (컨테이너 안에서 터미널 사용)
- `-v 호스트경로:컨테이너경로` : 볼륨 마운트 (윈도우 폴더 ↔ 리눅스 디렉터리 공유)
- `-d` : 백그라운드 실행

# 실습 흐름 (미니콘다)
```bash
docker pull continuumio/miniconda3
docker run -it -v /c/rokey:/rokey continuumio/miniconda3 /bin/bash
# 컨테이너 안: apt-get update && apt-get install nano → python hello.py → exit
docker ps -a
docker rename <기존 이름> linux
docker start linux
docker attach linux
```
