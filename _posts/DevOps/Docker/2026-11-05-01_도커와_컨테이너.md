# 1. Docker와 컨테이너

## Docker란

Docker는 애플리케이션과 실행에 필요한 파일·라이브러리·설정을 이미지로 묶고, 이미지를 컨테이너로 실행·관리하는 플랫폼입니다. 개발, 테스트, 운영 환경 사이의 차이를 줄이고 애플리케이션을 빠르게 전달하는 데 활용합니다.

## 컨테이너와 가상 머신

| 구분 | 컨테이너 | 가상 머신 |
|---|---|---|
| 격리 단위 | 애플리케이션 프로세스와 실행 환경 | 게스트 운영체제 전체 |
| 운영체제 | 호스트 커널을 공유 | VM마다 게스트 OS 포함 |
| 일반적 특징 | 가볍고 시작이 빠름 | 더 많은 자원을 쓰지만 OS 수준 격리 제공 |

컨테이너가 호스트와 완전히 독립된 별도 운영체제를 갖는 것은 아닙니다. 커널을 공유하면서 프로세스, 파일 시스템, 네트워크 등을 격리합니다.

## 이미지와 컨테이너

- **이미지**: 컨테이너를 만들기 위한 읽기 전용 템플릿. 파일 시스템과 실행 설정을 포함합니다.
- **컨테이너**: 이미지를 실행한 격리된 프로세스 환경입니다. 컨테이너는 실행 중인 프로그램 하나 또는 관련 프로세스의 단위로 다룹니다.
- **레지스트리**: 이미지를 저장하고 공유하는 저장소입니다. Docker Hub가 대표적인 공개 레지스트리입니다.

이미지 하나로 여러 컨테이너를 만들 수 있습니다. 컨테이너 내부에만 저장한 데이터는 컨테이너 삭제 시 사라질 수 있으므로, 보존할 데이터는 볼륨 등 컨테이너 외부 저장소에 둡니다.

## Docker를 사용하는 이유

1. **환경 일관성**: 애플리케이션과 종속성을 함께 패키징해 실행 환경 차이를 줄입니다.
2. **빠른 배포와 확장**: 같은 이미지로 컨테이너를 만들거나 늘릴 수 있습니다.
3. **자원 효율성**: 일반적으로 VM보다 가벼운 실행 단위를 제공합니다.
4. **격리**: 애플리케이션별 실행 환경을 분리해 충돌을 줄입니다.

컨테이너 격리는 보안을 자동으로 보장하지 않습니다. 이미지 출처, 권한, 공개 포트, 비밀 정보 관리도 함께 고려해야 합니다.

## 기본 흐름

```text
애플리케이션과 설정 준비
        ↓
이미지 가져오기 또는 빌드
        ↓
이미지로 컨테이너 생성·실행
        ↓
로그와 상태 확인
        ↓
중지·재시작·교체
```
