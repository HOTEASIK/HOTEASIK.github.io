# 증상
GitHub에서 `ws_dsr/src` 폴더를 누르면 404가 난다. 브랜치·커밋·PR 순서는 맞았고 PR #7도 develop에 머지됐는데 폴더 내용이 안 보였다.

# 원인
- `ws_dsr/src` 안에 `.git` 폴더가 하나 더 있었다. `ahnisinc/cobot_rg2`를 clone할 때 같이 생긴 것.
- git은 이런 폴더를 다른 저장소를 가리키는 링크(서브모듈)로 보고, 파일 대신 커밋 번호 하나만 저장한다.
- 링크 대상을 적어 두는 `.gitmodules`가 없어서 GitHub에서 열면 404가 난다.

# 해결
새 브랜치 `fix_ws_dsr_src` (최신 `origin/develop` 기준)
- `src/.git`은 지우지 않고 `~/cobot_rg2_src_git_backup`으로 옮김
- 서브모듈 링크를 빼고 실제 파일 134개 커밋: `rokey`, `rokey1`, `rg2`, `onrobot-ros2`, `README.md`
- `doosan-robot2`(약 400MB)는 `src/.gitignore`에 넣어 저장소에서 제외. 받는 방법은 `src/README.md`에 적음
- 커밋: `03422d1`

```bash
git -C ~/rokey_team_ai_workspace push -u origin fix_ws_dsr_src
```
push 후 GitHub에서 `fix_ws_dsr_src → develop` PR을 만들어 머지하면 폴더 내용이 보인다.

# 참고
- 기존 브랜치 `hoteasik_ws_cobot_pjt_2`에서 빠졌던 src 수정 사항(`rokey/rokey/move.py`, `rokey1/`)도 이번 커밋에 들어감
- 다른 저장소를 clone해서 팀 저장소에 넣을 때는 커밋 전에 그 폴더 안의 `.git`을 지우거나 옮겨야 같은 문제가 안 생긴다.
