  404가 난 이유
  ws_dsr/src 폴더 안에 .git 폴더가 하나 더 있었어요. ahnisinc/cobot_rg2를 clone할
  때 같이 생긴 거예요. git은 이런 폴더를 "다른 저장소를 가리키는
  링크"(서브모듈)로 보고, 파일 대신 커밋 번호 하나만 저장해요. 그런데 이 링크가
  어디를 가리키는지 적어 두는 .gitmodules 파일이 없어서, GitHub에서 폴더를 누르면
  404가 났어요. 브랜치, 커밋, PR 순서는 맞았고, PR #7도 develop에 머지됐지만 이
  링크만 들어간 상태예요.

  한 일 (새 브랜치 fix_ws_dsr_src, 최신 origin/develop 기준)
  - src/.git은 지우지 않고 ~/cobot_rg2_src_git_backup으로 옮겨 뒀어요.
  - 서브모듈 링크를 빼고 실제 파일 134개를 커밋했어요: rokey, rokey1, rg2,
    onrobot-ros2, README.md.
  - 고르신 대로 doosan-robot2(약 400MB)는 src/.gitignore에 넣어 저장소에서
    뺐어요. 대신 팀원들이 따로 받는 방법을 src/README.md에 적어 뒀어요.
  - 커밋: 03422d1

한일
  1. 아래 명령으로 push해 주세요. 로그인 정보는 직접 입력하셔야 해요:
  ! git -C ~/rokey_team_ai_workspace push -u origin fix_ws_dsr_src
  2. GitHub에서 fix_ws_dsr_src → develop으로 PR을 만들고 머지해 주세요. 머지하면
     그 링크에서 폴더 내용이 보일 거예요.

  참고
  - 기존 브랜치 hoteasik_ws_cobot_pjt_2에서 src 쪽 수정 사항(rokey/rokey/move.py,
    rokey1/)은 원래 커밋에 들어가지 못했었는데, 이번 커밋에는 포함됐어요.
  - 앞으로 다른 저장소를 clone해서 팀 저장소에 넣을 때는, 커밋하기 전에 그 폴더
    안의 .git을 지우거나 다른 곳으로 옮겨야 같은 문제가 안 생겨요.
