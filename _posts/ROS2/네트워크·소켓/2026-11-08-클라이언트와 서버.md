# 클라이언트와 서버

## 정의·핵심
- **서버**: 창구를 열고 **기다리는 쪽**. 문 열고 손님을 기다리는 가게 (기초 2차시).
- **클라이언트**: 먼저 찾아가 **요청하는 쪽**. 손님.
- **성능이 아니라 역할이다**: "서버가 더 센 컴퓨터" ✗. 내 노트북도 창구를 열고 기다리면 서버, 먼저 요청하면 클라이언트.
- **서버 먼저, 클라이언트 나중**: 개통도 안 한 번호로는 전화를 걸 수 없다 — 규칙이 아니라 상식. 순서가 어긋나면 `ConnectionRefusedError`(닫힌 가게에서 헛걸음).
- **블로킹**: `accept`·`recv`를 만나면 그 줄에서 멈춰 상대를 기다린다. "기다리는 중..."에서 화면이 멎는 건 **정상** — 멈춘 줄 알고 Ctrl+C로 끄면 통화를 받기도 전에 전화기를 끄는 셈.
- **ROS와 비교**
  - ROS2 **서비스**도 서버·클라이언트 구조(요청-응답)지만, 클라이언트는 `wait_for_service()`로 서버를 기다릴 수 있고 IP·포트를 몰라도 이름으로 찾는다.
  - ROS2 **토픽**은 서버·클라이언트가 아니라 발행·구독이라 **켜는 순서도 상관없다** (기초 3차시 "이름만 맞추면 그냥 된다").

## 원리·구조
```
서버:  socket → bind → listen → accept(블로킹 대기) → recv/send → close
클라:  socket ─────────────────→ connect ───────────→ send/recv → close
```

## 코드 예시
```python
# 서버를 먼저 켜지 않고 클라이언트부터 접속하면 → ConnectionRefusedError
import socket
probe = socket.socket(); probe.bind(("127.0.0.1", 0))
port = probe.getsockname()[1]; probe.close()      # 아무도 안 듣는 포트 하나 확보
c = socket.socket(); c.settimeout(10)             # Windows는 거부 응답이 2초쯤 늦게 온다
try:
    c.connect(("127.0.0.1", port))
except ConnectionRefusedError:
    print("ConnectionRefusedError → 서버를 먼저 켠다")
finally:
    c.close()
```
