# TCP와 UDP

## 정의·핵심
- **TCP**: 보낸 게 잘 갔는지 일일이 확인한다 — **등기우편**. 먼저 연결을 맺고, 빠진 건 재전송하고, 순서를 지킨다.
- **UDP**: 확인 없이 그냥 던진다 — **엽서**. 연결 없이 바로 전송, 빠르지만 분실 가능 (기초 2차시).
- **무엇이 더 좋은 게 아니라, 무엇이 더 빠짐없어야 하느냐로 갈린다**
  - 카메라 영상 → 관제 화면: **UDP**. 1초에 수십 장이 흐르니 한 장 빠져도 다음 장이 곧 온다. 빠진 장을 다시 받느라 화면이 늦으면 더 위험.
  - "앞으로 1미터 가고 멈춰": **TCP**. 한 글자도 빠지면 안 되고 순서도 뒤바뀌면 안 된다. "멈춰"가 분실되면 로봇이 벽을 향해 계속 달린다.
  - 같은 로봇 안에서도 영상은 UDP, 명령은 TCP — 데이터의 성격에 따라 갈라 쓴다.
- 실습 소켓 코드는 TCP(`SOCK_STREAM`) — 메시지·파일 통신이라 한 자도 빠지면 안 되기 때문.
- **ROS2와의 연결**: DDS는 기본적으로 UDP 위에서 돌고, 그 위에서 QoS **Reliability**로 "확실하게(RELIABLE, 재전송) / 빠르게(BEST_EFFORT)"를 고른다 — TCP/UDP 비유를 한 걸음 더 간 것 (실습 2차시).

## 원리·구조
| 구분 | TCP | UDP |
|---|---|---|
| 비유 | 등기우편(수령 확인) | 엽서(그냥 던짐) |
| 신뢰성 | 높음(빠진 건 재전송) | 낮음(분실 가능) |
| 속도 | 상대적으로 느림 | 빠름 |
| 연결 | 먼저 연결을 맺음 | 연결 없이 바로 |
| 파이썬 | `SOCK_STREAM` | `SOCK_DGRAM` |
| 대표 용도 | 웹·파일 전송·이메일·명령 | 실시간 영상·게임·음성 |

## 코드 예시
```python
# UDP: 연결(connect/accept) 없이 바로 던지고 받는다
import socket
rx = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
rx.bind(("127.0.0.1", 0)); rx.settimeout(2)
addr = rx.getsockname()
tx = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
tx.sendto("frame 1".encode(), addr)            # 엽서 던지기
data, _ = rx.recvfrom(1024)
print(data.decode())                           # frame 1
print(socket.SOCK_STREAM != socket.SOCK_DGRAM) # True  (TCP와 UDP는 다른 소켓 종류)
tx.close(); rx.close()
```
