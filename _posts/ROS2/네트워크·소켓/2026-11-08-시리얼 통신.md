# 시리얼 통신

## 정의·핵심
- **정의**: 데이터를 한 줄로 세워 **한 비트씩 차례로** 보내는 방식. 프로그램끼리(소켓)가 아니라 **회로끼리** 전선 한두 가닥으로 직접 말한다 (기초 2차시).
- **소켓과 비교**: 소켓은 IP·포트가 주소이고 운영체제·네트워크라는 두꺼운 층을 거친다(도시 간 통신). 시리얼은 두꺼운 층을 건너뛰고 전선에 직접 전기 신호를 싣는다(옆방과의 대화) — 멀리 못 가는 대신 단순하고 확실. OS가 멈추고 네트워크가 죽어도 선만 살아 있으면 끝까지 대화한다.
- **양쪽 설정(약속)이 같아야 한다** — 소켓에서 겪은 "양쪽 약속"이 물리 배선에서도 똑같이 성립.
  - 보율(baud rate): 1초에 신호 몇 개 (예 115200). 안 맞으면 박자가 어긋나 글자가 통째로 깨짐.
  - 데이터 비트: 한 글자를 몇 비트로 (보통 8).
  - 패리티 비트: 1의 개수로 오류 검사할지.
  - 정지 비트: 한 글자의 끝 표시 (보통 1). 흔히 "115200 8N1".
- **UART vs RS-232C vs RS-485**: UART는 비트를 줄 세우는 법, RS-232C·RS-485는 신호를 전기적으로 흘리는 규약.
  - RS-232C: 1:1, 짧은 거리(수 m), 노이즈에 약함 — 옛 PC 시리얼 포트.
  - RS-485: 1:N 버스(멀티드롭), 수백 m~1km, 차동 신호로 노이즈에 강함 — 산업 자동화·로봇·센서망. 기기마다 주소를 붙여 "3번, 온도 보고해"처럼 부르면 3번만 답한다.
- **로봇은 시리얼로 말한다**: 메인 컴퓨터(라즈베리파이 등, ROS 구동) ─USB·UART→ 제어보드(TurtleBot3의 OpenCR) → 모터에 전류 → 바퀴 회전수·센서값을 다시 시리얼로 보고. 맨 위엔 ROS 토픽, 가운데엔 소켓·DDS, 맨 아래엔 시리얼.
- 리눅스에서 USB 시리얼은 `/dev/ttyUSB0`·`/dev/ttyACM0` 파일로 잡히고, 권한은 `dialout` 그룹.

## 원리·구조
```
'A' = 0x41 = 0100 0001  →  [start 0][1 0 0 0 0 0 1 0 (LSB부터)][stop 1]   (8N1, 10비트)
```
$$\text{초당 글자 수} \approx \frac{\text{보율}}{10}\quad(115200 \Rightarrow 11520\ \text{글자/초})$$

## 코드 예시
```python
# 8N1 프레임 만들기/읽기 — 양쪽 비트 순서 약속이 다르면 다른 글자가 된다
def frame(ch):                           # start(0) + LSB부터 8비트 + stop(1)
    b = ord(ch)
    return [0] + [(b >> i) & 1 for i in range(8)] + [1]
def read(bits, lsb_first=True):
    data = bits[1:9] if lsb_first else bits[1:9][::-1]
    return chr(sum(bit << i for i, bit in enumerate(data)))
f = frame("A")
print(f)                                 # [0, 1, 0, 0, 0, 0, 0, 1, 0, 1]
print(read(f), ord(read(f, lsb_first=False)))   # A 130  ← 순서 약속이 어긋나면 엉뚱한 값
print(115200 // 10)                      # 11520
```
