# setup.cfg

## 정의·핵심
- **정의**: ament_python 패키지에서 **실행 파일을 어느 폴더에 설치할지** setuptools에 알려 주는 설정 파일 (입문 1차시).
- **내용은 거의 고정**: `pkg create`가 만들어 준 두 칸을 그대로 둔다 — 실행 스크립트를 `$base/lib/<패키지>` 아래에 설치하라.
- **왜 필요한가**: `ros2 run 패키지 실행이름`은 `install/<패키지>/lib/<패키지>/실행이름`을 찾는다. 이 파일이 없거나 패키지 이름이 틀리면 실행 파일이 `bin/`에 깔려 `No executable found`가 난다.
- **패키지 이름을 바꿀 때 함정**: setup.py의 `package_name`만 바꾸고 setup.cfg의 경로를 그대로 두면 실행 파일이 엉뚱한 곳에 깔린다 → package.xml·setup.py·setup.cfg·resource 마커·모듈 폴더 이름을 **모두 같이** 바꾼다.

## 원리·구조
```ini
[develop]
script_dir=$base/lib/my_py_pkg
[install]
install_scripts=$base/lib/my_py_pkg
```
```
install/my_py_pkg/
 ├─ lib/my_py_pkg/my_publisher                   ← ros2 run이 찾는 실행 파일 (setup.cfg)
 ├─ lib/python3.12/site-packages/my_py_pkg/      ← 모듈
 └─ share/my_py_pkg/package.xml                  ← data_files
```

## 코드 예시
```python
# setup.cfg를 실제로 읽어 설치 경로 확인 (표준 라이브러리 configparser)
import configparser
cfg = configparser.ConfigParser(interpolation=None)
cfg.read_string("[develop]\nscript_dir=$base/lib/my_py_pkg\n[install]\ninstall_scripts=$base/lib/my_py_pkg\n")
for sec, key in [("develop", "script_dir"), ("install", "install_scripts")]:
    print(sec, cfg[sec][key].replace("$base", "install/my_py_pkg"))
# develop install/my_py_pkg/lib/my_py_pkg
# install install/my_py_pkg/lib/my_py_pkg
pkg = "my_py_pkg"
print(all(v.endswith("/" + pkg) for v in (cfg["develop"]["script_dir"], cfg["install"]["install_scripts"])))  # True
```
