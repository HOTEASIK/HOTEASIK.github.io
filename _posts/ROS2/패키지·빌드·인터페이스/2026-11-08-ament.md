# ament

## 정의·핵심
- **정의**: ROS2의 **빌드 표준(규격)**. 패키지가 어떻게 생겨야 하고 어떻게 설치·색인돼야 하는지를 정한다. ROS1의 catkin을 대신한다 (입문 1차시).
- **ament는 규격, colcon은 조립 기계**: 두 용어를 가르면 평생 안 헷갈린다. ament_python 패키지도 ament_cmake 패키지도 colcon이 빌드한다.
- **빌드 타입이 곧 성격**: `--build-type ament_python`은 「나는 파이썬 규격 패키지」, `ament_cmake`는 「나는 C++(CMake) 규격 패키지」.
- **인터페이스 패키지는 ament_cmake**: rosidl 코드 생성이 CMake 빌드 단계 안에서 돌기 때문 (입문 2차시).
- **ament_index**: 설치된 패키지를 찾는 색인. `resource/패키지이름` 빈 마커 파일이 `share/ament_index/resource_index/packages/`에 설치돼 「이 패키지가 있다」를 알린다.
- **ament_lint**: `test/` 아래 copyright·flake8·pep257 같은 코드 스타일 검사.

## 원리·구조
| 구분 | ament_python | ament_cmake |
|---|---|---|
| 주 언어 | Python | C++ (및 인터페이스) |
| 빌드 정의 파일 | setup.py · setup.cfg | CMakeLists.txt |
| 컴파일 | 안 함(인터프리터) | 함(기계어) |
| `--symlink-install` 효과 | 크다 — 재빌드 거의 불필요 | 작다 — 컴파일 필요 |
| package.xml `<buildtool_depend>` | 없음 | `ament_cmake` |
| `<test_depend>` | ament_copyright·flake8·pep257·python3-pytest | ament_lint_auto·ament_lint_common |

## 코드 예시
```python
# 패키지 폴더를 보고 빌드 타입 추정
def build_type(files):
    if "CMakeLists.txt" in files: return "ament_cmake"
    if "setup.py" in files: return "ament_python"
    return "알 수 없음 — package.xml <export><build_type> 확인"
print(build_type(["package.xml", "setup.py", "setup.cfg", "resource", "test"]))   # ament_python
print(build_type(["package.xml", "CMakeLists.txt", "include", "src"]))           # ament_cmake
```
```bash
ros2 pkg create --build-type ament_python --license Apache-2.0 my_py_pkg
ros2 pkg create --build-type ament_cmake  --license Apache-2.0 my_cpp_pkg
ls /opt/ros/jazzy/share/ament_index/resource_index/packages | head
```
