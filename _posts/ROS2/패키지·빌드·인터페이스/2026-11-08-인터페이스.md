# 인터페이스

## 정의·핵심
- **정의**: 노드와 노드가 주고받을 **데이터의 모양을 미리 정의해 둔 약속** — 통신에 쓸 서식, 곧 계약서 (입문 2차시).
- **모양을 정하지, 값을 정하지 않는다**: Spawn은 「어디에 어떤 이름으로 한 마리 낸다」는 칸만 약속하고, 좌표가 5.0인지 이름이 leo인지는 부를 때 채운다. 한 장을 잘 설계하면 수천 번의 통신이 같은 규칙을 따른다.
- **계약서가 못 박는 두 가지**: **칸 이름**(보낸 칸을 같은 이름으로 꺼낸다)과 **칸 타입**(숫자·글자·참거짓을 두 쪽이 똑같이 이해). 이름만 같고 타입이 다르면 결국 어긋난다.
- **칸 없는 한 줄의 고생**: `"leo,5.0,2.0,1.5"`를 보내면 받는 쪽이 자르고 순서를 외우고 숫자로 바꿔야 한다. 순서를 하나만 틀려도 **에러 없이** 거북이가 엉뚱하게 움직인다 — 협업에서 무너진다.
- **언어 중립**: `int64`·`float64` 같은 ROS 공용 타입으로 한 장 적으면 빌드 때 rosidl이 파이썬·C++ 코드를 자동 생성 → 파이썬 노드와 C++ 노드가 같은 양식으로 통한다.
- **세 종류**: `.msg`(토픽, 방송), `.srv`(서비스, 전화 문의), `.action`(액션, 택배). 구분선 `---` 개수가 0·1·2.
- **먼저 찾고, 없으면 만든다**: 좌표·자세·영상·센서값은 표준(common_interfaces)에 이미 있다. 표준이 있는데 `MyPosition.msg`를 새로 만들면 생태계와 단절된 섬이 된다.
- **이름 관례**: 메시지는 명사(`TurtleGoal`, `RobotState`), 서비스·액션은 동사(`SetTurtleName`, `AddThreeInts`, `ComputePath`).

## 원리·구조
```
양식 한 장(.msg/.srv/.action) ──빌드(rosidl)──→ 파이썬 클래스 + C++ 구조체 ──source──→ 노드가 import
```
| 양식 | 구분선 | 방향 | 적합한 상황 |
|---|---|---|---|
| .msg | 0개 | 한 방향 흘려보내기 | 센서값·좌표 스트림 |
| .srv | 1개 (요청/응답) | 묻고 한 번 답 | 즉시 끝나는 계산·설정 |
| .action | 2개 (목표/결과/피드백) | 진행 보고 + 취소 | 오래 걸리는 이동 |

## 코드 예시
```python
# 콤마로 이어 붙인 한 줄 vs 칸이 정해진 서식
raw = "leo,5.0,2.0,1.5"                       # 보내는 쪽: 이름,x,y,속도
name, speed, x, y = raw.split(",")            # 받는 쪽은 이름,속도,x,y로 알고 있다
print("x =", x)                                # x = 2.0  ← 에러 없이 틀림

from dataclasses import dataclass
@dataclass
class TurtleGoal:
    turtle_name: str; x: float; y: float; speed: float
g = TurtleGoal(turtle_name="leo", x=5.0, y=2.0, speed=1.5)
print("x =", g.x)                              # x = 5.0  ← 칸 이름으로 꺼낸다
```
