# colcon

## 정의·핵심
- **정의**: 워크스페이스 안의 패키지들을 **ament 규격대로 한꺼번에 빌드하는 도구**(collective construction). ament가 상자의 규격이라면 colcon은 그 규격대로 조립하는 기계 (기초 5차시, 입문 1차시).
- **파이썬도 빌드하는 까닭**: ROS의 빌드는 번역보다 **정돈·등록**에 가깝다 — 코드를 ROS가 찾을 자리(install)에 배치하고, `entry_points`를 실제 실행 파일로 만들고, package.xml 정보를 색인에 등록한다. C++은 진짜 컴파일도 일어난다.
- **빌드 순서를 스스로 정한다**: 각 패키지의 package.xml 의존성을 읽어 A를 먼저, A에 기대는 B를 나중에. 의존성을 안 적으면 순서가 어긋나 「분명 있는데 못 찾는」 오류.
- **결과 읽기**: `Starting >>>` → `Finished <<< 이름 [초]` → `Summary: N packages finished`. Starting은 알파벳순, Finished 순서는 매번 갈릴 수 있다. 실패면 `Failed <<<` 바로 위 몇 줄의 **첫 영어 문장**을 읽는다.
- **빌드와 source는 한 세트**: 빌드 → `source install/setup.bash` → `ros2 run`.
- **재현성**: 워크스페이스(자리) + package.xml(의존성 신고) + colcon(표준 빌드) + source(환경) — 네 가지가 맞물리면 다른 컴퓨터·여섯 달 뒤의 나도 똑같이 빌드한다.

## 원리·구조
| 옵션 | 하는 일 | 언제 |
|---|---|---|
| (없음) | 워크스페이스의 모든 패키지 | 처음 받은 워크스페이스 |
| `--packages-select 이름` | 그 패키지만 | 하나만 고쳤을 때 |
| `--packages-up-to 이름` | 그 패키지 + 그것이 의존하는 것까지 | 의존 패키지를 처음 빌드 |
| `--symlink-install` | 복사 대신 원본을 가리키는 링크 | 파이썬 코드를 자주 고칠 때 |

- `--symlink-install`이어도 **entry_points·data_files를 바꾸거나 파일을 새로 추가**하면 다시 빌드해야 한다.

## 코드 예시
```python
# colcon처럼 package.xml 의존성으로 빌드 순서 정하기 (위상 정렬)
from graphlib import TopologicalSorter
deps = {"my_interfaces": set(), "my_py_pkg": {"my_interfaces"}, "my_first_package": set(),
        "patrol_bringup": {"my_py_pkg", "my_interfaces"}}
print(list(TopologicalSorter(deps).static_order()))
# ['my_interfaces', 'my_first_package', 'my_py_pkg', 'patrol_bringup']

def up_to(pkg):                      # --packages-up-to
    need, stack = set(), [pkg]
    while stack:
        p = stack.pop()
        if p not in need: need.add(p); stack += deps[p]
    return [p for p in TopologicalSorter(deps).static_order() if p in need]
print(up_to("my_py_pkg"))            # ['my_interfaces', 'my_py_pkg']
```
```bash
cd ~/ros2_ws
colcon build --packages-select my_py_pkg
colcon build --symlink-install
source install/setup.bash
ros2 pkg list | grep my_py_pkg
```

## 수업 메모

### 방법

1. 작업 폴더안에 src 폴더로 이동
	cd
2. 패키지 만들기
	ros2 pkg create --build-type ament_python my_pkg --dependencies rclpy
3. 작업 폴더로 이동
	cd ..
4. colcon build
	빌드 결과 폴더: `build/`, `install/`, `log/
	`src` 안에서 colcon build를 하면 안됨
		패키지 구조를 올바르게 인식 못함
		그래도 했으면 [[클린 빌드]]실행
5. source install/setup.bash
	underlay 먼저 소스 그후 overlay 소스
		환경 변수의 우선순위를 올바르게 설정하여 내가 수정한 코드가 시스템 기본 버전보다 먼저 인식되도록 하기 위함
		- 같은 이름의 패키지가 있으면 overlay가 우선합니다.
	
	source를 빠뜨리면: `Package not found`가 나고 탭 자동완성도 안 됩니다.
	다른 터미널 마다 source 필요
		source는 현재 터미널에만 적용되기 때문
