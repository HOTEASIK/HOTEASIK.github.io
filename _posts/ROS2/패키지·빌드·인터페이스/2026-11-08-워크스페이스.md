# 워크스페이스

## 정의·핵심
- **정의**: 내가 손보는 패키지들을 한곳에 모아 **함께 빌드하는 작업 단위 폴더**. 관례상 `~/ros2_ws` (기초 5차시, 입문 1차시).
- **비유**: 작업장 건물. 안의 `src` 방에 상자(패키지)를 늘어놓으면 colcon이라는 조립 기계가 한꺼번에 조립한다.
- **네 폴더**
  - `src`: 패키지 소스 — **내가 직접 만지는 유일한 곳**.
  - `build`: 조립 중 부산물(임시 작업 공간).
  - `install`: 완성품 — `ros2 run`이 실제로 보는 곳, `source` 대상.
  - `log`: 빌드·실행 기록.
- **「건드리는 건 src뿐」 은 안전장치**: 내 코드와 결과물을 섞지 않아야 꼬였을 때 `build install log`만 지우고 다시 빌드할 수 있다. 백업하거나 넘길 때도 `src`만.
- **빌드는 반드시 워크스페이스 루트에서**: `src` 안에서 `colcon build`를 치면 오류도 경고도 없이 `src/build` 등이 생겨 산출물이 두 벌 — 폴더를 열어야 보이는 무서운 함정.
- **시스템 영역과 분리**: ROS 본체는 `/opt/ros/jazzy`, 내 코드는 홈 아래 `~/ros2_ws` — 섞으면 ROS 업데이트 때 휩쓸려 사라질 수 있다.
- **작업대에는 지금 쓰는 것만**: 모든 패키지를 한 워크스페이스에 몰아넣지 않는다 — 빌드가 느려지고 꼬일 곳이 늘어난다.

## 원리·구조
```
~/ros2_ws/                 ← 여기서 colcon build
 ├─ src/                   ← 내가 쓴 것 (git으로 관리)
 │   ├─ my_first_package/
 │   ├─ my_py_pkg/
 │   └─ my_interfaces/
 ├─ build/   ┐
 ├─ install/ ├ colcon이 만든다 — 지워도 다시 생긴다
 └─ log/     ┘
```

## 코드 예시
```python
# src 안에서 빌드했는지 점검: build/install/log가 src 아래 생겼나
import tempfile, os
ws = tempfile.mkdtemp()
for d in ["src/my_py_pkg", "build", "install", "log", "src/build"]:   # src/build는 잘못 생긴 것
    os.makedirs(os.path.join(ws, d))
def check(ws):
    bad = [d for d in ("build", "install", "log") if os.path.isdir(os.path.join(ws, "src", d))]
    return f"⚠ src 안에 {bad} — 지우고 루트에서 다시 빌드" if bad else "OK"
print(check(ws))     # ⚠ src 안에 ['build'] — 지우고 루트에서 다시 빌드
```
```bash
mkdir -p ~/ros2_ws/src
cd ~/ros2_ws && colcon build
ls ~/ros2_ws          # build  install  log  src
```
