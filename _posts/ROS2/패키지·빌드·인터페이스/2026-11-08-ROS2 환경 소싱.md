# ROS2 환경 소싱

## 정의·핵심
- **정의**: `source …/setup.bash`로 그 셸이 ROS와 내 패키지의 위치·실행 정보를 **환경 변수로 읽어 들이게** 하는 것. 리눅스의 `$PATH`가 여기서 살아난다 — 터미널에게 패키지를 어디서 찾을지 길을 알려 주는 것이 전부 (입문 1차시).
- **새 터미널은 빈손으로 태어난다**: 이전 창에서 한 source·export를 기억하지 못한다.
- **빌드 한 번, source 매번** (냉장고 비유): 빌드 = 요리해 냉장고(install)에 넣기 — 코드를 바꿀 때만. source = 손님에게 냉장고 위치 알려 주기 — 새 터미널마다.
- **시작 전 세 줄 점검**: 짐작하지 말고 확인한다. 새 장비·동료 PC를 받았을 때 현장에서 먼저 하는 일도 이 세 줄.
  - `printenv ROS_DISTRO` → `jazzy`
  - `ros2 --help` → Commands: 목록
  - `which colcon` → `/usr/bin/colcon`
- **바뀌는 변수**: `AMENT_PREFIX_PATH`, `PATH`, `PYTHONPATH`, `LD_LIBRARY_PATH`, `ROS_DISTRO` 등.
- **편의**: `.bashrc`에 underlay와 alias(`cb='colcon build'`, `sr='source install/setup.bash'`).

## 원리·구조
| 증상 | 원인 | 해결 |
|---|---|---|
| `ros2: command not found` | 본체 source 안 함 | `source /opt/ros/jazzy/setup.bash` |
| `printenv ROS_DISTRO` 비어 있음 | 그 터미널에 ROS 안 켜짐 | 위와 같다 |
| `which colcon` 비어 있음 | colcon 미설치 | `python3-colcon-common-extensions` 설치 |
| `Package 'my_py_pkg' not found` | 빌드 후 overlay source 안 함 | `source ~/ros2_ws/install/setup.bash` |
| export 값이 새 창에서 사라짐 | export는 그 터미널에서만 산다 | `.bashrc`에 |

## 코드 예시
```python
# 세 줄 점검을 환경 사전으로 흉내
def check(env):
    out = []
    out.append("ROS_DISTRO=" + env.get("ROS_DISTRO", "(비어 있음 → 본체 source)"))
    out.append("ros2 " + ("OK" if "/opt/ros/jazzy/bin" in env.get("PATH", "") else "command not found"))
    out.append("colcon " + ("OK" if env.get("has_colcon") else "없음 → python3-colcon-common-extensions"))
    return out
print(check({"PATH": "/usr/bin"}))
# ['ROS_DISTRO=(비어 있음 → 본체 source)', 'ros2 command not found', 'colcon 없음 → python3-colcon-common-extensions']
print(check({"PATH": "/opt/ros/jazzy/bin:/usr/bin", "ROS_DISTRO": "jazzy", "has_colcon": True}))
# ['ROS_DISTRO=jazzy', 'ros2 OK', 'colcon OK']
```
```bash
printenv ROS_DISTRO && ros2 --help | head -3 && which colcon
echo 'source /opt/ros/jazzy/setup.bash' >> ~/.bashrc
echo "alias cb='colcon build'" >> ~/.bashrc
```
