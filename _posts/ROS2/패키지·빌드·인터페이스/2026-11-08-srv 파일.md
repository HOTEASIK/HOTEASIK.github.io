# srv 파일

## 정의·핵심
- **정의**: 서비스용 양식. `srv/` 폴더에 두고 **구분선 `---` 하나**로 위는 요청(보낼 것), 아래는 응답(받을 것) (입문 2차시).
- **구분선이 경계**: 빠뜨리면 ROS가 메시지로 오해한다. 작대기는 **정확히 셋** — `--`는 인식 안 됨.
- **응답이 비어도 된다**: `turtlesim/srv/SetPen`은 구분선 아래가 비어 있다 — 시키기만 하고 돌려받을 게 없는 서식.
- **응답은 두 칸 관례**: `bool success` + `string message` — success만으로는 왜 실패했는지 알 길이 없다(「이미 같은 이름이 존재한다」).
- **칸을 정하는 질문**: 요청 = 「무엇을 보내야 일이 되는가」, 응답 = 「끝나면 무엇을 알아야 하는가」.
- **양식 고르기 두 물음**: ① 응답이 필요한가? 아니오 → `.msg` ② 즉시 끝나는가? 예 → `.srv`, 아니오(오래·중간 경과·취소) → `.action`. 5초 걸리는 로봇팔 이동을 서비스로 만들면 진행도 모르고 취소도 못 한다. 반대로 요청-응답을 메시지 둘로 흉내 내면 「내 요청의 답」 짝이 보장되지 않는다.
- **빌드 결과**: rosidl이 `이름_Request`·`이름_Response` 둘로 만든다.

## 원리·구조
```
# srv/AddThreeInts.srv          # srv/SetTurtleName.srv
int64 a                         string new_name      # 요청
int64 b                         ---
int64 c                         bool success         # 응답
---                             string message
int64 sum
```

## 코드 예시
```python
# 구분선 개수로 양식 종류 판별 + 요청/응답 나누기
def split_iface(text):
    parts = [p.strip().splitlines() for p in text.split("\n---\n")]
    kind = {1: "msg", 2: "srv", 3: "action"}.get(len(parts), "?")
    return kind, parts
kind, (req, res) = split_iface("int64 a\nint64 b\nint64 c\n---\nint64 sum")
print(kind, req, res)          # srv ['int64 a', 'int64 b', 'int64 c'] ['int64 sum']
print(split_iface("int64 a\n--\nint64 sum")[0])   # msg  ← 작대기 둘이면 구분선이 아니다
print(split_iface("uint8 r\nuint8 off\n---\n")[1][1])   # []  ← SetPen처럼 빈 응답
```

```bash
ros2 interface show my_interfaces/srv/AddThreeInts
ros2 interface show turtlesim/srv/SetPen
```
