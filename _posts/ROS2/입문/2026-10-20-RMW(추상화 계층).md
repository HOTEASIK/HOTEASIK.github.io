# 정의
ROS 2가 특정 DDS 제품에 종속되지 않도록, 어떤 DDS든 똑같은 방식으로 쓸 수 있게 맞춰주는 통신 어댑터 플러그
	  즉 각 DDS에 유연하게 대체 가능함

**RMW (ROS MiddleWare interface)**

# 계층
```
rclpy (Python) / rclcpp (C++)    ← 우리가 쓰는 API
        rcl                       ← 공통 C 라이브러리
        rmw                       ← 추상화 계층 (어댑터)
rmw_fastrtps_cpp / rmw_cyclonedds_cpp / ...   ← DDS 구현별 플러그
Fast DDS / Cyclone DDS / ...      ← 실제 DDS
```
우리 코드는 위쪽 API만 쓰므로, 아래 DDS를 바꿔도 코드를 고칠 필요가 없다.

# 특징
- 같은 ROS2라도 어떤 DDS 구현을 깔았느냐에 따라 세부 동작이 조금씩 다를 수 있다 — 통신 문제를 다룰 때 「어떤 미들웨어를 쓰는가」가 단서가 된다
- 강의 실습 환경: **`rmw_fastrtps_cpp`** (Jazzy 기본)
- 로그 문턱을 debug로 낮추면 `[rmw_fastrtps_cpp]` 이름표가 붙은 내부 로그가 보인다
- 메시지 형식이 어긋나면 `RMWError: failed to deserialize ROS message`로 멈춘다

# 바꾸기
```bash
export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp   # 해당 rmw 패키지가 설치되어 있어야 함
ros2 doctor --report | grep -i middleware       # 지금 쓰는 미들웨어 확인
```
통신하는 노드끼리는 같은 RMW를 쓰는 편이 안전하다.
