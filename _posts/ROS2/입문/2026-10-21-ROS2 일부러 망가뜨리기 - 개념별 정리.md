# ROS2 일부러 망가뜨리기 — 개념별 정리

> 출처: ROS2 기초 1~5차시, 입문 1~9차시 강의 자료의 「일부러 막혀 보기 / 깨뜨려 보기」 실습과 오류 해독 표

## 0. 왜 일부러 망가뜨리나

- 잘 되는 화면만 따라 치면 혼자 할 때 똑같이 막힌다 → 한 번 깨뜨리고 고치면 같은 오류에 당황하지 않는다 ("오류 메시지는 적이 아니라 길 안내")
- 소켓으로 직접 통신을 짜며 IP·포트·순서·인코딩을 손으로 맞추는 고생을 해 봐야 ROS의 자동화가 와닿는다
- **조용한 실패**를 알아보는 눈을 기른다 — 많은 고장은 오류 없이 빌드 성공·화면 침묵으로 나타난다
- **진단 사다리**: 바깥(노드·이름·타입·연결)부터 명령으로 확인하고, 그다음 코드 안을 본다

## 1. 리눅스 기본 — 권한

| 망가뜨리기 | 증상 | 원인 | 해결 |
|---|---|---|---|
| `sudo` 없이 `apt install tree` | `Permission denied` | 설치는 관리자 권한 필요 | `sudo` 붙이기 |
| 스크립트 만들고 바로 `./run.sh` | `Permission denied` | 실행 권한(x) 없음 (`-rw-r--r--`) | `chmod +x run.sh` |
| `apt update` 없이 설치 | `Unable to locate package` | 패키지 목록 미갱신 | `sudo apt update` 먼저 |

- 권한 숫자: r=4, w=2, x=1 → `chmod 755` = `-rwxr-xr-x`

## 2. 통신의 약속 (소켓 → ROS가 대신 해 주는 것)

| 망가뜨리기 | 증상 | 원인 | 해결 |
|---|---|---|---|
| 서버 안 켜고 클라이언트부터 | `ConnectionRefusedError` | 기다리는 서버 없음 | 서버 먼저 |
| 같은 포트로 재실행 | `Address already in use` | 포트 점유 | Ctrl+C 후 재실행 / 포트 변경 |
| `decode` 빼기 | `b'...'` 깨진 글자 | 바이트 그대로 출력 | `.decode()` |
| `encode` 빼기 | `TypeError ... bytes` | 문자열을 바로 전송 | `.encode()` |
| 클라이언트 포트만 9091 | 영영 연결 안 됨 | 양쪽 약속 불일치 | 양쪽 일치 |

- 핵심: 통신은 양쪽 약속이 맞아야 성립 → ROS는 **이름만 맞추면** 연결·순서를 알아서 처리

## 3. 환경 설정 — source (underlay / overlay)

| 망가뜨리기 | 증상 | 원인 | 해결 |
|---|---|---|---|
| source 없이 `ros2` | `ros2: command not found` | ROS 본체(underlay) 미적용 | `source /opt/ros/jazzy/setup.bash` |
| 빌드 후 overlay source 안 함 | `Package 'my_py_pkg' not found` / `pkg list`에 없음 | 워크스페이스 미적용 | `source ~/ros2_ws/install/setup.bash` |
| 새 터미널에서 source 없이 호출 | `The passed ... type is invalid` | 그 터미널이 양식 패키지를 모름 (양식 이름 오타일 때도 같은 문장) | source 후 재시도 · 이름 확인 |
| overlay 없이 Jupyter 실행 | `No module named 'my_interfaces'` | 환경은 띄우는 순간 결정 | 노트북 끄고 overlay 켠 터미널에서 다시 실행 (`!source`는 sh라 안 됨) |

- underlay는 `.bashrc`에 넣어도 되고, overlay는 빌드 후 직접 친다
- `export`는 그 터미널에서만 유효

## 4. 패키지 만들기

| 망가뜨리기 | 증상 | 원인 | 해결 |
|---|---|---|---|
| 같은 이름으로 `pkg create` | `Aborted! The directory already exists` | 이미 존재 (덮어쓰지 않아 안전) | 다른 이름 / 기존 폴더 정리 |
| 이름을 `--dependencies` 뒤에 | `required: package_name` | 의존성 목록이 이름까지 삼킴 | 이름을 `--dependencies` 앞으로 |
| 이름에 하이픈 `my-pkg` | 빌드는 되고 나중에 못 찾음 | 파이썬 모듈명에 `-` 불가 | 소문자 + 언더스코어 |
| `--license` 생략 | `Unknown license` 경고 | — | `--license Apache-2.0` |

## 5. 빌드 (colcon)

| 망가뜨리기 | 증상 | 원인 | 해결 |
|---|---|---|---|
| `src` 안에서 빌드 | **오류 없이 성공**, `src`에 build/install/log 생김 | 빌드 위치 오류 | 세 폴더 지우고 루트(`~/ros2_ws`)에서 빌드 |
| colcon 미설치 | `colcon: command not found` | — | `sudo apt install python3-colcon-common-extensions` |
| conda 켜진 상태 | 파이썬 import/버전 충돌 | conda 파이썬 사용 | `conda deactivate` |
| 클린 후 `--packages-select my_py_pkg`만 | `Check that the following packages have been built: my_interfaces` | 의존 양식 패키지 미빌드 | `--packages-select` 떼고 전체 빌드 |
| 목록에서 줄 하나 지우고 빌드 | 엉뚱한 `fatal error` / `interface show`는 멀쩡 | build/·install/의 옛 산출물 | `rm -rf build install log` 후 클린 빌드 |
| 코드를 고쳤는데 그대로 | 동작 변화 없음 | install/ 미갱신 | 재빌드 → source (개발 중 `--symlink-install`) |

- 빌드 실패 시: `Failed <<< 패키지` 바로 위 몇 줄의 **첫 영어 문장**을 읽는다

## 6. 실행 파일 등록 (setup.py · entry_points · data_files)

| 망가뜨리기 | 증상 | 원인 | 해결 |
|---|---|---|---|
| entry_points 미등록 | `No executable found` | 등록 안 함 / 재빌드 안 함 | 등록 → 빌드 → source |
| 등록 줄 지우고 재빌드 | `StopIteration` + `Process exited with failure 1` | install/에 옛 실행 파일 남음 | 등록 복구 또는 build/·install/ 지우고 재빌드 |
| 항목 사이 콤마 누락 | `Failed <<<` + `CalledProcessError` | colcon은 원인 안 보여 줌 | 패키지 폴더에서 python으로 직접 → `'tuple' object is not callable ... missed a comma?` |
| 새 줄의 **앞 줄** 콤마 삭제 | 빌드 중단, `'tuple' object is not callable` | `(...)(...)`를 함수 호출로 해석 | 가리킨 줄 끝에 콤마 (마지막 줄 콤마는 무관) |
| entry_points를 `my_py_pkg.…`로 오기 | `ModuleNotFoundError` | 패키지.모듈 경로 불일치 | `hangman.game_node:main`처럼 실제 위치로 |
| 실행 이름 오타 | `No executable found` (따옴표 없음) | — | 실행 이름 확인 |
| 패키지 이름 오타 | `Package 'xxx' not found` (따옴표 있음) | — | 패키지 이름 확인 |

## 7. 인터페이스 (.msg / .srv / .action)

| 망가뜨리기 | 증상 | 원인 | 해결 |
|---|---|---|---|
| `find_package`를 `rosidl_generate_interfaces` 아래로 | `Unknown CMake command "rosidl_generate_interfaces"` | 생성기를 꺼내기 전에 호출 | `find_package`를 위로 |
| 폴더보다 파일 먼저 | `bash: msg/T.msg: No such file or directory` | 폴더 없음 | `mkdir -p` 먼저 |
| ament_python 패키지에 양식 | 빌드 통과, 타입 안 생김 | 코드 생성 단계 없음 | 전용 **ament_cmake** 패키지 |
| 생성 목록에 파일 안 적음 | 빌드 성공, `interface show` not found | 목록에 적힌 것만 생성 | 목록 추가 → 재빌드 |
| 목록 이름과 파일 이름 다름 | `the passed file 'srv/calc.srv' doesn't exist` | 대소문자까지 불일치 | 글자 단위로 맞춤 |
| `DEPENDENCIES`만 뺌 | 빌드 실패 | 끌어쓴 타입 못 찾음 | 추가 |
| `<depend>`만 뺌 | **빌드 성공** (더 위험) | 남의 PC에서 터짐 | 둘 다 적기 |
| `.action` 속을 비움 | `InvalidActionSpecification: Number of '---' separators` | 구분선 부족 | `---` 두 줄 (목표/결과/피드백) |
| `.srv`에 `--`(둘) | 인식 안 됨 | 구분선은 정확히 셋 | `---` |
| 타입 `float` | 인식 안 됨 | 비트 수 필요 | `float32`/`float64` |
| 칸 타입 변경(`float64→int32`) | 경고 없이 통과 | **깨뜨리는 변경** | 칸 추가는 안전, 타입 변경은 피함 |
| 정의 안 된 양식 import | 빌드 성공, 실행 시 `ImportError` | 파이썬은 빌드 때 import 검사 안 함 | 정의 → 목록 → 빌드 |
| 양식만 다시 빌드 | 노드에서 `AttributeError` | 쓰는 패키지 미재빌드 | 전체 재빌드 → 새 터미널 source |

| 큐 깊이 1 + 느린 처리           | 메시지 유실                             | 쌓을 공간 부족      | 큐 깊이 조정                                                |

## 9. 서비스

| 망가뜨리기 | 증상 | 원인 | 해결 |
|---|---|---|---|
| 서버 콜백 `return res` 삭제 | 서버 `TypeError`로 죽음, 클라이언트 무한 대기 | 응답 객체 미반환 | `return res` — **양쪽 터미널 확인** |
| 0 나누기 방어 제거 | 서버 `ZeroDivisionError`로 죽음, 클라이언트 무응답 | 예외 미처리 | 방어 복구 + `ok=False`로 실패 알림 |
| 서버 없이 클라이언트 | 「서버 대기 중...」 반복 | 서버 미실행 / 이름 불일치 | 서버 먼저, 이름 대조 |
| 콜백 이름을 `handle` | `'method' object does not support the context manager protocol` | Node 내부 이름과 충돌 | `on_request` 등 |
| 콜백 안에서 동기 호출 | 조용히 멈춤 | 데드락 | `call_async` |

## 10. 액션

| 망가뜨리기 | 증상 | 원인 | 해결 |
|---|---|---|---|
| 기본형 서버에 목표 2개 | 두 번째가 앞 것 끝날 때까지 밀림 | 일손 하나 | 완성형 (여러 일손) |
| 기본형에 Ctrl+C 취소 | 끝까지 계속 셈 | 취소 콜백 없음 + 일손 하나 | 취소 콜백 + MultiThreadedExecutor |
| `succeed()`~`return result` 삭제 | `Goal state not set, assuming aborted` + `Assertion failed` → `Aborted`, 클라이언트 영영 대기 | 도장·결과 누락 (None 반환) | `succeed()` + `return result` / 클라이언트는 `Ctrl+\` |
| `succeed()`만 빠짐 | 결과는 오는데 끝 상태 ABORTED | 종결 도장 누락 | `succeed()` |
| execute 안에서 토픽 기다림 | 판이 영영 안 끝남, Ctrl+C 안 먹음 | 일손 하나를 붙든 채 대기 | 목표에 다 담는 설계 |

## 11. 실행기와 콜백 그룹

| 망가뜨리기 | 증상 | 원인 | 해결 |
|---|---|---|---|
| 기본 `spin` + 느린 콜백 | 빠른 타이머 멈춤 | 창구 하나 | MultiThreadedExecutor + 콜백 그룹 |
| `USE_MULTI=False`로 액션 실행 | 액션 도는 동안 구독·서비스 끊김 | 창구 하나 | 다중 실행기 (액션 실행 함수는 그룹 밖 일감 → **창구 수**가 가름) |
| 단일 실행기로 순찰 | 10초간 상태·명령 멈춤, 오류 없음 | 같은 원인 | 같은 해결 |
| 그룹 없이 느린 서비스 콜백 | 다른 콜백 끊김 | 기본 그룹은 한 번에 하나 | 재진입 그룹 |
| `rclpy.shutdown()`으로 종료 | `rcl_shutdown already called` | 이중 종료 | `rclpy.try_shutdown()` |

- 여러 창구일 때 로그 순서가 뒤섞이는 것은 **정상**

|---|---|---|---|
| rqt_graph 그대로 | 빈 창 | 띄운 순간 스냅샷 | 새로고침, `Nodes/Topics (all)` |
| 거북이 창 클릭 후 방향키 | 안 움직임 | 포커스 | teleop 터미널 클릭 |
| remap 없이 조종기 2개 | 같은 거북이만 움직임 | 같은 토픽 | `-r /turtle1/cmd_vel:=/turtle2/cmd_vel` |
| remap에 `=` 하나 | `is neither a valid ...` | 문법 오류 | `:=` |
| namespace 언더스코어 하나 | namespace 안 먹음 | `__ns`는 두 개 | `__ns:=/robot1` |

## 17. 진단 사다리 (고장 다섯)

| 단 | 명령 | 정상 | 고장 신호 | 고장 예 |
|---|---|---|---|---|
| ⓪ | 서버 창 | 오류 없음 | 트레이스백 | 결과 미반환 |
| ① | `ros2 node list` | 노드 보임 | 노드 없음 (죽은 노드가 보이면 `--no-daemon`) | 노드 안 켬 |
| ② | `ros2 topic info /이름` | Type 하나, 양쪽 1 이상 | 양쪽에 0 하나씩 / Type이 둘 | 이름·타입 불일치 |
| ③ | `ros2 topic echo /이름` | 값이 찍힘 | 조용 | 발행 안 함 (로직) |
| ④ | `ros2 topic hz /이름` | 입력 박자를 따라감 | 입력보다 느림 | 무거운 콜백 |

- ①~② = **통신 문제**, ③~④ = **로직 문제** → 바깥에서 안으로

## 18. 공통 원칙

1. 화면의 **첫 영어 문장**을 그대로 오류 표에서 찾는다
2. **빌드 + source는 한 세트**, 새 터미널마다 source
3. 이상하면 `rm -rf build install log` **클린 빌드**
4. 통신 오류는 **양쪽 터미널**을 다 본다 (원인은 대개 서버 쪽)
5. **조용한 실패**를 의심 — 성공 메시지 대신 받는 쪽·`param get`·`hz`로 확인
6. 고장 낸 코드는 확인 후 **반드시 되돌린다**
