# 정의 
미들웨어의 종류중 하나
	데이터 중심 아키텍처: 분산 시스템 환경에서 중앙 서버 없이 노드 간 직접 통신(P2P)을 지원하여 단일 장애점(SPOF)을 제거함.
		  즉 데이터를 주는 주체가 아니라 필요한 데이터만  글로벌 데이터 공간에서 끌어 올림

**DDS (Data Distribution Service)**: 항공·국방·금융에서 오래 쓰여 온 **산업 표준 통신 미들웨어**. ROS2는 노드끼리 데이터를 주고받는 일을 직접 구현하지 않고 DDS 위에 얹혀 있다.

# ROS1과 비교
| ROS1 | ROS2 |
|---|---|
| 가운데 마스터(roscore)라는 중앙 교환원 | 중앙 교환원 없음 — DDS 기반 **분산 발견** |
| 교환원이 꺼지면 통신이 끊김 | 노드들이 같은 네트워크에서 서로를 직접 찾아 연결 |
| 마지막 배포판 Noetic (2020~2025) | 여러 로봇이 얽히는 현장에 잘 맞음 |

# DDS가 주는 것
- 중앙 마스터 없이 노드들이 서로를 **자동으로 찾아** 연결된다
- 토픽마다 통신 품질을 따로 정할 수 있다 → [[QoS(통신 품질)]] (신뢰성·지속성 등)
- 메시지를 공통 형식으로 직렬화해 전달하므로 C++ talker와 Python listener가 그대로 통신한다

# 도메인 ID
같은 물리 네트워크를 여러 **논리 네트워크**로 나누는 번호. 「몇 호실」이다.
- 같으면: 서로를 발견하고 통신한다
- 다르면: 같은 와이파이에 있어도 서로를 아예 못 본다 (발견조차 도메인 안에서만)
- 기본값 0, 보통 **0~101** 사이를 권장

```bash
export ROS_DOMAIN_ID=7             # 방 번호를 먼저 정하고
source /opt/ros/jazzy/setup.bash
ros2 run demo_nodes_cpp talker     # 그다음 띄운다 (이미 뜬 노드는 나중에 export 해도 안 바뀜)
```
- 교육장: 자리마다 다른 번호 → 옆자리 메시지가 섞이지 않는다
- 물류창고 AMR 다섯 대: 로봇마다 다른 번호 → 트래픽 격리, 협력할 땐 같은 번호로 묶는다
