# 정의
노드에 등록된 콜백(타이머·구독·서비스)을 **실제로 꺼내 불러 주는 엔진**. 단순히 기다리는 함수가 아니다.
노드 4요소(`rclpy.init` → `Node` 상속 → `create_*` → `rclpy.spin`) 중 앞의 셋이 준비라면 spin은 운전이다. 빠지면 노드는 한 번 깜빡이고 즉시 종료된다.

```python
rclpy.init()
node = MyNode()
rclpy.spin(node)      # Ctrl+C 까지 콜백을 돌린다
```

- `create_timer(1.0, self.cb)`는 **등록만** 한다. `self.cb()`를 직접 부르는 줄은 없다 — 언제 부를지는 spin이 정한다
- 「콜백이 안 불려요」의 첫 점검: 그 콜백을 만드는 줄이 정말 실행됐는가, spin이 있는가

# 특징 

한 번에 하나의 콜백만 꺼내 끝까지 실행한 뒤 다음 일감으로 넘어간다.
	 - 하나가 밀리면 나머지가 밀리는 병목 현상이 일어난다. 
	 - 서로의 실행을 가로채지 않으니, 입문 단계에서는 콜백 안에서 변수를 건드려도 충돌을 걱정하지 않아도 된다

## spin 뒤의 실행기
`rclpy.spin(node)` 한 줄은 세 동작을 대신하는 편의 함수다.
1. `SingleThreadedExecutor`를 만든다
2. 노드를 붙인다
3. 실행기를 돌린다 — 일감을 돌며 콜백을 부른다

실행기(Executor) = 어떤 콜백을 몇 개의 일손으로 처리할지 정하는 관리자.

## spin의 형제들
| 함수 | 어디까지 도나 |
|---|---|
| `rclpy.spin(node)` | 콜백을 끊임없이 꺼내 실행 |
| `rclpy.spin_once(node)` | 일감을 한 번만 처리하고 돌아옴 |
| `rclpy.spin_until_future_complete(node, future)` | 특정 작업(예: 서비스 응답)이 끝날 때까지만 |

# 주기 

수집 → 선택 → 실행 → 반복
	실행 부분에서 막힘
	기본값: 단일 쓰레드 
		콜백끼리 충돌 없고 예측 쉬움
	 막혔을 시 
		 해결방안:
		  ① `MultiThreadedExecutor` 
		  ② 콜백을 **서로 다른 그룹**에 두기
		  둘다 시행 해야함

```python
from rclpy.executors import MultiThreadedExecutor
from rclpy.callback_groups import MutuallyExclusiveCallbackGroup

slow_group = MutuallyExclusiveCallbackGroup()
self.create_timer(0.5, self.fast_cb)                              # 기본 그룹
self.create_timer(2.0, self.slow_cb, callback_group=slow_group)   # 새 그룹

ex = MultiThreadedExecutor()      # num_threads=4 처럼 창구 수 고정 가능
ex.add_node(node)                 # 여러 번 부르면 노드 여럿을 함께 관리
ex.spin()
```

## 콜백 그룹
| 구분 | 배타적 (MutuallyExclusive) | 재진입 (Reentrant) |
|---|---|---|
| 같은 그룹 안 | 한 번에 하나 | 여럿이 동시에 |
| 다른 그룹끼리 | 동시에 돌 수 있다 | 동시에 돌 수 있다 |
| 기본값 | 기본값 | 명시해야 씀 |
| 맞는 자리 | 같은 변수·파일·하드웨어를 건드리는 콜백 | 완전히 독립적인 작업 |
| 조심 | 서로를 동기 호출하면 데드락 | 공유 변수 동시 접근 시 경쟁 상태 |
