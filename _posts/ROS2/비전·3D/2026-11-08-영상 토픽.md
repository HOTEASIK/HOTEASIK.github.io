# 영상 토픽

## 정의·핵심
- **정의**: ROS에서 영상은 특별한 무엇이 아니라 **토픽 하나** — 카메라 노드가 프레임 한 장을 `sensor_msgs/msg/Image`에 담아 일정 주기로 `/camera/image_raw`에 발행하고, 쓰는 노드가 구독해 콜백에서 처리한다 (실습 6차시).
- **입문 구독자와 골격이 같다** — 달라진 점은 메시지 안이 글자가 아니라 픽셀 덩어리라는 것뿐. 라디오 방송처럼 발행자가 일방적으로 내보내고 관심 있는 구독자가 받아 간다.
- **한 장 = 숫자 격자**: 640 × 480 × 3(파랑·초록·빨강) = **921,600**개 숫자. 메시지 칸: `height`·`width`·`step`(한 줄의 바이트 수)·`encoding`(색 규칙)·`data`·`header`(stamp·frame_id).
- **양이 많고 끊임없이 흐른다**: 글자 한 줄은 수십 바이트, 영상 한 장은 거의 백만 — 초당 15·30장. 콜백 안 계산이 발행 간격보다 짧아야 밀리지 않는다 → 가벼운 고전 방식, 해상도 줄이기(`cv2.resize`)·몇 프레임에 한 번만 처리.
- **감지 → 판단 → 행동**: 카메라는 감지의 입구. 영상 처리 = 숫자 격자를 다른 숫자 격자로 바꾸는 계산(흑백·Canny·ROI·Hough 모두).
- **흐름 진단(창 없이)**: `ros2 topic list`(이름) · `ros2 topic hz /camera/image_raw`(`average rate: 14.995`) · `ros2 topic info`(`Type: sensor_msgs/msg/Image`, Publisher/Subscription count). 발행자가 없으면 `WARNING: topic [/camera/image_raw] does not appear to be published yet`.
- **설치**: `sudo apt install -y ros-jazzy-cv-bridge ros-jazzy-image-transport` — 실습 환경엔 이미 있었다(`0 newly installed`). image_transport는 영상 토픽을 효율적으로 주고받게 돕는다.

## 원리·구조
```
camera_publisher ──/camera/image_raw (Image, 15Hz)──┬─▶ viewer          (imshow)
                                                    └─▶ lane_detector ──/lane/overlay──▶ rqt_image_view
                                                                     └─/lane/offset──▶ lane_follower ─/cmd_vel
```

## 코드 예시
```python
# Image 메시지 칸 계산: 한 장의 크기와 초당 데이터량
h, w, ch = 480, 640, 3
step = w * ch                     # 한 줄의 바이트 수 (bgr8: 픽셀당 3바이트)
size = h * step
print(step, size)                 # 1920 921600
for hz in (15, 30):
    print(hz, "Hz →", round(size * hz / 1e6, 1), "MB/s")
# 15 Hz → 13.8 MB/s
# 30 Hz → 27.6 MB/s
print(round(1 / 15, 3), round(1 / 30, 3))   # 0.067 0.033  ← hz의 min/max 간격
```
```bash
ros2 topic hz /camera/image_raw
ros2 topic info /camera/image_raw --verbose
ros2 topic echo /camera/image_raw --field encoding --once
```
