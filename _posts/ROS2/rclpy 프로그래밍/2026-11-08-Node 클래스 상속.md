# Node 클래스 상속

## 정의·핵심
- **정의**: `class MyPublisher(Node):`라고 쓰는 순간 내 클래스는 rclpy `Node`가 갖춘 능력을 그대로 물려받는다. 부모에게는 공통 기능을 맡기고, 자식에는 **부모와 다른 점(노드가 맡을 일)** 만 적는다 (입문 3·4차시).
- **물려받는 것**: `create_publisher`·`create_subscription`·`create_timer`·`create_service`·`create_client`, `get_logger`, `get_clock`, `declare_parameter`/`get_parameter`, `get_name`, `destroy_node` …
- **`super().__init__('이름')`**: 부모 초기화와 함께 노드 이름을 붙인다 — `ros2 node list`에 뜨는 이름. 이것을 빼면 부모 기능이 준비되지 않아 `self.create_...`에서 터진다.
- **이름 충돌 함정**: Node가 이미 쓰는 이름으로 메서드를 지으면 부모 기능이 가려진다. 서비스 콜백을 `handle`로 지으면 노드를 만드는 줄에서 `TypeError: 'method' object does not support the context manager protocol`로 멈춘다 (Node 내부가 `self.handle`을 쓰기 때문). `tick`·`on_request`·`cb_scan`처럼 하는 일이 드러나게.
- **상속 없이도 된다**: `node = Node('x')` 후 `node.create_timer(...)` — 짧은 예제용. 상태(카운터 등)를 가진 노드는 클래스로 묶는 편이 읽기 쉽다.

## 원리·구조
```
 rclpy.node.Node (부모)  ── create_* · get_logger · get_clock · parameters · handle(내부)
        ▲
 MyPublisher (자식)      ── __init__: super().__init__('my_publisher') + 통로
                           tick(): 내 로직
```

## 코드 예시
```python
# 부모 이름을 자식이 덮으면 부모 기능이 가려진다 — 순수 파이썬으로 같은 현상
class Node:
    def __init__(self, name):
        self.name = name
        with self.handle:            # 부모 내부가 self.handle을 컨텍스트로 쓴다고 가정
            pass
    @property
    def handle(self):
        import contextlib; return contextlib.nullcontext()

class Good(Node):
    def on_request(self, req): return req

class Bad(Node):
    def handle(self, req): return req   # 부모의 handle을 덮어씀

Good("add_server"); print("Good OK")    # Good OK
try:
    Bad("add_server")
except TypeError as e:
    print("TypeError:", e)              # TypeError: 'method' object does not support the context manager protocol
```
