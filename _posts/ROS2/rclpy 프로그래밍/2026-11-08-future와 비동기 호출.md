# future와 비동기 호출

## 정의·핵심
- **future**: 「지금은 값이 없지만 곧 채워질 약속」을 담는 객체 — **택배 송장번호**. `call_async`를 부른 직후에는 답이 존재하지 않으니 돌려줄 수 없고, 대신 future를 곧바로 돌려받는다. 답이 오면 그 자리에 담기고 `future.result()`로 꺼낸다 (입문 3·5차시).
- **ROS만의 개념이 아니다**: 파이썬 `concurrent.futures`, `asyncio`, JS Promise — 거의 모든 언어의 비동기 기본기.
- **서비스는 원격 함수 호출(RPC)**: 요청이 프로세스 경계를 건너가 처리되고 돌아오니, 부르는 순간과 결과 도착 사이에 시간 간격이 생긴다 → 그 간격을 다루는 장치가 future.
- **동기 vs 비동기**

| | 동기 `call()` | 비동기 `call_async()` |
|---|---|---|
| 호출 직후 | 답이 올 때까지 그 자리에서 멈춤 | future를 받고 흐름 계속 |
| 콜백 안에서 | 데드락 위험(조용히 멈춤) | 안전 |
| 답 꺼내기 | 호출문이 곧 결과 | `future.result()` |
| rclpy 권장 | 비권장 | 권장 |

- **기다리는 두 방법**: main에서 `spin_until_future_complete(node, fut)` / 어디서든 `fut.add_done_callback(함수)` — 채워지면 함수를 불러 달라(액션 클라이언트가 줄줄이 쓰는 방식).
- `fut.done()`으로 채워졌는지 확인, `fut.result()`가 None이면 실패 — `fut.exception()` 확인.

## 원리·구조
```
call_async ──→ fut(비어 있음) ─┬─ spin_until_future_complete → result()
                              └─ add_done_callback(on_done) → spin이 채워지면 on_done(fut)
```

## 코드 예시
```python
# 표준 라이브러리 future로 같은 흐름: 즉시 송장을 받고, 채워지면 콜백
from concurrent.futures import ThreadPoolExecutor
import time
def add_server(a, b):                 # 다른 곳에서 도는 "서버"
    time.sleep(0.2); return a + b
with ThreadPoolExecutor() as pool:
    fut = pool.submit(add_server, 3, 4)          # call_async
    print("즉시 돌아옴, done =", fut.done())      # 즉시 돌아옴, done = False
    fut.add_done_callback(lambda f: print("콜백: sum =", f.result()))
    print("기다려 꺼냄:", fut.result(timeout=2))   # spin_until_future_complete 에 해당
# 콜백: sum = 7 / 기다려 꺼냄: 7  (두 줄의 순서는 스레드 타이밍에 따라 바뀔 수 있다)
```
