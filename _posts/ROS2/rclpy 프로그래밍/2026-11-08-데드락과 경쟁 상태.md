# 데드락과 경쟁 상태

## 정의·핵심
- **경쟁 상태(race condition)**: 두 창구가 같은 변수를 동시에 건드릴 때 생긴다. `self.count += 1` 한 줄은 사실 **읽기 → 1 더하기 → 쓰기** 세 동작 — 둘이 거의 동시에 옛 값을 읽으면 둘 다 같은 새 값을 써서 하나가 사라진다 (입문 4차시 심화).
  - 생기는 조건: 멀티스레드 실행기 + 재진입 그룹(또는 서로 다른 그룹)이 같은 변수를 건드릴 때.
  - 처방: 같은 자원을 건드리는 콜백을 **같은 배타적 그룹**에 / `threading.Lock` / 공유 상태를 줄인다.
- **데드락(deadlock)**: 서로가 상대의 완료를 영영 기다릴 때. 에러도 경고도 없이 **조용히 멈춘다**.
  - 전형: 콜백 안에서 다른 서비스를 **동기로** 부르고 창구를 붙잡은 채 기다린다 → 그 응답을 처리하려면 같은 창구가 비어야 하는데 비지 않는다.
  - 처방: `call_async` + 기다림은 main에서(또는 `add_done_callback`) / 서로를 호출하는 콜백을 같은 배타적 그룹에 묶지 않는다 / 클라이언트를 다른 그룹 + 멀티스레드.
- 둘 다 막연한 경고가 아니라 원인이 분명한 현상 — 원리를 알면 피하는 법도 보인다.

## 원리·구조
```
경쟁:   창구A read 5 ──────── +1 → write 6
        창구B   read 5 ── +1 → write 6         결과 6 (기대 7)
데드락: 콜백X(창구 점유) ─동기 call→ 서버 응답 ─처리하려면 창구 필요─→ (창구는 X가 점유) ∞
```

## 코드 예시
```python
# 실제 스레드로 경쟁 상태 재현 + Lock으로 해결, 그리고 lock 대기 타임아웃으로 데드락 감지
import threading, time
count = 0
def unsafe(n):
    global count
    for _ in range(n):
        v = count          # 읽기
        time.sleep(0)      # 창구가 바뀔 틈
        count = v + 1      # 쓰기
ts = [threading.Thread(target=unsafe, args=(2000,)) for _ in range(4)]
[t.start() for t in ts]; [t.join() for t in ts]
print("lock 없음:", count, "(기대 8000)", count < 8000)   # lock 없음: (8000보다 작은 값) (기대 8000) True

count, lock = 0, threading.Lock()
def safe(n):
    global count
    for _ in range(n):
        with lock: count += 1
ts = [threading.Thread(target=safe, args=(2000,)) for _ in range(4)]
[t.start() for t in ts]; [t.join() for t in ts]
print("lock 있음:", count)                               # lock 있음: 8000

a, b = threading.Lock(), threading.Lock()
a.acquire()                      # 콜백X가 창구 a를 쥔 채
def server():                    # 응답을 처리하려면 a가 필요
    return a.acquire(timeout=0.5)
r = []; t = threading.Thread(target=lambda: r.append(server())); t.start(); t.join()
print("응답 처리 가능?", r[0])    # 응답 처리 가능? False  ← 서로 기다림(데드락)
```
