# 액션 취소와 선점

## 정의·핵심
- **취소(cancel)**: 진행 중인 목표를 도중에 멈추게 하는 요청. 액션이 서비스와 갈리는 가장 큰 능력 — 5초 걸리는 로봇팔 이동 중 사람이 작업 공간에 들어오면 멈춰야 한다 (입문 5차시).
- **선점(preemption)**: 새 목표가 오면 진행 중인 목표를 멈추고 **갈아탄다**. 내비게이션에서 목적지를 바꾸면 이전 목표를 취소하고 새 목표로 — 서버의 `goal_callback`이 정책을 정하는 자리.
- **취소는 다섯 손길의 협력**: ① 클라이언트 `cancel_goal_async()` ② 서버 `cancel_callback`이 ACCEPT ③ 실행 함수가 **매 단계** `is_cancel_requested` 확인 ④ `goal_handle.canceled()` 도장 ⑤ 취소 콜백이 실행 중에 들어올 **빈 일손**(Reentrant 그룹 + MultiThreadedExecutor). 하나라도 빠지면 취소가 수락되고도 동작에 반영되지 않는다.
- **현장 시나리오**: 로봇팔이 취소를 무시한다 → is_cancel_requested를 안 살피거나 일손이 하나. / 두 사용자가 거의 동시에 서로 다른 목적지를 보내 갈팡질팡 → 새 목표가 오면 기존 목표를 abort하고 새것만 수행하도록 정책을 둔다.
- **상태 번호**: `Goal finished with status: CANCELED` — 내부적으로는 숫자(4=SUCCEEDED, 5=CANCELED, 6=ABORTED)로 오고, 상태로 다음 행동을 가른다.
- **CLI 취소**: `send_goal` 중 Ctrl+C → `Canceling goal...` — 취소는 두 터미널(서버·클라이언트)에 나뉘어 찍힌다.

## 원리·구조
| 상태 | 번호 | 뜻 |
|---|---|---|
| ACCEPTED / EXECUTING | 1 / 2 | 받음 / 실행 중 |
| CANCELING | 3 | 취소 요청 수락, 정리 중 |
| SUCCEEDED | 4 | 완료 |
| CANCELED | 5 | 취소로 끝 |
| ABORTED | 6 | 서버가 포기 |

## 코드 예시
```python
# 선점 정책 흉내: 새 목표가 오면 기존 목표를 ABORTED로 끝내고 갈아탄다
class NavServer:
    def __init__(self): self.active, self.log = None, []
    def goal_callback(self, goal):
        if self.active:
            self.log.append(f"{self.active} → ABORTED(선점)")
        self.active = goal
        return "ACCEPT"
    def cancel(self):
        self.log.append(f"{self.active} → CANCELED"); self.active = None
s = NavServer()
s.goal_callback("주방"); s.goal_callback("현관"); s.cancel()
print(s.log)    # ['주방 → ABORTED(선점)', '현관 → CANCELED']
STATUS = {4: "SUCCEEDED", 5: "CANCELED", 6: "ABORTED"}
print(STATUS[5])  # CANCELED
```
```python
# 클라이언트 쪽 취소 요청 (rclpy)
from rclpy.node import Node
def request_cancel(node: Node, goal_handle):
    fut = goal_handle.cancel_goal_async()
    fut.add_done_callback(lambda f: node.get_logger().info(
        f'취소 응답 목표 수: {len(f.result().goals_canceling)}'))
```
