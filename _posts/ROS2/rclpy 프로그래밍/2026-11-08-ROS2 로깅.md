# ROS2 로깅

## 정의·핵심
- **정의**: `self.get_logger().info(...)`처럼 노드의 로거로 남기는 기록. print 대신 쓴다 (입문 4차시).
- **print가 아닌 까닭**: 여러 노드를 한 번에 띄우면 누가 무슨 말을 했는지 모른다. 로그는 **등급·시각·노드 이름**이 자동으로 붙고, 등급 문턱으로 「평소엔 INFO 위만, 문제를 쫓을 때만 DEBUG까지」 거를 수 있다. print는 전부 나오거나 전부 지우거나 둘뿐.
- **꼴**: `[등급] [시각] [노드 이름]: 메시지` — 예 `[WARN] [1789962448.57] [my_publisher]: 값이 좀 낮다`. launch로 띄우면 앞에 `[my_publisher-1]` 프로세스 꼬리표, namespace가 있으면 노드 이름이 점으로(`r1.my_publisher`).
- **기본 문턱은 INFO**: debug 줄이 안 보이는 건 코드가 틀린 게 아니다 → `--ros-args --log-level my_publisher:=debug`로 그 노드만 낮춘다. 노드를 짚지 않고 `--log-level debug`만 주면 rcl·rmw 내부 로그까지 열려 화면이 폭주.
- **`warn()`과 `warning()`** 은 같은 줄을 찍는다.
- **/rosout**: 모든 노드 로그가 이 토픽으로도 모인다 → `rqt_console`로 걸러 본다.
- **한 번만·가끔만**: `info(..., once=True)`, `throttle_duration_sec=1.0` — 고주파 콜백에서 화면 폭주 방지.

## 원리·구조
| 등급 | 메서드 | 쓰는 때 |
|---|---|---|
| DEBUG | `debug()` | 개발 중에만 보는 속사정 |
| INFO | `info()` | 정상 동작 알림 |
| WARN | `warning()` | 멈추진 않지만 이상한 값·상태 |
| ERROR | `error()` | 이번 일감 실패 |
| FATAL | `fatal()` | 노드가 더 갈 수 없음 |

## 코드 예시
```python
# 같은 생각을 파이썬 logging으로: 등급 문턱 + 이름표
import logging, sys
fmt = logging.Formatter("[%(levelname)s] [%(name)s]: %(message)s")
h = logging.StreamHandler(sys.stdout); h.setFormatter(fmt)
log = logging.getLogger("my_publisher"); log.addHandler(h); log.propagate = False
log.setLevel(logging.INFO)                 # 기본 문턱 INFO
for lv, m in [("info", "정상 동작 중"), ("warning", "값이 좀 낮다"),
              ("error", "연결이 끊겼다"), ("debug", "기본 설정에서 안 보인다")]:
    getattr(log, lv)(m)
# [INFO] [my_publisher]: 정상 동작 중 / [WARNING] [my_publisher]: 값이 좀 낮다 / [ERROR] [my_publisher]: 연결이 끊겼다
log.setLevel(logging.DEBUG)                # --log-level my_publisher:=debug 에 해당
log.debug("이제 보인다")                    # [DEBUG] [my_publisher]: 이제 보인다
```
```bash
ros2 run my_py_pkg my_publisher --ros-args --log-level my_publisher:=debug
ros2 topic echo /rosout
```

## 수업 메모

### 정의
노드가 남기는 기록. `print` 대신 `self.get_logger()`로 찍으면 **시각·노드 이름·등급**이 자동으로 붙어, 여러 노드가 한 화면에 섞여도 누가 한 말인지 가려진다.

| | print | 로깅 |
|---|---|---|
| 누가 한 말인지 | 알 수 없다 | 노드 이름이 붙는다 |
| 걸러 보기 | 전부 나오거나 전부 지우거나 | 등급 문턱으로 조절 |

### 등급
DEBUG < INFO < WARN < ERROR < FATAL
	기본으로는 INFO 이상만 화면에 출력

| 등급 | 메서드 | 언제 쓰나 |
|---|---|---|
| DEBUG | `get_logger().debug(...)` | 개발 중에만 보고 싶은 속사정 |
| INFO | `get_logger().info(...)` | 정상 동작을 알리는 평상시 기록 |
| WARN | `get_logger().warning(...)` | 당장 멈추진 않지만 이상한 값·상태 |
| ERROR | `get_logger().error(...)` | 이번 일감이 실패 |
| FATAL | `get_logger().fatal(...)` | 노드가 더 갈 수 없음 |

`warn()`도 동작하며 결과는 `warning()`과 같다.

### 코드
```python
log = self.get_logger()
log.info('정상 동작 중')
log.warning('값이 좀 낮다')
log.error('연결이 끊겼다')
log.debug('기본 설정에서는 안 보인다')
```

출력 형식: `[등급] [시각] [노드 이름]: 메시지`
```
[INFO] [1789962448.576490621] [my_publisher]: 정상 동작 중
[WARN] [1789962448.576854550] [my_publisher]: 값이 좀 낮다
[ERROR] [1789962448.577225672] [my_publisher]: 연결이 끊겼다
```

특정 노드만 debug로 켜기: `--ros-args --log-level 노드:=debug`
```bash
ros2 run my_py_pkg my_publisher --ros-args --log-level my_publisher:=debug
```
- 노드 이름 없이 `--log-level debug`를 주면 `rcl`·`rmw_fastrtps_cpp` 같은 ROS 내부 로그까지 열려 화면이 폭주한다

### 현장에서
센서·인식·제어 노드의 로그가 한 터미널에 섞여 흐를 때, 평소에는 INFO만 흘리고 이상 신호만 WARN·ERROR로 남기면 운영자는 등급 표식만 보고 볼 노드를 좁힌다.
