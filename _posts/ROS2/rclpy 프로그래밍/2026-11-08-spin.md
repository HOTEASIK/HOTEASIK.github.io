# spin

## 정의·핵심
- **정의**: `rclpy.spin(node)` — 노드를 살려 두고 **콜백을 실제로 불러 주는 엔진**. 단순히 기다리는 함수가 아니다. 4요소 중 셋(init·Node·create_*)이 준비라면 spin은 운전 — 심장이 뛰어야 피가 돌듯 (입문 3·4차시).
- **한 바퀴**: 수집(타이머가 울렸나, 메시지가 왔나) → 선택(일감 하나) → 실행(콜백 끝까지) → 다시 수집. Ctrl+C까지 반복.
- **콜백을 직접 부르는 코드가 없던 이유**: spin이 대신 부른다.
- **뒤에 실행기가 숨어 있다**: `rclpy.spin(node)` = 기본 실행기(SingleThreadedExecutor)를 만들고 → `add_node` → `spin()` 세 줄의 줄임.
- **형제들**
  - `rclpy.spin_once(node, timeout_sec=0.1)`: 일감 하나만 처리하고 돌아온다 — 내 while 루프 안에서 섞어 쓸 때.
  - `rclpy.spin_until_future_complete(node, future)`: future가 채워질 때까지만 — 서비스 클라이언트 main에서. **콜백 안에서는 쓰지 않는다**(데드락).
- **spin을 빼먹으면**: main이 그대로 반환 → 노드가 즉시 종료, 타이머는 한 번도 안 울림.
- **spin 뒤 코드는 Ctrl+C 이후에야** 실행된다 — spin 아래에 로직을 두지 않는다.

## 원리·구조
| 함수 | 언제 돌아오나 | 쓰는 자리 |
|---|---|---|
| `spin(node)` | 종료(Ctrl+C)될 때 | 일반 노드의 main |
| `spin_once(node, timeout_sec)` | 일감 하나 처리 또는 타임아웃 | 직접 만든 루프 |
| `spin_until_future_complete(node, fut)` | future 완료 시 | 서비스·액션 클라이언트 main |
| `executor.spin()` | 종료될 때 | 멀티스레드·노드 여럿 |

## 코드 예시
```python
import rclpy
from rclpy.node import Node
from rclpy.executors import SingleThreadedExecutor

def main():
    rclpy.init()
    node = Node('spin_demo')
    node.create_timer(0.5, lambda: node.get_logger().info('tick'))

    # rclpy.spin(node) 한 줄이 감춘 세 줄
    ex = SingleThreadedExecutor()
    ex.add_node(node)
    try:
        ex.spin()
    except KeyboardInterrupt:
        pass
    finally:
        node.destroy_node()
        rclpy.try_shutdown()

def loop_style():
    rclpy.init()
    node = Node('loop_demo')
    for _ in range(10):                       # 내 루프 + spin_once
        rclpy.spin_once(node, timeout_sec=0.1)
    node.destroy_node(); rclpy.try_shutdown()
```

## 수업 메모

### 정의
노드에 등록된 콜백(타이머·구독·서비스)을 **실제로 꺼내 불러 주는 엔진**. 단순히 기다리는 함수가 아니다.
노드 4요소(`rclpy.init` → `Node` 상속 → `create_*` → `rclpy.spin`) 중 앞의 셋이 준비라면 spin은 운전이다. 빠지면 노드는 한 번 깜빡이고 즉시 종료된다.

```python
rclpy.init()
node = MyNode()
rclpy.spin(node)      # Ctrl+C 까지 콜백을 돌린다
```

- `create_timer(1.0, self.cb)`는 **등록만** 한다. `self.cb()`를 직접 부르는 줄은 없다 — 언제 부를지는 spin이 정한다
- 「콜백이 안 불려요」의 첫 점검: 그 콜백을 만드는 줄이 정말 실행됐는가, spin이 있는가

### 특징 

한 번에 하나의 콜백만 꺼내 끝까지 실행한 뒤 다음 일감으로 넘어간다.
	 - 하나가 밀리면 나머지가 밀리는 병목 현상이 일어난다. 
	 - 서로의 실행을 가로채지 않으니, 입문 단계에서는 콜백 안에서 변수를 건드려도 충돌을 걱정하지 않아도 된다

#### spin 뒤의 실행기
`rclpy.spin(node)` 한 줄은 세 동작을 대신하는 편의 함수다.
1. `SingleThreadedExecutor`를 만든다
2. 노드를 붙인다
3. 실행기를 돌린다 — 일감을 돌며 콜백을 부른다

실행기(Executor) = 어떤 콜백을 몇 개의 일손으로 처리할지 정하는 관리자.

#### spin의 형제들
| 함수 | 어디까지 도나 |
|---|---|
| `rclpy.spin(node)` | 콜백을 끊임없이 꺼내 실행 |
| `rclpy.spin_once(node)` | 일감을 한 번만 처리하고 돌아옴 |
| `rclpy.spin_until_future_complete(node, future)` | 특정 작업(예: 서비스 응답)이 끝날 때까지만 |

### 주기 

수집 → 선택 → 실행 → 반복
	실행 부분에서 막힘
	기본값: 단일 쓰레드 
		콜백끼리 충돌 없고 예측 쉬움
	 막혔을 시 
		 해결방안:
		  ① `MultiThreadedExecutor` 
		  ② 콜백을 **서로 다른 그룹**에 두기
		  둘다 시행 해야함

```python
from rclpy.executors import MultiThreadedExecutor
from rclpy.callback_groups import MutuallyExclusiveCallbackGroup

slow_group = MutuallyExclusiveCallbackGroup()
self.create_timer(0.5, self.fast_cb)                              # 기본 그룹
self.create_timer(2.0, self.slow_cb, callback_group=slow_group)   # 새 그룹

ex = MultiThreadedExecutor()      # num_threads=4 처럼 창구 수 고정 가능
ex.add_node(node)                 # 여러 번 부르면 노드 여럿을 함께 관리
ex.spin()
```

#### 콜백 그룹
| 구분 | 배타적 (MutuallyExclusive) | 재진입 (Reentrant) |
|---|---|---|
| 같은 그룹 안 | 한 번에 하나 | 여럿이 동시에 |
| 다른 그룹끼리 | 동시에 돌 수 있다 | 동시에 돌 수 있다 |
| 기본값 | 기본값 | 명시해야 씀 |
| 맞는 자리 | 같은 변수·파일·하드웨어를 건드리는 콜백 | 완전히 독립적인 작업 |
| 조심 | 서로를 동기 호출하면 데드락 | 공유 변수 동시 접근 시 경쟁 상태 |
