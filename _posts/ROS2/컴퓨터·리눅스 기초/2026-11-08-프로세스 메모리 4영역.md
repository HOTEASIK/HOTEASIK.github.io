# 프로세스 메모리 4영역

## 정의·핵심
- **정의**: 운영체제가 프로세스에 준 메모리(책상)를 용도에 따라 나눈 네 칸 — 코드·데이터·힙·스택 (기초 1차시).
  - **코드(Code)**: 실행할 명령어. 읽기 전용.
  - **데이터(Data)**: 전역변수·정적변수가 산다.
  - **힙(Heap)**: 실행 중 직접 만들고 지우는 영역. 해제를 잊으면 **메모리 누수**.
  - **스택(Stack)**: 함수 호출마다 쌓인다(지역변수·매개변수). 끝없이 쌓이면 **스택 오버플로**.
- **로봇 노드에서 가장 무서운 것**: 장시간 켜두는 노드의 **힙 메모리 누수**. 한 번에 1KB씩만 새도 며칠 켜두면 RAM이 바닥나 노드가 죽는다.
  - 현업에서는 노드를 며칠 돌려보며 메모리 사용량이 계속 **우상향**하는지 지켜본다.
- 스레드는 이 중 **스택만 따로** 갖고 코드·데이터·힙은 공유한다 → 경쟁 상태의 원인.

## 원리·구조
```
높은 주소
┌──────────────┐
│ 스택 Stack    │  함수 호출마다 ↓ 쌓임 (지역변수·매개변수)
│      ↓       │
│      ↑       │
│ 힙 Heap       │  실행 중 생성·해제 ↑ (누수 주의)
├──────────────┤
│ 데이터 Data    │  전역·정적 변수
├──────────────┤
│ 코드 Code     │  명령어 (읽기 전용)
└──────────────┘
낮은 주소
```

## 코드 예시
```python
# 스택 오버플로 흉내: 끝없는 재귀 호출 → 파이썬은 RecursionError로 막는다
import sys
def dive(n):
    return dive(n + 1)
try:
    dive(0)
except RecursionError:
    print("스택이 넘쳤다 (한도:", sys.getrecursionlimit(), ")")
# 스택이 넘쳤다 (한도: 1000 )

# 메모리 누수 흉내: 콜백마다 리스트에 쌓기만 하고 비우지 않음
leak = []
for _ in range(1000):              # 콜백 1000번
    leak.append(bytearray(1024))   # 1KB씩 쌓임
print(len(leak) * 1024, "bytes")   # 1024000 bytes  ← 계속 우상향
```
