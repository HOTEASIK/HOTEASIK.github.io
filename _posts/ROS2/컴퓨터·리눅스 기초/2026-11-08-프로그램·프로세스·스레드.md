# 프로그램·프로세스·스레드

## 정의·핵심
- **프로그램(program)**: 명령어를 순서대로 적어 저장해 둔 **정적인 파일**. 평소엔 서랍(저장장치)에서 자는 설계도.
- **프로세스(process)**: 그 프로그램이 메모리에 올라가 **실행되고 있는 동적인 상태**. 책상(메모리) 위로 올라가 CPU가 돌리기 시작한 것.
- **스레드(thread)**: 한 프로세스 안에서 일을 여러 갈래로 나눠 맡는 **실행 흐름**. "일꾼 안의 손 여러 개".
- **ROS와의 연결** (기초 1차시): ROS에서 하루 종일 하는 일이 노드를 켜고 끄는 일이다 — **노드가 곧 프로세스**다. 노드를 실행하면 깨어나고, Ctrl+C로 끄면 재운다.
- 크롬 창을 두 개 띄우면 프로그램은 하나, 프로세스는 둘.
- 스레드를 늘리는 게 프로세스를 새로 띄우는 것보다 자원도 덜 쓰고 전환도 빠르다. 대신 메모리를 공유하므로 둘이 같은 값을 동시에 건드리면 꼬이는 **동기화 문제**가 생긴다.
- 프로세스는 서로 메모리를 못 보므로 데이터 교환에 **통신(IPC·소켓)** 이 필요하고, 스레드는 변수를 그냥 공유한다 (기초 2차시).

## 원리·구조
| 구분 | 정의 | 상태 | 비유 | 메모리 |
|---|---|---|---|---|
| 프로그램 | 명령어를 적어 저장한 파일 | 정적 | 잠자는 설계도 | 저장장치에 보관 |
| 프로세스 | 메모리에 올라가 실행 중인 상태 | 동적 | 깨어난 일꾼 | 독립된 4영역 할당 |
| 스레드 | 프로세스 안의 실행 흐름 | 동적 | 일꾼 안의 손 여러 개 | 스택만 따로, 나머지 공유 |

## 코드 예시
```python
# 한 프로세스(PID 하나) 안에 스레드 여러 개가 돈다
import os, threading
MAIN_PID = os.getpid()
names = []
def work():
    names.append((os.getpid() == MAIN_PID, threading.current_thread().name))

ts = [threading.Thread(target=work, name=f"손{i}") for i in range(3)]
for t in ts: t.start()
for t in ts: t.join()
print(sorted(names))
# [(True, '손0'), (True, '손1'), (True, '손2')]  ← PID는 모두 같고 스레드 이름만 다르다
```
```bash
ps aux | grep python    # 실행 중인 프로세스와 PID 보기
```
