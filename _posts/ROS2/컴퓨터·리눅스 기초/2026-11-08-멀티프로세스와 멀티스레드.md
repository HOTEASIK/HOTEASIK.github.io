# 멀티프로세스와 멀티스레드

## 정의·핵심
- **멀티프로세스**: 여러 프로세스를 띄워 일을 나눈다. 메모리가 각자 독립(격리)되어 안전하지만, 데이터 교환에 통신이 필요하다.
- **멀티스레드**: 한 프로세스 안에 스레드를 여러 개 둔다. 코드·데이터·힙을 공유하고 스택만 분리 → 가볍고 빠르지만 동기화 문제가 생긴다.
- **동시에 도는 것처럼 보이는 비밀 — 스케줄링** (기초 1차시): CPU 코어는 몇 개뿐인데 수십 개 프로세스가 동시에 도는 것처럼 보이는 건, 스케줄러(교통경찰)가 코어를 아주 짧은 시간씩 번갈아 나눠주기 때문. 1초에 수백 번 전환 — 필름이 정지 사진의 연속인 것과 같다.
  - **배정**: 짧은 시간씩 코어를 준다.
  - **전환(컨텍스트 스위칭)**: 갈아끼울 때마다 상태를 저장·복원한다.
  - **선점**: 급한 일은 우선순위로 먼저 끼워 넣는다.
- **경쟁 상태(race condition)**: 두 스레드가 같은 변수를 읽고 → 사이에 컨텍스트 스위칭이 끼어들고 → 같은 옛 값에 각자 덮어써서 → 두 번 더했는데 1만 늘어난다. 어쩌다 한 번만 틀려 **재현조차 어렵다**는 게 무섭다. 막으려면 **락(lock)** 으로 잠근다.
- **ROS는 둘 다 쓴다**: 노드를 프로세스로 따로 띄우기도(`ros2 run`), 스레드로 묶기도 한다(MultiThreadedExecutor, Component).

## 원리·구조
| 항목 | 멀티프로세스 | 멀티스레드 |
|---|---|---|
| 메모리 | 각자 독립(격리) | 코드·데이터·힙 공유, 스택만 분리 |
| 데이터 교환 | 통신(IPC·소켓) 필요 | 변수 공유 |
| 위험 | 격리되어 안전 | 동시 수정 시 충돌 → 락 |
| 생성·전환 비용 | 큼 | 작음 |

## 코드 예시
```python
# 경쟁 상태 재현과 락으로 해결
import threading, time
count = 0
def add_unsafe():
    global count
    for _ in range(100):
        v = count          # ① 읽기
        time.sleep(0)      # ② 사이에 전환이 끼어들 틈
        count = v + 1      # ③ 옛 값에 덮어쓰기

ts = [threading.Thread(target=add_unsafe) for _ in range(4)]
[t.start() for t in ts]; [t.join() for t in ts]
print("락 없음 → 400보다 작음:", count < 400)   # 대부분 True

count = 0
lock = threading.Lock()
def add_safe():
    global count
    for _ in range(100):
        with lock:         # 읽기~쓰기를 한 덩어리로 잠근다
            v = count; time.sleep(0); count = v + 1

ts = [threading.Thread(target=add_safe) for _ in range(4)]
[t.start() for t in ts]; [t.join() for t in ts]
print("락 있음:", count)                        # 락 있음: 400
```
