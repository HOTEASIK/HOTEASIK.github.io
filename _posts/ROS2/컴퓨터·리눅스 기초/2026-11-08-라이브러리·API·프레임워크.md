# 라이브러리·API·프레임워크

## 정의·핵심
- **라이브러리**: 남이 미리 만들어 둔 **기능 상자**. 예 파이썬 `socket`, `numpy`. 라이브러리가 없다면 운영체제 밑바닥까지 직접 건드려야 한다 — `import socket` 한 줄로 그 절차가 통째로 끝난다 (기초 2차시).
- **API**: 그 상자를 부르는 **약속된 손잡이**(사용법). 상자 속은 몰라도 손잡이만 알면 쓴다 — 엔진을 몰라도 핸들과 페달(자동차의 API)로 운전한다.
- **프레임워크**: 부엌이 통째로 차려져 있어 내 코드만 얹으면 되는 **틀**. 정해진 자리에 코드를 끼우면 틀이 알아서 그 코드를 부른다 → **주도권이 뒤집힌다**(제어의 역전).
- **ROS는 프레임워크다**: 콜백 함수를 등록해 두면 메시지가 올 때마다 ROS가 그 함수를 대신 실행한다 — 틀이 나를 부르는 실제 모습. 동시에 `rclpy` 함수는 내가 부르는 라이브러리이기도 하다. ROS2는 셋의 성격을 다 가진다 (기초 1차시 부록).
- **선택의 기준**: 라이브러리는 자유도가 높은 대신 다 직접 짜야 하고, 프레임워크는 자유도가 낮은 대신 구조가 정해져 편하다.
- 소켓(라이브러리)으로 짠 통신은 손이 많이 갔고, ROS(프레임워크)는 그 일을 대신 맡는다 (기초 2차시 마무리).

## 원리·구조
| 구분 | 무엇인가 | 주도권 | 비유 | 예 |
|---|---|---|---|---|
| 라이브러리 | 기능 상자 | 내 코드가 부른다 | 식재료 상자 | socket, numpy |
| API | 부르는 약속 | 사양만 정의(구현 감춤) | 메뉴판·손잡이 | 핸들과 페달 |
| 프레임워크 | 코드를 끼우면 불러주는 구조 | 틀이 나를 부른다 | 부엌 전체 | ROS, Django |

## 코드 예시
```python
# 라이브러리: 내가 부른다 / 프레임워크: 등록해 두면 틀이 부른다
import math
print(math.sqrt(16))                   # 4.0  ← 라이브러리 호출

class MiniFramework:                   # ROS의 subscription + spin 을 흉내 낸 틀
    def __init__(self): self.callbacks = {}
    def subscribe(self, topic, cb): self.callbacks.setdefault(topic, []).append(cb)
    def spin(self, messages):
        for topic, msg in messages:   # 메시지가 오면 틀이 내 함수를 부른다
            for cb in self.callbacks.get(topic, []): cb(msg)

def my_callback(msg):                  # 내가 채우는 빈칸
    print("받음:", msg)

fw = MiniFramework()
fw.subscribe("/chatter", my_callback)
fw.spin([("/chatter", "Hello World: 0"), ("/other", "x"), ("/chatter", "Hello World: 1")])
# 받음: Hello World: 0
# 받음: Hello World: 1
```
