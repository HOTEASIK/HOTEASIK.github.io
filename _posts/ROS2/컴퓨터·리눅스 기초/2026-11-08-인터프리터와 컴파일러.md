# 인터프리터와 컴파일러

## 정의·핵심
- **배경**: 컴퓨터는 0과 1로 된 기계어밖에 모른다 — 사람이 쓴 코드를 번역해야 실행된다. 번역 방식이 둘로 갈린다 (기초 2차시).
- **인터프리터(파이썬)**: 한 줄씩 그때그때 번역해 실행한다 — 동시통역사. 바로 돌려볼 수 있어 편하다.
- **컴파일러(C, C++)**: 코드 전체를 미리 한꺼번에 번역해 둔다 — 책 번역 출판. 빌드 시간이 들지만 실행이 아주 빠르다.
- **우열이 아니라 도구의 차이**: 자주 고쳐 가며 시험할 땐 통역사가, 완성해 빠르게 굴릴 땐 번역본이 유리하다.
- **한 로봇 안에 두 언어가 같이 산다**
  - 파이썬: 사람과 대화하거나 AI를 붙이는 높은 단계를 빠르게 만든다, 새 기능 시험이 빠르다.
  - C++: 모터를 1초에 수백 번 돌리는 정밀 제어. 파이썬으로 하면 번역 부담 때문에 박자를 놓칠 수 있다.
  - 언어를 하나로 통일하지 않아도 ROS가 그 사이를 이어 준다 (C++ talker + Python listener, 기초 3차시). 소켓에선 언어 맞추기도 고역.
- **ROS2에서**: rclpy(파이썬)·rclcpp(C++) 클라이언트 라이브러리. 파이썬 패키지는 ament_python, C++은 ament_cmake로 빌드한다. 파이썬도 `colcon build`를 거치지만 이는 기계어 번역이 아니라 **설치(등록)** 단계다.

## 원리·구조
| 구분 | 인터프리터 | 컴파일러 |
|---|---|---|
| 번역 방식 | 한 줄씩 실행할 때마다 | 전체를 미리 한 번에 |
| 비유 | 동시통역사 | 책 번역 출판 |
| 첫 실행 | 빠름 (바로 돌려봄) | 느림 (빌드 시간) |
| 실행 속도 | 상대적으로 느림 | 빠름 |
| 대표 언어 | 파이썬 | C++ |

## 코드 예시
```python
# 파이썬도 내부적으로는 '바이트코드'로 번역한 뒤 한 줄씩 해석·실행한다
import dis, io, contextlib
def add(a, b):
    return a + b
buf = io.StringIO()
with contextlib.redirect_stdout(buf):
    dis.dis(add)
print("BINARY_OP" in buf.getvalue() or "BINARY_ADD" in buf.getvalue())   # True
print(add(2, 3))                                                          # 5
```
```bash
python3 hello.py                 # 인터프리터: 바로 실행
g++ hello.cpp -o hello && ./hello   # 컴파일러: 번역 후 실행
```
