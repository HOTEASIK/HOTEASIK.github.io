# 터미널과 셸

## 정의·핵심
- **터미널**: 글자로 명령을 입력하고 결과를 보는 창. **셸(shell)**: 그 명령을 해석해 실행하는 프로그램 — 우분투 기본은 **bash**.
- **GUI vs CLI — 왜 까만 화면인가** (기초 1차시): 로봇 서버는 화면조차 없이 도는 경우가 많아 CLI가 사실상 유일한 손잡이다. 까만 화면은 불편함이 아니라 힘이다.

| 항목 | GUI | CLI |
|---|---|---|
| 방식 | 클릭·드래그 | 텍스트 명령 |
| 메모리 소비 | 높음 | 낮음 |
| 속도 | 상대적으로 느림 | 빠름 |
| 진입장벽 | 쉬움 | 어려움 |
| 자동화 | 어려움 | 강력(스크립트) |

- **손이 편해지는 두 습관**
  - **Tab 자동완성**: 몇 글자 치고 Tab → 나머지를 채운다. 후보가 여럿이면 Tab 두 번으로 목록. (`ros2 run my_` + Tab)
  - **위·아래 화살표(history)**: 방금 친 긴 명령을 꺼내 살짝 고쳐 재실행.
- **터미널 여러 개** (기초 2차시): 실습 내내 둘 이상 띄운다 — 한쪽은 서버(talker), 다른 쪽은 클라이언트(listener). 프로그램을 켜 둔 채 다른 창에서 또 켠다.
- **Ctrl+C**: 멈춘(또는 계속 도는) 프로그램 끊기. 이것만 알아도 막힘의 절반은 스스로 푼다.
  - 통신 프로그램은 상대를 기다리느라 멈춘 듯 보일 때가 많다 — 멈춘 게 아니라 **기다리는 중**(블로킹)이다.
- **SSH**: 원격 컴퓨터의 셸에 접속. 현장에서 화면 없는 로봇·서버를 다루는 기본 수단.

## 원리·구조
```
[터미널 창] ──키 입력──→ [셸 bash] ──해석──→ PATH에서 실행 파일 찾기 ──→ 프로세스 실행
                ↑                                                 │
                └──────────────── 출력(stdout/stderr) ─────────────┘
```

## 코드 예시
```python
# 셸이 하는 일(명령 해석 → 실행 → 출력)을 파이썬 subprocess로 흉내
import subprocess, sys
r = subprocess.run([sys.executable, "-c", "print('안녕, 파이썬')"],
                   capture_output=True, text=True, encoding="utf-8")
print(r.returncode, r.stdout.strip())     # 0 안녕, 파이썬
```
```bash
python3 hello.py       # 안녕, 파이썬
history | tail -5      # 최근 명령 5개
ssh user@192.168.0.5   # 원격 로봇에 접속
```
