# 프로세스 일생과 격리

## 정의·핵심
- **프로세스의 일생**: 생성(new) → 준비(ready) → 실행(running) ⇄ 대기(waiting) → 종료 (기초 1차시).
  - 생성: 메모리에 올라가 프로세스가 된다.
  - 준비: 대기열에서 CPU 차례를 기다린다.
  - 실행: CPU를 받아 명령을 처리한다.
  - 대기: 센서·디스크를 기다리며 멈춘다. 기다리던 일이 끝나면 다시 준비로.
  - 종료: 일을 마치고 사라진다.
- **핵심**: 실행 중이 아니라고 죽은 게 아니다. 센서를 기다리는 노드는 대부분의 시간을 **대기**로 보내며 CPU를 거의 안 쓴다 — 정상. 거꾸로 계속 실행에 머물며 **CPU 100%** 를 붙들고 있는 노드가 오히려 의심 신호.
- **격리**: 프로세스끼리는 각자 자기 책상만 보고 옆 책상은 못 본다. 이 격리가 **안전장치**다 — 카메라 노드가 죽어도 모터 노드는 살아 있을 수 있다.
  - 현업에서는 노드가 조용히 죽어도 로봇이 멈추지 않게, 죽으면 자동으로 다시 깨우는 장치를 둔다.
  - 대가: 주고받으려면 정해진 창구(통신, IPC)를 거쳐야 한다 → 기초 2차시 소켓 → ROS 통신.
- **부모·자식 관계**: 터미널이 부모, 내 노드가 자식.
  - **좀비(zombie)**: 자식은 죽었는데 부모가 사망 신고를 안 거둬 프로세스 표에 흔적만 남음. 잠깐은 정상이지만 쌓이면 새 프로세스를 못 만든다.
  - **고아(orphan)**: 부모가 먼저 죽고 자식만 남음. 최상위 프로세스가 입양해 뒤를 봐준다 — 큰 문제는 아니다.

## 원리·구조
```
 생성 ──→ 준비 ──(스케줄러 배정)──→ 실행 ──→ 종료
           ↑                        │
           └──── 대기 ←─(센서·디스크 기다림)
```

## 코드 예시
```python
# 프로세스 격리: 자식 프로세스가 바꾼 변수는 부모에게 보이지 않는다
import multiprocessing as mp
counter = 0

def child():
    global counter
    counter = 999            # 자식의 책상에서만 바뀜

if __name__ == "__main__":
    p = mp.Process(target=child)
    p.start(); p.join()
    print("부모가 본 counter:", counter)   # 부모가 본 counter: 0
    print("자식 종료 코드:", p.exitcode)    # 자식 종료 코드: 0
```
```bash
sleep 300 &              # 백그라운드로 프로세스 띄우기
ps aux | grep sleep      # PID 확인 (STAT 칸 S=대기, R=실행, Z=좀비)
kill <PID>               # 종료
```
