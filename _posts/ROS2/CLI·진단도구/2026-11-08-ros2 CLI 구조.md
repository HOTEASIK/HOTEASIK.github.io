# ros2 CLI 구조

## 정의·핵심
- **정의**: `ros2` 명령줄 도구. **로봇의 청진기** — 청진기가 몸을 열지 않고 안을 듣듯, 코드를 열지 않고 시스템 내부의 통신을 들려준다 (실습 1차시).
- **골격은 〈대상〉〈행동〉**: `ros2 topic list`(토픽을 나열하라), `ros2 node info`(노드의 정보를 보여라), `ros2 pkg executables`, `ros2 action send_goal`. 대상만 알면 행동은 `-h`로 찾는다.
- **문제는 코드가 아니라 노드 사이의 연결에 있는 경우가 많다** — 코드를 뜯기 전에 명령줄로 지금을 듣는다.
- **확보할 능력 다섯 갈래**: 보기(list·info·echo) / 재기(hz·bw) / 직접 넣기(pub·call·send_goal·param set) / 저장·재현(bag·param dump) / 환경 점검(doctor·daemon).
- **진단은 위에서 아래로**: 노드 → 연결 → 이름 → 값 → 주기 순으로 범위를 좁힌다([[진단 사다리]]).
- **데몬(daemon)**: list 명령은 뒤에서 도는 도우미가 기억해 둔 목록을 읽는다 — 갑자기 죽은 노드가 한동안 남아 보일 수 있다 → `--no-daemon`(지금을 직접 묻기), `ros2 daemon stop`(기억 비우기).
- **탭 완성**: `ros2 to<Tab>`, 토픽 이름·타입까지 완성된다 — 오타 방지.
- 실행을 멈출 때는 `^C`. 켜 둔 `topic pub -r`을 잊으면 거북이가 계속 돈다.

## 원리·구조
| 대상 | 주요 행동 |
|---|---|
| `node` | list, info |
| `topic` | list, info, echo, pub, hz, bw, find, type |
| `service` | list, type, call, find |
| `action` | list, info, send_goal |
| `param` | list, get, set, describe, dump, load |
| `interface` | list, show, package |
| `pkg` | list, executables, prefix, create, xml |
| `run` / `launch` | 실행 |
| `bag` | record, play, info, convert |
| `doctor` / `daemon` | 환경 점검 / 도우미 관리 |
| `component` / `lifecycle` | 컨테이너 적재 / 상태 전이 |

## 코드 예시
```python
# 〈대상〉〈행동〉 골격 검사기
VERBS = {"node": {"list", "info"}, "topic": {"list", "info", "echo", "pub", "hz", "bw", "find", "type"},
         "service": {"list", "type", "call", "find"}, "param": {"list", "get", "set", "describe", "dump", "load"}}
def check(cmd):
    parts = cmd.split()
    if parts[:1] != ["ros2"] or len(parts) < 3: return "형식: ros2 <대상> <행동> ..."
    tgt, verb = parts[1], parts[2]
    if tgt not in VERBS: return f"대상 '{tgt}' 모름 → ros2 -h"
    return "OK" if verb in VERBS[tgt] else f"'{tgt}'의 행동: {sorted(VERBS[tgt])}"
print(check("ros2 topic hz /turtle1/pose"))   # OK
print(check("ros2 node echo /turtlesim"))     # 'node'의 행동: ['info', 'list']
```
```bash
ros2 -h
ros2 topic -h
ros2 node list --no-daemon
ros2 daemon status
```
