# ros2 topic

## 정의·핵심
- **정의**: 토픽을 보고, 재고, 직접 흘려보내는 명령 묶음 — 가장 많이 쓰는 청진기 (기초 4차시, 실습 1차시).
- **보기**: `list`(`-t` 타입까지) · `info`(타입, 발행·구독 수, `--verbose` QoS까지) · `echo`(값) · `type` · `find 타입`(그 타입을 쓰는 토픽 — 아무것도 안 찍히는 것도 정상 답).
- **재기**: `hz`(측정된 평균 주기를 갱신하며 — `average rate: 9.998`) · `bw`(초당 흐르는 데이터 양 — 영상·점구름이 망을 얼마나 먹나).
- **직접 넣기 `pub`**: `ros2 topic pub <토픽> <타입> "<YAML>"` — 코드 없이 받는 쪽을 시험.
  - `-r 10`: 10Hz로 계속(거북이가 원을 그리며 돈다), Ctrl+C로 멈춤.
  - `--once`: 한 번 보내고 끝 — 단, **받는 쪽이 하나라도 붙을 때까지 기다렸다** 보낸다. 듣는 쪽이 없으면 끝나지 않는다 → 진단 단서.
  - YAML: 콜론 뒤 공백, 전체를 따옴표로 — `"{linear: {x: 2.0}, angular: {z: 1.0}}"`.
- **토픽은 발행자나 구독자 중 하나만 있어도 목록에 선다**: 거북이가 `/turtle1/cmd_vel`을 구독하니 아무도 안 보내도 목록에 있다.
- **현장 시나리오 — 로봇이 안 움직인다**: echo로 명령이 흐르는지 듣고(안 흐르면 보내는 쪽), pub으로 직접 넣어 움직이면 받는 쪽은 정상 → 문제를 반으로 가른다.

## 원리·구조
| 명령 | 답하는 질문 |
|---|---|
| `topic list -t` | 어떤 토픽이 어떤 타입으로? |
| `topic info /t -v` | 누가 보내고 누가 받나, QoS는? |
| `topic echo /t` | 지금 무슨 값이 흐르나? |
| `topic hz /t` | 얼마나 자주? |
| `topic bw /t` | 얼마나 많이? |
| `topic pub /t T "..."` | 내가 넣으면 반응하나? |

## 코드 예시
```python
# topic hz 가 하는 계산: 도착 시각들로 평균 주기·표준편차
import statistics as st
stamps = [0.000, 0.101, 0.199, 0.300, 0.402, 0.500, 0.601]
dts = [b - a for a, b in zip(stamps, stamps[1:])]
rate = 1 / st.mean(dts)
print(f"average rate: {rate:.3f}")                      # average rate: 9.983
print(f"min: {min(dts):.3f}s max: {max(dts):.3f}s std dev: {st.pstdev(dts):.5f}s window: {len(stamps)}")
# min: 0.098s max: 0.102s std dev: 0.00143s window: 7
# topic bw: 메시지 크기 × 주기
print(f"{640*480*3*30/1e6:.1f} MB/s")                    # 27.6 MB/s ← 640x480 bgr8 30Hz 영상
```
```bash
ros2 topic list -t
ros2 topic pub -r 10 /turtle1/cmd_vel geometry_msgs/msg/Twist "{linear: {x: 2.0}, angular: {z: 1.0}}"
ros2 topic pub --once /turtle1/cmd_vel geometry_msgs/msg/Twist "{linear: {x: 1.0}}"
ros2 topic hz /turtle1/pose
ros2 topic bw /turtle1/pose
ros2 topic find turtlesim/msg/Pose
```
