# 정의
로봇뿐만 아니라 주변 환경, 센서, 조명, 물리 엔진 파라미터까지 포괄적으로 정의하기 위한 시뮬레이션 전용 포맷
**SDF (Simulation Description Format)**: Gazebo(gz sim)가 읽는 XML 형식. 파일 하나가 **월드(world) 전체**를 담을 수 있다.

# URDF와 비교
| 구분 | [[URDF]] | SDF |
|---|---|---|
| 대상 | 로봇 한 대 | 월드 전체 (로봇 여러 대 + 환경) |
| 쓰는 곳 | ROS 도구 (RViz, robot_state_publisher, TF) | Gazebo 시뮬레이터 |
| 담는 것 | 링크·조인트·모양 | + 지형·물체·조명·중력·물리 엔진·센서·플러그인 |
| 구조 | 트리 (부모 하나) | 닫힌 고리 구조도 표현 가능 |

# 구성
```xml
<sdf version="1.9">
  <world name="demo">
    <physics type="ode"> ... </physics>       <!-- 물리 엔진 설정 -->
    <light name="sun" type="directional"> ... </light>
    <model name="box">
      <link name="link">
        <collision> ... </collision>          <!-- 충돌용 모양 -->
        <visual> ... </visual>                <!-- 화면용 모양 -->
        <inertial> ... </inertial>            <!-- 질량·관성 -->
        <sensor type="gpu_lidar"> ... </sensor>
      </link>
    </model>
  </world>
</sdf>
```
- 시뮬레이터에서는 `visual`만으로 부족하다 — 부딪힘과 무게를 계산하려면 `collision`·`inertial`이 함께 필요하다

# 실행 (Jazzy + Gazebo Harmonic)
```bash
sudo apt install -y ros-jazzy-ros-gz     # ROS2 ↔ Gazebo 통합 꾸러미
gz sim shapes.sdf                        # 도형 여섯 개가 놓인 예제 월드 (▶ 눌러야 시간이 흐름)
gz sim -s -r shapes.sdf                  # 화면 없이 서버만, 바로 실행
```
- Gazebo와 ROS2 토픽은 `ros_gz_bridge`로 잇는다 (구형 Classic의 `gazebo_ros`는 지원 종료)
- Gazebo의 가상 센서(라이다·카메라·IMU)는 실제 센서와 같은 메시지 타입으로 나온다

# RViz vs Gazebo
| | RViz | Gazebo |
|---|---|---|
| 하는 일 | 데이터 시각화 | 물리 시뮬레이션 |
| 물리 계산 | 안 함 | 함 |
| 한마디 | 로봇이 아는 것 | 실제로 일어나는 것 |
