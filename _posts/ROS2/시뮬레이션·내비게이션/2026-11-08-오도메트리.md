# 오도메트리

## 정의·핵심
- **정의**: 바퀴가 몇 바퀴 굴렀는지 헤아려 **이동 거리와 회전을 추정**한 「내가 방금 얼마나 움직였는가」 — 토픽 `/odom`(nav_msgs/msg/Odometry), TF `odom → base_link` (실습 5차시).
- **약점 — 누적 오차**: 바퀴가 미끄러지거나 헛돌면 오차가 점점 쌓인다.
- **라이다로 바로잡는다**: 그 일이 SLAM(지도를 그리며)과 AMCL(있는 지도 위에서)의 몫 — 「바퀴로 어림하고, 라이다로 바로잡는다」가 이동 로봇 위치 추정의 핵심 구도.
- **TF 트리에서의 자리**: `map → odom`(SLAM·AMCL이 보정) → `odom → base_link`(오도메트리, 매끄럽지만 드리프트) → `base_link → base_scan`(URDF).
- **시뮬레이션에서**: Gazebo가 계산한 새 위치가 다리를 건너 `/odom`으로 나온다(`gz.msgs.Odometry -> nav_msgs/msg/Odometry`). 명령(/cmd_vel)이 들어가 → 계산 → 관측(/odom)이 나오는 닫힌 고리를 숫자로 본다.
- **확인**: `ros2 topic echo --once /odom --field pose.pose.position` — 움직이기 전 x 9.6e-09(거의 0), w로 조금 뒤 0.134.
- 엔코더 원리와 차동 구동 계산은 [[엔코더]].

## 원리·구조
```
엔코더 틱 → 바퀴 회전각 → (좌·우 바퀴 이동거리) → Δs, Δθ → (x, y, θ) 적분
nav_msgs/msg/Odometry: header(frame_id=odom), child_frame_id=base_link,
                       pose.pose(position, orientation), twist.twist
```

## 코드 예시
```python
# 차동 구동 오도메트리 적분 + 미끄러짐으로 쌓이는 오차
import math
def integrate(steps, slip=0.0, b=0.16):
    x = y = th = 0.0
    for dl, dr in steps:
        dr *= (1 - slip)                     # 오른쪽 바퀴가 조금 헛돈다
        ds, dth = (dl + dr) / 2, (dr - dl) / b
        x += ds * math.cos(th + dth / 2); y += ds * math.sin(th + dth / 2); th += dth
    return round(x, 3), round(y, 3), round(math.degrees(th), 1)
straight = [(0.01, 0.01)] * 100              # 1 m 직진
print(integrate(straight))                   # (1.0, 0.0, 0.0)
print(integrate(straight, slip=0.02))        # (0.987, -0.062, -7.2)  ← 직진했다고 믿지만 휘었다
```
```bash
ros2 topic echo --once /odom --field pose.pose.position
ros2 run tf2_ros tf2_echo odom base_link
```
