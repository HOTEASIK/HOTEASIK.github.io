# QoS 호환 규칙

## 정의·핵심
- **정의**: 연결되려면 **발행자가 제공(Offered)하는 수준이 구독자가 요청(Requested)하는 수준보다 같거나 더 강해야 한다** (실습 2차시).
- **요청** = 「최소한 이만큼은 해 줘야 한다」는 요구 조건, **제공** = 「내가 해 줄 수 있는 수준」. 「약속한 쪽이 요구받은 것을 들어줄 수 있는가」라는 상식과 같다.
- **강한 쪽만 기억**: 신뢰성은 RELIABLE, 지속성은 TRANSIENT_LOCAL — 표를 외우지 않아도 매번 추론된다.
- **비유 — 등기와 일반우편**: 요구 「최소한 등기로」 + 제공 「일반우편만 가능」 → 거래 불성립. 요구 「일반우편이면 된다」 + 제공 「등기로 보내겠다」 → 문제없음.
- **두 축은 독립**: reliability(빠짐없이?)와 durability(늦은 구독자도?)는 다른 질문 — 규칙은 둘 다 「발행자가 같거나 강해야」. 어느 축이 깨졌는지는 경고 끝 낱말 `RELIABILITY`·`DURABILITY`가 알려 준다.
- **echo는 상대에 맞춰 붙는다**: 옵션 없는 `ros2 topic echo`는 구독 전에 발행자를 먼저 보고 호환되는 약속으로 붙는다(`--help` 기본값 「Compatible profile with running endpoints」). 옵션을 붙인 echo와 **내가 짠 노드는 적은 약속을 고집** — 그래서 echo는 받는데 내 노드는 못 받는 일이 생긴다.
- **경고 두 줄의 말도 규칙 그대로**: 구독 쪽 `offering incompatible QoS`(상대가 내놓는 약속이 안 맞음), 발행 쪽 `requesting incompatible QoS`(상대가 요구하는 약속이 안 맞음).

## 원리·구조
```
강도:  BEST_EFFORT < RELIABLE        VOLATILE < TRANSIENT_LOCAL
연결:  offered >= requested  (두 축 모두)
```

## 코드 예시
```python
# 호환 판정기 — 끊기면 경고 끝 낱말을 돌려준다
RANK = {"BEST_EFFORT": 0, "RELIABLE": 1, "VOLATILE": 0, "TRANSIENT_LOCAL": 1}
def compatible(pub, sub):
    for policy, p, s in (("RELIABILITY", pub[0], sub[0]), ("DURABILITY", pub[1], sub[1])):
        if RANK[p] < RANK[s]:
            return f"✖ Last incompatible policy: {policy}"
    return "○ 연결"
print(compatible(("BEST_EFFORT", "VOLATILE"), ("RELIABLE", "VOLATILE")))   # ✖ Last incompatible policy: RELIABILITY
print(compatible(("RELIABLE", "VOLATILE"), ("BEST_EFFORT", "VOLATILE")))   # ○ 연결
print(compatible(("RELIABLE", "VOLATILE"), ("RELIABLE", "TRANSIENT_LOCAL")))   # ✖ Last incompatible policy: DURABILITY
print(compatible(("RELIABLE", "TRANSIENT_LOCAL"), ("RELIABLE", "VOLATILE")))   # ○ 연결
```
