# QoS 프리셋

## 정의·핵심
- **정의**: 네 항목을 용도에 맞게 **미리 채워 둔 프로파일**. 대표는 `qos_profile_sensor_data` — BEST_EFFORT 기반, KEEP_LAST에 적당한 depth (실습 2차시).
- **마법이 아니다**: 센서용 BEST_EFFORT 프로파일을 직접 만들어 끼운 것과 같다. 안에 무엇이 들었는지 알고 써야 verbose에서 「왜 BEST_EFFORT지?」 하고 당황하지 않는다.
- **센서 구독엔 프리셋 한 줄**: `self.create_subscription(LaserScan, 'scan', self.cb, qos_profile_sensor_data)` — 숫자 10(RELIABLE)으로 두면 드라이버(대부분 BEST_EFFORT)와 어긋나 수신 0 + 경고 한 줄(`Last incompatible policy: RELIABILITY`), 콜백은 한 번도 안 불린다.
- **세 가지 핵심 조합 — 실무 대부분이 여기로 수렴**
  - 센서(라이다·카메라): BEST_EFFORT + KEEP_LAST — 최신 값만 중요, 재전송 부담 회피.
  - 속도 명령(cmd_vel): RELIABLE + KEEP_LAST — 한 번이라도 놓치면 안전 문제.
  - 지도(map)·정적 파라미터/상태: RELIABLE + TRANSIENT_LOCAL — 빠짐없이 + 늦은 구독자도.
- **처음 보는 토픽**: 「센서인가 · 명령인가 · 지도인가」만 판단하면 약속이 거의 자동으로 정해진다.
- 그 밖의 rclpy 프리셋: `qos_profile_system_default`, `qos_profile_services_default`, `qos_profile_parameters` 등.

## 원리·구조
| 데이터 | 권장 | 이유 |
|---|---|---|
| 라이다·카메라 | BEST_EFFORT + KEEP_LAST | 최신 값, 재전송 회피 |
| cmd_vel | RELIABLE + KEEP_LAST | 놓치면 안전 문제 |
| map | RELIABLE + TRANSIENT_LOCAL | 늦은 구독자도 |
| 정적 파라미터/상태 | RELIABLE + TRANSIENT_LOCAL | 한 번 알리면 유지 |

## 코드 예시
```python
from rclpy.qos import qos_profile_sensor_data, ReliabilityPolicy
from sensor_msgs.msg import LaserScan

print(qos_profile_sensor_data.reliability == ReliabilityPolicy.BEST_EFFORT)   # True
print(qos_profile_sensor_data.depth)                                          # 5

# 노드 __init__ 안에서 — 10 대신 프리셋
# self.create_subscription(LaserScan, 'scan', self.cb, qos_profile_sensor_data)
```
