# QoS 불일치 진단

## 정의·핵심
- **정의**: 「토픽은 흐르는데 내 노드만 못 받는다」를 **경고 한 줄 → verbose** 순으로 원인 확정하는 절차 (실습 1·2차시).
- **의심 순서**: ① 토픽 이름이 정말 같은가(`/scan` vs `/Scan`) ② 메시지 타입이 같은가 ③ 그다음 QoS — 먼저 경고를 읽는다 ④ `topic info --verbose`로 양쪽 약속을 나란히 놓고 확정.
- **불일치의 지문 넷**: 발행자 터미널엔 「보냄」이 흐른다 / 구독자엔 「받음」이 한 줄도 없다 / 양쪽에 경고 한 줄씩, 끝은 `Last incompatible policy: RELIABILITY` / 두 노드 모두 멈추지 않는다(그래서 놓치기 쉽다).
- **경고는 한 번만**: 구독 쪽은 띄우고 1초 안팎 뒤 한 번(그 한 줄이 화면의 전부), 발행 쪽은 「보냄」 줄 사이에 끼어 곧 밀려난다. 어긋난 구독자가 새로 붙을 때가 아니면 다시 안 뜬다. `[WARN]` 머리가 `[INFO]`와 구분하는 유일한 표지.
- **hz는 멀쩡히 찍힌다**: `ros2 topic hz`는 발행자와 상관없이 붙도록 만든 도구 — 수신 0인 구독자가 붙어 있는 순간에도 `average rate: 2.000`. hz가 본 것은 흐름이지 내 노드와의 연결이 아니다.
- **verbose 읽기**: Publisher count 아래 발행자, Subscription count 아래 구독자의 QoS profile — Reliability·Durability를 위아래로 비교. `History (Depth): UNKNOWN`.
- **증상별 갈래**
  - 수신 0 + RELIABILITY 경고 → 신뢰성 불일치(1순위 용의자).
  - 늦게 켠 구독자만 못 받음, 경고 없음 → 발행자 VOLATILE + 발행이 이미 끝남(타이밍).
  - 과거 값 요구한 구독자 수신 0 + DURABILITY 경고 → 지속성 불일치.
  - 버스트 후 일부 누락, 경고 없음 → depth 부족.

## 원리·구조
```
[WARN] [...] [qos_listener]: New publisher discovered on topic 'qos_chat',
  offering incompatible QoS. No messages will be received from it.
  Last incompatible policy: RELIABILITY
$ ros2 topic info /qos_chat --verbose
  (Publisher)    Reliability: BEST_EFFORT   Durability: VOLATILE
  (Subscription) Reliability: RELIABLE      Durability: VOLATILE   ← 이 줄이 범인
```

## 코드 예시
```python
# 로그에서 QoS 경고를 찾아 어긋난 항목과 어느 쪽인지 뽑기
log = """[INFO] [1790493137.009760128] [qos_talker]: 보냄: hello 5
[WARN] [1790493137.016067666] [qos_talker]: New subscription discovered on topic 'qos_chat', requesting incompatible QoS. No messages will be sent to it. Last incompatible policy: RELIABILITY
[INFO] [1790493137.509682460] [qos_talker]: 보냄: hello 6"""
for line in log.splitlines():
    if line.startswith("[WARN]") and "incompatible QoS" in line:
        side = "발행 쪽" if "requesting" in line else "구독 쪽"
        policy = line.rsplit(": ", 1)[1]
        topic = line.split("topic '")[1].split("'")[0]
        print(side, topic, policy)        # 발행 쪽 qos_chat RELIABILITY
```
```bash
ros2 topic info /qos_chat --verbose
ros2 topic echo /qos_chat --qos-reliability reliable    # 내 노드처럼 고집 → 재현
```
