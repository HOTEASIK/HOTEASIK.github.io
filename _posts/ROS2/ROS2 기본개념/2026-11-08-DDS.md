# DDS

## 정의·핵심
- **정의**: Data Distribution Service. 발행·구독 방식의 산업 표준 통신 미들웨어. **ROS2의 통신을 실제로 떠받치는 층**이다 — 이름만 맞추면 통하던 동작, IP·포트·직렬화·끊김 처리를 대신해 준 정체 (기초 3차시).
- **하는 일**
  - **발견(discovery)**: 같은 네트워크·같은 도메인의 참가자들이 서로를 자동으로 찾는다 → 중앙 마스터가 필요 없다.
  - **직렬화**: 메시지를 공통 형식(CDR)으로 바꿔 보낸다 → C++ talker와 Python listener가 코드 0줄로 통한다. 언어와 무관.
  - **전달**: 보통 UDP 위에서 돌며, 큰 메시지는 조각내 보낸다.
  - **QoS**: 신뢰성·지속성·이력 등 "통신의 약속"을 고른다 (실습 2차시).
- **도메인**: DDS에는 같은 물리 네트워크를 여러 논리 네트워크로 나누는 번호가 있다 = `ROS_DOMAIN_ID`. 발견조차 도메인 안에서만 일어난다.
- **RMW(ROS Middleware interface)**: ROS2와 DDS 구현 사이의 갈아끼우는 층. Jazzy 기본은 Fast DDS(`rmw_fastrtps_cpp`), Cyclone DDS 등으로 바꿀 수 있다(`RMW_IMPLEMENTATION`).
- **DDS 위에 있다는 사실이 실무에 주는 것** (실습 2차시): 통신이 안 될 때 DDS의 발견·QoS·네트워크(멀티캐스트, 방화벽, WiFi)를 의심할 줄 알아야 한다.

## 원리·구조
```
 노드(rclpy) ─→ rcl ─→ rmw ─→ DDS 구현(Fast DDS / Cyclone DDS) ─→ UDP/IP 네트워크
                                   │
                    발견(SPDP/SEDP) · 직렬화(CDR) · QoS · 전달
```
| 소켓으로 직접 할 때 | DDS가 대신 |
|---|---|
| 상대 IP·포트 적기 | 자동 발견 |
| encode·split 규칙 | CDR 직렬화 |
| while·끊김 처리 | 연결 관리·재연결 |
| 연결마다 관리(1:N) | 같은 토픽 구독만 |

## 코드 예시
```bash
printenv RMW_IMPLEMENTATION                 # 비어 있으면 기본(Fast DDS)
ros2 doctor --report | grep -i middleware   # 쓰는 RMW 확인
export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp   # (설치돼 있으면) 다른 DDS로
```
