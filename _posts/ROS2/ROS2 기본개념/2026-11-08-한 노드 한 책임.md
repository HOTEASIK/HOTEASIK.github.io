# 한 노드 한 책임

## 정의·핵심
- **원칙**: 노드 하나는 **한 가지 일**만 맡는다 (단일 책임 원칙의 ROS판) (기초 4차시, 입문 1차시).
- **두 가지 시험**
  - **"그리고" 시험**: 노드가 하는 일을 한 문장으로 말해 본다. 「카메라 영상을 받고 **그리고** 사람을 찾고 **그리고** 모터를 돌린다」 — 접속사가 끼면 쪼갤 때.
  - **이사 시험**: 이 노드를 떼어 다른 로봇에 그대로 옮겨 쓸 수 있나? 안 되면 책임이 엉켜 있다.
- **얻는 것**: 고장 격리(하나가 죽어도 나머지는 산다), 교체(길찾기만 새 알고리즘으로), 재사용, 테스트(노드 하나만 띄워 `topic pub`으로 시험), 분업(사람마다 노드 하나).
- **너무 잘게도 금물**: 수백 개로 쪼개면 토픽 배선이 거미줄, 통신 지연·관리 비용이 커진다. 함께 바뀌고 함께 배포되는 것은 한 노드로.
- **설계는 사람 몫**: ROS는 연결을 해 주지만 「어디서 자를지」는 정해 주지 않는다 — 시스템 그림(노드·토픽)을 먼저 그리고 코드를 쓴다.

## 원리·구조
| | 거대 노드 하나 | 책임별 분리 |
|---|---|---|
| 고장 | 한 곳 에러 → 전체 정지 | 그 노드만 재시작 |
| 수정 | 전체를 다시 빌드·테스트 | 해당 노드만 |
| 재사용 | 통째로만 | 노드 단위로 다른 로봇에 |
| 성능 | 통신 비용 없음 | 토픽 비용 약간 (필요 시 Component로 합침) |
| 디버깅 | 로그가 뒤섞임 | rqt_graph·echo로 경계마다 확인 |
```
나쁨:  [robot_main: 카메라+인식+판단+모터]
좋음:  [camera] →/image→ [detector] →/person→ [decider] →/cmd_vel→ [motor_driver]
```

## 코드 예시
```python
# "그리고" 시험: 설명 문장에 접속사가 몇 번 나오나
import re
def and_test(desc):
    n = len(re.findall(r"그리고|및 |, ", desc))
    return "OK" if n == 0 else f"쪼개기 후보({n + 1}가지 일)"
print(and_test("카메라 영상을 발행한다"))                               # OK
print(and_test("영상을 받고, 사람을 찾고, 모터를 돌린다"))        # 쪼개기 후보(3가지 일)
```
