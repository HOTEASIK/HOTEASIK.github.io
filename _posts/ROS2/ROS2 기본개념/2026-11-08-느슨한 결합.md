# 느슨한 결합

## 정의·핵심
- **정의**: 노드들이 서로를 **직접 알지 않고** 토픽 이름과 메시지 타입이라는 **약속만** 공유하는 구조. 발행자는 누가 듣는지, 구독자는 누가 보내는지 모른다 (입문 1차시).
- **ROS2는 분산 시스템**: 노드 = 각자의 프로세스(때로는 다른 컴퓨터). 함수 호출로 엮인 한 프로그램이 아니라 메시지로 엮인 여러 프로그램.
- **"통신은 ROS, 로직은 나"**: 연결·발견·재연결은 ROS가, 무엇을 계산할지는 내가.
- **얻는 것**
  - 교체: 진짜 라이다 노드 ↔ 시뮬레이터 ↔ bag 재생을 바꿔 끼워도 받는 쪽 코드는 그대로.
  - 확장: 구독자를 하나 더 붙여도 발행자는 손대지 않는다.
  - 언어 자유: C++ 노드와 Python 노드가 섞인다.
- **라이브러리 vs 프레임워크**: 라이브러리는 내가 부르고, 프레임워크(ROS2)는 나를 부른다 — 나는 **콜백**을 등록하고 `spin`에 맡긴다(제어의 역전).
- **노드 일생 3단계**: ① 생성·설정(발행자·구독자·타이머·콜백 등록) → ② spin(이벤트가 올 때마다 콜백) → ③ 종료·정리.
- **ROS를 쓰지 않아도 될 때**: 프로그램 하나로 끝나는 스크립트, 한 번 쓰고 버릴 실험 — 느슨한 결합의 이득보다 워크스페이스·빌드 비용이 크다.
- **대가**: 이름 오타·타입 불일치가 컴파일 에러가 아니라 **조용한 무통신**으로 나타난다 → `topic info`·rqt_graph로 확인하는 습관.

## 원리·구조
```
강한 결합:  camera.get_frame() → detector.run(frame) → motor.set(v)   (서로의 함수를 직접 호출)
느슨한 결합: [camera] ─/image→ ( ROS ) ─/image→ [detector] ─/cmd_vel→ ( ROS ) → [motor]
             발행자는 구독자를 모른다 · 구독자는 발행자를 모른다
```

## 코드 예시
```python
# 발행자를 바꿔 끼워도 구독자 코드는 그대로 (콜백 = 프레임워크가 부르는 함수)
subs = {}
def subscribe(topic, cb): subs.setdefault(topic, []).append(cb)
def publish(topic, msg): [cb(msg) for cb in subs.get(topic, [])]

def on_scan(msg): print("최소 거리:", min(msg))     # 내 로직
subscribe("/scan", on_scan)

def real_lidar(): publish("/scan", [1.2, 0.8, 2.5])
def bag_replay(): publish("/scan", [0.5, 0.9])
real_lidar()    # 최소 거리: 0.8
bag_replay()    # 최소 거리: 0.5
```
