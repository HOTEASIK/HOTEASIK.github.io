# 메시지 타입

## 정의·핵심
- **정의**: 토픽으로 오가는 데이터의 **모양(필드 이름과 자료형)** 을 정한 약속. 편지 양식 — 양식이 같아야 받는 쪽이 읽을 수 있다 (기초 4차시).
- **이름은 세 부분**: `패키지/msg/타입` — 예 `std_msgs/msg/String`, `geometry_msgs/msg/Twist`. 가운데 `msg`는 토픽용(서비스는 `srv`, 액션은 `action`).
- **발행자와 구독자의 타입이 같아야** 연결된다. 다르면 `ros2 topic info`에 둘 다 보여도 데이터는 오지 않는다.
- **자주 보는 패키지**
  - `std_msgs`: String, Int32, Float64, Bool… (기본형. `String`은 공식적으로 권장되지 않지만 실습에서는 많이 쓴다)
  - `geometry_msgs`: Point(x,y,z), Twist(linear·angular, 각각 Vector3), Pose, PoseStamped
  - `sensor_msgs`: Image, LaserScan, Imu, PointCloud2
- **중첩**: 메시지 안에 메시지 — Twist = linear(Vector3) + angular(Vector3), Vector3 = x,y,z(float64).
- 내용 보기: `ros2 interface show geometry_msgs/msg/Twist`.

## 원리·구조
```
geometry_msgs/msg/Twist
 ├─ linear : Vector3 { float64 x, y, z }    ← 앞뒤(x) 속도
 └─ angular: Vector3 { float64 x, y, z }    ← 회전(z) 속도
YAML로 쓰면: "{linear: {x: 2.0}, angular: {z: 1.8}}"
```

## 코드 예시
```python
# 타입 이름 3부분 쪼개기 + 중첩 메시지를 dict로 흉내
def split_type(t):
    pkg, kind, name = t.split("/")
    return pkg, kind, name
print(split_type("geometry_msgs/msg/Twist"))     # ('geometry_msgs', 'msg', 'Twist')

twist = {"linear": {"x": 2.0, "y": 0.0, "z": 0.0}, "angular": {"x": 0.0, "y": 0.0, "z": 1.8}}
print(twist["linear"]["x"], twist["angular"]["z"])   # 2.0 1.8
```
```bash
ros2 interface show geometry_msgs/msg/Twist
ros2 topic list -t                 # /turtle1/cmd_vel [geometry_msgs/msg/Twist]
```
