# ROS1과 ROS2

## 정의·핵심
- **ROS1**: 연구실·학교에서 오래 다져진 1세대. 가운데에 **마스터(roscore)** 라는 중앙 교환원이 있어 모든 노드 이름을 등록받고 누가 무엇을 주고받는지 중매했다 → 교환원이 끊기거나 죽으면 **시스템 전체가 마비**(단일 실패 지점). 마지막 배포판 Noetic(2020~2025년 5월 지원 종료) (기초 3·4차시).
- **ROS2**: 중앙 교환원을 없애고 **DDS 기반 분산 발견**으로 바꿨다. 같은 네트워크(같은 도메인)의 노드들이 서로를 직접 찾아 연결 → 더 튼튼하고, 여러 로봇이 얽히는 현장에 잘 맞는다.
- **뼈대는 그대로**: 노드·토픽·패키지라는 골격은 두 버전이 똑같다. 달라진 것은 노드를 어떻게 잇고 어떻게 빌드하느냐 같은 아래쪽 토대.
- 도메인 ID(`ROS_DOMAIN_ID`)는 「서로 직접 찾아 연결하는」 ROS2 구조 위에서 작동하는 장치다.

## 원리·구조
| 항목 | ROS1 | ROS2 | 한 줄 의미 |
|---|---|---|---|
| 노드를 잇는 방식 | 중앙 마스터 roscore가 중매 | 마스터 없이 분산 탐색(자동 discovery) | 중매쟁이가 죽으면 멈추던 약점 해소 |
| 동작 플랫폼 | 주로 Linux | Linux·Windows·macOS | 사용 환경의 폭 |
| 빌드 도구 | catkin (CMake 중심) | ament + colcon | C++·파이썬 혼용이 깔끔 |
| 언어 버전 | C++03 · Python 2 | C++17 · Python 3 | 최신 언어 기능 |
| 겨냥하는 용도 | 주로 연구·학술 | 상업 제품까지 | 실제 출시 로봇용 설계 |
| 통신 품질 | TCPROS 고정 | DDS QoS로 선택 | 신뢰성·지속성 조절 |
```
ROS1:   노드A ─등록→ [roscore] ←등록─ 노드B     (roscore 죽으면 새 연결 불가)
ROS2:   노드A ←──DDS 자동 발견──→ 노드B          (중앙 없음)
```

## 코드 예시
```python
# 중앙 중매(ROS1) vs 분산 발견(ROS2)을 흉내: 중매자가 죽었을 때 새 노드가 연결될 수 있나
class Master:
    alive = True
    def register(self, n): return self.alive
m = Master(); m.alive = False
print("ROS1 새 노드 연결:", m.register("listener"))     # ROS1 새 노드 연결: False

domain = {"talker"}                                      # 같은 도메인의 참가자 목록(각자 광고)
def discover(name): domain.add(name); return "talker" in domain
print("ROS2 새 노드 연결:", discover("listener"))        # ROS2 새 노드 연결: True
```
