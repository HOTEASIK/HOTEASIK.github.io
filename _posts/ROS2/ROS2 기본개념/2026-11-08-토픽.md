# 토픽

## 정의·핵심
- **정의**: 노드끼리 메시지를 주고받는 **이름 붙은 통로**. 발행자(publisher)가 보내고 구독자(subscriber)가 받는다. **비동기·단방향** — 보내는 쪽은 받는 쪽이 있는지 기다리지 않고 계속 쏜다 (기초 4차시).
- **비유**: 단톡방 이름. 방 이름(`/chatter`)만 알면 누구나 글을 올리고(발행) 누구나 읽는다(구독). 서로 연락처(IP)를 몰라도 된다.
- **연결 형태**: 1:N(카메라 하나 → 인식·녹화·화면 여럿), N:1(센서 여럿 → 융합 노드 하나), N:N 모두 가능. 소켓이라면 연결마다 따로 관리했을 일.
- **두 가지 약속**: 토픽 **이름**이 정확히 같아야 하고(대소문자·슬래시까지), **메시지 타입**도 같아야 한다. 이름이 한 글자 다르면 에러 없이 **조용히** 안 통한다.
- **언제 쓰나**: 계속 흘러가는 데이터 — 센서 값, 영상, 속도 명령, 위치. ROS 코드의 약 70%가 토픽 (기초 5차시).
- **맞지 않는 곳**: 「답이 꼭 필요한」 요청(→ 서비스), 오래 걸리고 중간 보고·취소가 필요한 일(→ 액션).
- 기본으로 떠 있는 토픽: `/parameter_events`, `/rosout`(로그 모음).

## 원리·구조
```
[카메라 노드] ─publish→ ( /image_raw ) ─→ [인식 노드]
                                       ├→ [녹화 노드]
                                       └→ [ros2 topic echo]
```
| 명령 | 용도 |
|---|---|
| `ros2 topic list -t` | 토픽과 타입 |
| `ros2 topic info /t` | 타입, 발행자·구독자 수 |
| `ros2 topic echo /t` | 내용 엿보기 |
| `ros2 topic hz /t` | 주기(Hz) |
| `ros2 topic pub /t <타입> "<값>"` | 손으로 발행 |

## 코드 예시
```python
# 토픽 = 이름으로 묶인 발행·구독. 순수 파이썬으로 흉내 낸 버스
from collections import defaultdict
bus = defaultdict(list)
def subscribe(topic, cb): bus[topic].append(cb)
def publish(topic, msg):
    for cb in bus[topic]: cb(msg)
    return len(bus[topic])

subscribe("/chatter", lambda m: print("listener:", m))
subscribe("/chatter", lambda m: print("echo    :", m))
print(publish("/chatter", "Hello World: 0"))   # listener: Hello World: 0 / echo    : Hello World: 0 / 2
print(publish("/Chatter", "오타"))              # 0  ← 에러 없이 아무도 못 받음
```
