# 노드

## 정의·핵심
- **정의**: 하나의 목적만 수행하도록 분리된, **가장 작은 실행 단위의 프로그램**. 보통 프로세스 하나로 돈다 — 자기 메모리 공간에서 따로 돌고 옆 노드에 직접 간섭하지 않는다 (기초 4차시, 입문 1차시).
- **식당 비유**: 한 사람은 주문만, 한 사람은 면만 삶고, 한 사람은 서빙만. 로봇에서는 카메라 노드, 바퀴 노드를 따로 둔다. talker도 「말을 거는 일만 하는 직원」.
- **왜 잘게 쪼개나**: 한 사람이 주문·요리·서빙·계산을 다 맡으면 그 사람이 쓰러지는 순간 식당 전체가 멈춘다.
  - 거대한 프로그램 하나: 카메라 처리가 어긋나면 바퀴 제어까지 멈춤.
  - 노드 단위 분리: 한 노드가 죽어도 나머지는 산다, 문제 노드만 골라 고치거나 다시 띄운다, 잘 만든 카메라 노드를 다른 로봇에 그대로 옮겨 끼운다. 운영체제의 **프로세스 격리**가 ROS에서 실용적으로 쓰이는 형태.
- **입도(granularity)**: 너무 굵으면 한 노드가 많은 일을 끌어안아 하나가 느려지면 다 느려지고, 너무 잘면 노드가 수백 개로 불어나 토픽 배선이 거미줄. 실전 기준 둘 — **한 문장으로 설명되는가**(접속사 "그리고"가 끼면 너무 굵다), **따로 교체·재사용할 단위인가**.
- **예 — 청소 로봇 다섯 노드**: 라이다(센서 값 읽기) / 지도(지도 그리기) / 길찾기(갈 길 정하기) / 바퀴(모터 굴리기) / 배터리(상태 알리기). 길찾기를 바꿔도 나머지 넷은 손대지 않는다.
- **이름**: 노드마다 이름이 있고, 같은 이름이 둘 떠 있으면 시스템이 혼란스러워한다 → 겹치지 않게. 실행 파일 이름(`turtlesim_node`)과 노드 이름(`/turtlesim`)은 다를 수 있다.
- **껐다 켜도 연결은 돌아온다**: 발행자를 Ctrl+C로 꺼도 구독자는 죽지 않고 새 메시지만 안 들어오며, 다시 띄우면 저절로 다시 받는다.
- **노드의 일생 세 단계**: 생성·설정(콜백 등록) → 콜백 반복(spin) → 종료·정리 (입문 1차시).

## 원리·구조
| 명령 | 보여 주는 것 |
|---|---|
| `ros2 node list` | 누가 살아 있는가 — 로봇을 켜고 가장 먼저 치는 청진기 |
| `ros2 node info /이름` | 발행·구독 토픽, 제공 서비스·액션 |

## 코드 예시
```bash
ros2 run turtlesim turtlesim_node
ros2 node list               # /turtlesim   ← 실행 파일 이름과 다르다
ros2 node info /turtlesim
ros2 run turtlesim turtlesim_node --ros-args -r __node:=my_turtle   # 노드 이름 바꿔 띄우기
```
```python
# 최소 노드: 이름을 가진 Node 하나를 만들고 spin
import rclpy
from rclpy.node import Node

def main():
    rclpy.init()
    node = Node('camera_publisher')     # 한 문장으로 설명되는 이름
    node.get_logger().info('카메라 노드 시작')
    rclpy.spin(node)
    node.destroy_node()
    rclpy.shutdown()
```
