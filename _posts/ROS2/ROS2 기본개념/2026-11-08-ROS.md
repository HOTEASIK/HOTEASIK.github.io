# ROS

## 정의·핵심
- **정의**: Robot Operating System. 이름과 달리 운영체제가 아니라 로봇 프로그램(노드)들을 **잇는 미들웨어(+도구 모음)** 다. 비유하면 **우체국** — 카메라 프로그램이 「나 지금 사람 봤어!」라는 편지를 우체국에 맡기면, 받고 싶은 프로그램들에게 우체국이 알아서 배달한다 (기초 3차시).
- **어느 층에 사나**: 펌웨어보다 위, 우리가 짜는 노드보다 아래. 정확히는 ROS2의 통신을 떠받치는 **DDS**가 미들웨어이고, ROS는 그 위에서 로봇 개발자가 쓰기 좋게 다듬은 한 겹.
- **통신은 ROS, 로직은 나** (입문 1차시): ROS는 통신·발견·재연결만 맡는다. "무엇을 보낼지"는 내가 짠다. 직접 짠 소켓 통신에서는 "어떻게 보낼지"에 노력이 거의 다 들어갔다.
- **이름만 같으면 된다**: 보내는 쪽은 「이 이름으로 보낼게」, 받는 쪽은 「그 이름 듣고 있을게」만 정한다. 서로의 IP도 존재도 몰라도 ROS가 연결한다 — 이 이름이 **토픽**.
- **ROS2는 프레임워크다**: 틀이 먼저 돌고, 나는 정해진 자리(콜백)에 코드를 끼워 넣는다. 메시지가 도착하면 ROS2가 등록해 둔 함수를 대신 부른다.
- **언제 ROS를 쓰나**: 노드가 여럿이고 서로 협력해야 할 때, 다른 사람과 코드를 주고받을 때. 센서 하나 읽어 숫자만 띄우는 스크립트·한 번 쓰고 버리는 실험에는 워크스페이스·패키지·빌드 비용이 더 클 수 있다.
- **생태계**: 잘 만든 패키지를 전 세계가 가져다 쓴다 — 길찾기는 Nav2, 로봇팔은 MoveIt 2. "바닥부터 전부 만들지 않는다"는 개발 기간과 비용을 좌우하는 경쟁력. 2024 ROS Metrics 기준 ROS2가 전체 다운로드의 약 72%.
- **함께 오는 도구**: RViz(시각화), rqt_graph(노드 연결도), Gazebo(시뮬레이터), ros2 bag(녹화·재생).

## 원리·구조
| 구분 | 내가 하는 일 | ROS2가 해 주는 일 |
|---|---|---|
| 통신 | 「무엇을 어떤 이름으로」 정한다 | 상대 찾기 · 전달 · 재시도 |
| 실행 | 노드의 콜백(할 일)을 짠다 | 콜백을 부르는 때를 관리 |
| 탐색 | 노드·토픽 이름을 짓는다 | 같은 이름끼리 자동으로 잇는다 |
```
 [우리가 짜는 노드]   카메라 노드 · 판단 노드 · 모터 노드
 [ROS2 (rclpy/rclcpp)]  노드·토픽·서비스·액션·파라미터 API
 [DDS 미들웨어]        발견 · 직렬화 · 전달 · QoS
 [OS: Ubuntu 24.04] → [하드웨어]
```

## 코드 예시
```bash
source /opt/ros/jazzy/setup.bash
ros2 run demo_nodes_cpp talker      # 터미널 A
ros2 run demo_nodes_py listener     # 터미널 B
```
