# TF2

## 정의·핵심
- **정의**: 시간에 따라 변하는 **좌표계(frame) 관계를 트리로 관리**하고, 한 좌표계의 점을 다른 좌표계 기준으로 변환해 주는 ROS2 표준 라이브러리 (실습 4차시, 기초 카페 컵 비유).
- **기준이 다르면 위치도 다르다**: 같은 컵이 「내 앞 30cm」(몸 기준), 「창가 테이블 위」(테이블 기준). 로봇도 map/world(방), base_link(몸통), 카메라·손끝(부품 자신)을 동시에 가진다. 카메라가 「컵이 내 앞 50cm」라 해도 잡으려면 손끝 기준으로 번역해야 한다 — 그 번역이 좌표 변환.
- **관계만 등록하면 중간을 이어 계산**: 좌표계들 사이 변환을 발행 → 「이 점을 저 기준으로」 물으면 → TF2가 트리에서 경로를 찾아 중간 변환을 곱한다. 삼각함수·행렬을 직접 안 짠다. base_link→camera_link를 직접 등록하지 않아도 중간 관계만 있으면 답한다.
- **왜 트리인가**: 각 좌표계는 **부모를 하나만** 가진다 → 임의의 두 좌표계 사이 경로가 늘 하나, 결과가 한 가지로 정해지고 「한 프레임은 한 발행자가 책임진다」.
- **시간도 변수**: 변환마다 타임스탬프를 달아 보관 → 「0.1초 전 시점의 변환」처럼 측정된 그 시점의 관계로 변환. tf2_echo의 `At time …`.
- **토픽**: `/tf`(움직이는 변환) · `/tf_static`(고정 변환).
- **TF 문제의 대부분은 수학이 아니라 발행하는 쪽의 문제**: 디버깅은 계산식이 아니라 발행 주체와 타임스탬프부터.
- **회전 표기**: 속으로는 쿼터니언(x, y, z, w) — 회전 없음은 (0, 0, 0, 1). 사람은 RPY로 적고 라이브러리로 바꿔 넣는다.

## 원리·구조
```
map
 └─ odom
     └─ base_link
         ├─ arm_link ── gripper_link
         └─ sensor ── camera
lookup(base_link → camera) = T(base_link→sensor) · T(sensor→camera)
```

## 코드 예시
```python
# TF2 흉내: 부모 링크만 등록, 두 프레임 사이 변환은 경로를 따라 곱한다 (이동만)
import numpy as np
parent = {"sensor": ("base_link", [1.0, 0, 0]), "camera": ("sensor", [0, 0, 0.2]),
          "base_link": ("odom", [2.0, 1.0, 0])}
def to_root(f):
    T = np.eye(4)
    while f in parent:
        p, xyz = parent[f]
        step = np.eye(4); step[:3, 3] = xyz
        T = step @ T; f = p
    return f, T
def lookup(target, source):
    r1, Tt = to_root(target); r2, Ts = to_root(source)
    if r1 != r2: return f"not part of the same tree ({r1} vs {r2})"
    return np.round((np.linalg.inv(Tt) @ Ts)[:3, 3], 3).tolist()
print(lookup("base_link", "camera"))   # [1.0, 0.0, 0.2]  ← 아무도 직접 발행하지 않았다
print(lookup("odom", "camera"))        # [3.0, 1.0, 0.2]
parent["map_x"] = ("map", [0, 0, 0])
print(lookup("base_link", "map_x"))    # not part of the same tree (odom vs map)
```

## 수업 메모

로봇의 다양한 부품(센서, 관절, 몸체 등)이 가지는 **서로 다른 좌표계(Frame) 간의 위치와 자세(변환 관계)를 시간에 따라 관리하고 계산**해 주는 ROS2의 표준 라이브러리.

### 왜 필요한가
카메라가 「컵이 내 앞 50cm」라고 알려 줘도, 팔이 잡으려면 손끝(또는 몸통) 기준으로 **번역**해야 한다. 이 번역이 좌표 변환(transform)이다. 관계만 등록하면 TF2가 중간을 이어 계산해 준다 — 삼각함수·행렬을 직접 계산하지 않는다.

| 좌표계 | 기준 |
|---|---|
| `map` / `world` | 방 전체 |
| `odom` | 주행 기록 원점 |
| `base_link` | 로봇 몸통 |
| `camera_link` 등 | 그 부품 자신 |

### 좌표계 트리
`map → odom → base_link → camera_link`
- 각 좌표계는 **부모를 하나만** 가진다 → 두 좌표계 사이 경로가 늘 하나로 정해진다
- 직접 등록하지 않은 두 프레임 사이도, 경로의 중간 변환을 곱해 답을 준다
- 설계 원칙: 한 프레임은 한 발행자가 책임진다

### 시간
변환마다 **타임스탬프**를 달아 보관한다 → 「0.1초 전 시점의 변환」처럼 측정 시점 기준으로 조회할 수 있다.

### static vs dynamic
| 구분 | 의미 | 예 | 발행 |
|---|---|---|---|
| static | 안 변하는 관계 | 몸통에 고정된 센서 | `static_transform_publisher` / `StaticTransformBroadcaster` → `/tf_static` (한 번) |
| dynamic | 계속 바뀌는 관계 | 바퀴, 관절 | `TransformBroadcaster` → `/tf` (주기 발행) |

- 변하는 관계를 static으로 내면 → 처음엔 맞다가 점점 어긋난다
- 안 변하는 관계를 dynamic으로 내면 → 불필요한 부하, 발행이 끊기면 조회 실패

### 명령어
```bash
ros2 run tf2_ros static_transform_publisher --x 1 --y 0 --z 0 \
  --frame-id base_link --child-frame-id sensor      # 부모 base_link, 자식 sensor 가 x 로 1m 앞
ros2 run tf2_ros tf2_echo base_link sensor           # 두 프레임 사이 변환 (Translation, Quaternion, RPY, 행렬)
ros2 run tf2_tools view_frames                       # 전체 트리를 PDF 그림으로
```

### 코드 (listener)
```python
from tf2_ros import Buffer, TransformListener, LookupException, ConnectivityException, ExtrapolationException

self._buffer = Buffer()
self._listener = TransformListener(self._buffer, self)   # /tf, /tf_static 을 들어 버퍼에 쌓음

def _lookup(self):
    try:
        tf = self._buffer.lookup_transform('base_link', 'sensor', rclpy.time.Time())  # 최신 변환
        tr = tf.transform.translation
    except (LookupException, ConnectivityException, ExtrapolationException):
        pass   # 아직 변환이 없거나 트리가 끊김
```
