# 문제

처음 `task_log`에는 **"결과(성공 여부, 시간)"만** 있었습니다.
모델은 `입력 → 결과`를 배우는 것이라, **"어떤 값으로 했는지(입력)"와 "얼마나 잘 됐는지(품질)"** 가 없으면 데이터를 아무리 모아도 최적값을 고를 수 없습니다.

# DB에 추가한 것

| # | 추가 | 위치 | 이유 |
|---|---|---|---|
| 1 | **그때 쓴 파라미터** (목표 힘, 강성, 속도, 도구, TCP) | `task_log.params` ← feedback `params_json` | yaml은 계속 바뀌므로 실행 시점 값을 같이 저장 |
| 2 | **품질 점수** 1~5, 작업 후 틈 깊이 | `quality` 테이블 (웹에서 입력) | 0/1 성공만으로는 "더 잘 된 값"을 못 고름 |
| 3 | **힘 요약** 평균·최소·최대·표준편차, **접촉 유지 비율** | `task_log.contact_ratio`, `force_stats` | 끝 값 1개로는 벽에서 떴는지 알 수 없음 |
| 4 | 시도 번호, 오류 코드 분리 | `task_log.attempt`, `error_code` | 재시도가 섞이면 통계 왜곡 |
| 5 | 실행 정보 (재료, 코드 버전, 실험/시연 구분) | `run` 테이블 | 다른 조건 데이터를 섞지 않도록 걸러냄 |

공정 담당자가 할 일은 feedback에 `params_json`, `force_stats`를 채우는 것뿐이 되도록 맞췄습니다.

# 분석 SQL

```sql
-- 파라미터 조합별 성공률·접촉 유지율·품질
SELECT t.params->>'$.target_fz' AS fz, t.params->>'$.vel' AS vel,
       COUNT(*) n, AVG(t.success) ok, AVG(t.contact_ratio) contact, AVG(q.score) score
FROM task_log t
JOIN run r ON r.run_id = t.run_id AND r.purpose = 'EXPERIMENT' AND r.material = 'clay'
LEFT JOIN quality q ON q.run_id = t.run_id AND q.gap_id = t.gap_id AND q.task_code = t.task_code
WHERE t.step = 'putty_scrape' AND t.attempt = 0
GROUP BY fz, vel ORDER BY score DESC;
```

표만 봐도 좋은 조합이 보입니다. 이것만으로도 "데이터 기반 파라미터 선정"의 근거가 됩니다.

# 처음 모델의 문제

| 문제 | 이유 |
|---|---|
| 성공(0/1)만 예측 | 27회면 대부분 성공 → 실패가 없으면 학습 불가 |
| 로지스틱 계수를 그대로 비교 | 목표 힘(≈−10)과 길이(≈100)는 단위가 달라 비교 불가 |
| 입력에 틈 길이 | 같은 틈으로 실험 → 값이 하나라 정보 없음 |
| 결정트리만 사용 | 조합 9개로는 경계만 찾고 최적값을 못 줌 |
| 검증 없음 | 모델이 맞는지 알 수 없음 |

# 바꾼 모델 (`analysis/train.py`)

| 출력 | 예측 대상 | 모델 | 조건 |
|---|---|---|---|
| 조합별 표 | — | SQL GROUP BY | 항상 |
| **최적 조합 (주 모델)** | `contact_ratio` (자동 측정, 연속값) | 2차 회귀(반응표면) `fz, vel, fz², vel², fz·vel` | 10개 이상 |
| 성공 확률 | `success` | 표준화 + 로지스틱 회귀 | 성공·실패 각 3개 이상 |
| 발표용 규칙 | `quality.score` | 결정트리 depth 2 | 5개 이상 |

- 입력은 목표 힘·속도 2개로 줄임
- 최적 조합: 실험 범위를 11×11 격자로 나눠 예측값이 최대인 점
- 검증: **LOO 교차검증 R²** — 0보다 커야 평균으로 찍는 것보다 나음
- 데이터가 부족하면 해당 모델은 "건너뜀"만 출력

# 실험 방법

1. 목표 힘 3단계 × 속도 3단계 × 3회 = **27회**, 아이클레이, **순서는 섞기** (도구 마모·재료 굳음 영향 분산)
2. 틈 종류 고정
3. `python3 analysis/train.py putty_scrape clay`
4. 최적 조합을 `robot.yaml`에 넣고 3~5회 → 기존 값과 접촉률·점수 비교
5. 최적이 범위 끝에 나오면 범위를 넓혀 재실험

# 검증 상태

- 가짜 데이터(최적 fz=−10, vel=50, 27개)로 전체 실행 → 최적 (−10.0, 50.0), **LOO R² 0.96**
- DB 컬럼 추가(migrate) 후 기록 테스트: params, contact_ratio, force_stats, attempt 정상 저장
