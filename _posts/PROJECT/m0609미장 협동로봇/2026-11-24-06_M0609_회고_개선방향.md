# 잘한 점

- 모든 공정을 **Action 양식 하나(`Process.action`)** 로 통일, 피드백 1번 = 로그 1줄
- **움직이기 전에 계산으로 검사** (IK, 특이점, J3 한계, FK 충돌 샘플링)
- 실측 알람 번호를 근거로 특이점 여유 각도를 수치화
- DB 끊김 시 로컬 보관 후 재전송, `git describe`로 코드 버전 기록
- 가짜 DB·가짜 Action 서버로 **로봇 없이 전체 공정 테스트**
- 실로봇에서 탐색 → 내부 탐색 → 퍼티 → 샌딩 **끝까지 연속 동작**

# 받은 피드백

- 라이다·비전 활용, 비전과 순응·힘제어를 같이 응용
- 이동(모바일) 구현
- 퍼티 교반, 점성 확인
- **정량적인 벽체 탐지 기준** (조명 조건 + 수식 + 정답 데이터)
- 무게·높이 조건 추가
- 실행 시간 개선

→ 공통적으로 "동작은 하는데, **얼마나 정확한지 숫자로 보여 달라**"는 의미로 받아들였습니다.

# 개선 방향 (노력 대비 효과 순)

| 순서 | 할 일 | 기대 |
|---|---|---|
| 1 | HMI 접근 제어(토큰), 요청 형식 검사, 속도 상한, 비밀번호를 설정 파일에서 분리 | 보안·안전 |
| 2 | 브랜치 규칙 `feat/<기능>`, 머지 후 삭제, 발표 전 develop → main 릴리스 + 태그 | 협업 |
| 3 | 공통 `dsr_client`(타임아웃 있는 서비스 호출) + `ROBOT_ID` 한 곳에서 정의 | 모듈화·두산 API |
| 4 | 전체 시스템을 띄우는 launch 1개 + 설계 문서 갱신 | 구조·문서 |

# 다음 프로젝트에서 먼저 할 것

1. **1일차에 인터페이스 계약** (Action·토픽 이름, 필드, 오류 코드)을 문서로 확정하고 인터페이스 패키지는 한 사람이 관리
2. **계층 분리**: HMI(화면) / 매니저(순서) / Skill(단위 동작) / 드라이버
3. 공정은 **Behavior Tree**처럼 성공·실패·재시도를 명시적으로
4. **안전 계층 먼저**: 하드웨어 비상정지 운용, 한계값, 정지 경로 이중화
5. 정량 평가 기준을 미리 정하고 정답 데이터 수집 (피드백 반영)
6. AI(LLM·VLA)는 그 위에 **계획자**로만 얹기

> 핵심: 기반 계층(ROS 2, Skill, 실행 흐름, 안전)을 먼저 단단하게 만들고, 기능과 AI는 그 위에 얹는다.
