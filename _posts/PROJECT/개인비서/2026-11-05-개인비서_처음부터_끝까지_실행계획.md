# 개인 비서 만들기: 처음부터 끝까지 실행 계획

환경 확인부터 개인 문서 검색, 스킬 적용, 선택적 파인 튜닝까지 순서대로 정리한 실행 계획.

## 목표와 현재 조건

- 실행 환경: Windows + Docker Desktop + WSL2 Linux 컨테이너
- GPU: NVIDIA GeForce RTX 3060 Ti, VRAM 8GB
- 언어 모델: Python에서 Transformers로 실행
- 개인 문서: 질문과 관련된 부분을 검색해 답변에 제공
- 말투/행동: Markdown 스킬 지침을 먼저 적용
- 파인 튜닝: 지침만으로 해결되지 않는 반복 행동이 발견될 때 LoRA/QLoRA SFT를 진행

### 설계 선택

개인 문서를 모델 가중치에 통째로 넣는 대신 검색(RAG)으로 연결합니다. 문서가 수정될 때 재학습할 필요가 없고, 답변 근거를 원문에서 찾기 쉽습니다. 말투와 행동 규칙은 먼저 system 지침으로 관리합니다. 규칙만으로 일관성이 부족한 반복 행동을 고품질 대화 예시로 만들었을 때에만 파인 튜닝합니다.

RTX 3060 Ti 8GB에서는 학습 중 가중치 외에 활성화값, 작업 공간, 디스플레이가 VRAM을 사용합니다. 우선 0.6B급 작은 모델로 전체 파이프라인을 확인하고, 한국어 품질이 부족할 때에만 1B~2B급 후보를 시험합니다. QLoRA 4-bit, batch 1, 짧은 시퀀스 길이로 시작하되 성공 가능한 설정이라고 보장하지 않으며, 실제 VRAM 사용에 따라 모델/시퀀스 길이를 낮춥니다.

## 전체 흐름

```text
Docker/WSL2/GPU 확인
        ↓
Python 컨테이너와 기본 추론 확인
        ↓
개인 문서 검색(RAG) + Markdown 스킬 지침
        ↓
질문 평가표로 부족한 점 확인
        ↓ 필요한 경우에만
대화 예시(JSONL) → LoRA/QLoRA SFT
        ↓
전/후 비교 → 보존 및 일상 사용
```

## 0단계: 준비물과 프로젝트 위치 정하기

### 확인할 항목

- Docker Desktop을 실행할 수 있는지
- Windows에서 WSL2가 사용 가능하고, Docker Desktop이 WSL2 backend를 쓰는지
- NVIDIA 드라이버가 설치되어 있는지
- 여유 시스템 메모리 및 디스크 공간
- 개인 문서의 총량과 포함된 민감정보

### 사용자 작업

Docker Desktop을 열고 Linux containers 모드인지 확인합니다. Docker Desktop 설정에서 WSL2 backend가 켜져 있는지도 확인합니다. 이 계획서의 명령은 PowerShell에서 실행하는 예시입니다.

이 프로젝트의 문서와 이후 코드는 다음 폴더를 기준으로 둡니다.

```text
C:\Users\adg61\Desktop\OpenAI\work1_개인비서
```

코드 작성 단계에서는 개인 문서, 모델 가중치, 학습 산출물이 Git에 들어가지 않도록 `.gitignore`를 설정합니다. 모델 파일과 원본 문서는 용량이 크거나 개인 정보가 포함될 수 있습니다.

**완료 조건:** Docker Desktop이 실행 중이고 WSL2 backend가 활성화되어 있으며, 프로젝트에 쓸 문서 위치를 정했습니다.

## 1단계: Docker 컨테이너에서 GPU 확인

PowerShell에서 아래 Docker 공식 GPU 예시를 실행합니다.

```powershell
docker run --rm --gpus=all nvcr.io/nvidia/k8s/cuda-sample:nbody nbody -gpu -benchmark
```

**성공 기준:** 명령이 끝나고 NVIDIA GPU 장치 및 벤치마크 실행 결과가 출력됩니다.

**실패 시:** 오류 전문을 기록하고 여기서 멈춥니다. Docker Desktop WSL2 backend, Linux containers 모드, WSL2 상태, NVIDIA 드라이버/GPU passthrough를 순서대로 점검합니다. GPU가 컨테이너에서 확인되기 전에는 모델이나 학습 패키지를 설치할 필요가 없습니다.

참고로 이전 점검에서 현재 작업 터미널의 `wsl --status`가 `E_ACCESSDENIED`를 반환했고 `docker` 명령을 찾지 못했습니다. 사용자는 Docker를 사용할 수 있다고 알려주셨지만, 이 작업 터미널에서 Docker 실행 가능 여부는 확인되지 않았습니다. 사용자 PC에서 명령이 실행되는지 확인하는 단계가 필요합니다.

**완료 조건:** Docker에서 RTX 3060 Ti가 보입니다.

## 2단계: Python 개발 컨테이너 구성

GPU 확인이 성공하면 프로젝트 코드를 추가합니다. 권장 구성은 다음과 같습니다.

```text
work1_개인비서/
  Dockerfile
  compose.yaml
  requirements.txt
  .gitignore
  app/
    main.py                 # 대화 입력, 지침/검색 결과 조립, 생성
    retrieval.py            # 개인 문서 검색
  skills/
    persona.md              # 말투와 공통 행동 규칙
  data/
    private_docs/           # 원본 Markdown 문서
    train/                  # 선택적 SFT용 JSONL
    eval/                   # 평가용 질문과 기준
  models/                   # 내려받은 모델 파일
  outputs/                  # 체크포인트와 평가 결과
```

`Dockerfile`에는 Linux, Python 및 호환되는 PyTorch/CUDA/Transformers 패키지를 구성합니다. `compose.yaml`은 GPU 접근과 `data`, `models`, `outputs`의 볼륨 마운트를 담당합니다. 정확한 버전과 CUDA 조합은 이 단계에서 공식 설치 지침 및 상호 호환성을 확인한 뒤 정합니다. 패키지를 한꺼번에 최신 버전으로 바꾸지 말고 정상 동작한 의존성 버전을 기록합니다.

**완료 조건:** 컨테이너 안에서 Python과 PyTorch가 실행되고 PyTorch가 CUDA 장치를 인식합니다.

## 3단계: 기반 모델 선택 및 기본 응답 확인

### 선택 기준

1. Transformers에서 사용할 수 있는 Hugging Face 형식인지 확인합니다.
2. 한국어 대화 품질과 chat template이 적합한지 확인합니다.
3. 모델 카드에서 라이선스, 제한, 모델 사용법을 읽습니다.
4. 모델 가중치를 내려받을 디스크 공간을 확인합니다.

첫 파이프라인 확인용으로 Qwen3-0.6B 계열을 후보로 둘 수 있습니다. 작고 Apache 2.0 라이선스로 공개되어 있지만, 0.6B 모델이 원하는 한국어 품질을 낼 것이라는 보장은 없으므로 시험 기준 모델로 취급합니다. 더 좋은 답변이 필요하면 1B~2B 후보를 비교하되, 8GB VRAM에서 학습 가능 여부는 시험 설정과 실제 메모리 여유로 판단합니다.

### 기본 추론 점검

- 모델과 토크나이저를 함께 로드합니다.
- 모델에 포함된 chat template으로 user/assistant 메시지를 구성합니다.
- 한국어 질문, 모르는 정보에 대한 대응, 긴 답변/짧은 답변 요청 등 대표 입력을 시험합니다.
- 기본 답변과 생성 설정을 저장해 추후 비교 기준으로 삼습니다.

**완료 조건:** 컨테이너에서 질문을 넣고 모델 응답을 받을 수 있으며, 대표 질문과 답변이 기록되어 있습니다.

## 4단계: 개인 문서 검색(RAG) 구성

### 문서 준비

1. 개인 문서 원본을 `data/private_docs/` 아래에 복사합니다.
2. 개인정보, 자격 증명, 공개하면 안 되는 내용을 검토합니다.
3. 원본은 보존하고, 검색 대상으로 삼을 파일만 선택합니다.
4. 문서의 제목과 출처 경로가 결과에 유지되도록 합니다.

### 색인 및 검색

1. Markdown 제목/문단 구조를 읽습니다.
2. 긴 문서는 제목과 문맥을 보존하며 문단 경계를 우선해 나눕니다.
3. 각 조각에 원본 파일명과 제목 경로를 메타데이터로 붙입니다.
4. 검색용 임베딩을 만들고 로컬 인덱스에 저장합니다.
5. 질문에 가까운 조각만 검색해 모델 입력에 넣습니다.
6. 답변에 근거 문서의 파일명/제목을 표시하도록 system 지침을 둡니다.

처음부터 고정 청크 길이를 정답으로 여기지 말고, 실제 대표 질문에서 올바른 문단이 검색되는지 확인한 뒤 크기와 겹침을 조정합니다. 인덱스는 다시 생성할 수 있어야 하며, 원본 문서와 분리해 보관합니다.

### 평가

개인 문서에서 답을 찾을 수 있는 질문과, 문서에 답이 없는 질문을 모두 만듭니다. 검색된 출처가 맞는지, 답이 출처 내용과 일치하는지, 모르는 경우 모른다고 하는지 확인합니다.

**완료 조건:** 대표 질문에서 관련 근거가 검색되고, 답변이 근거에 맞으며, 출처를 확인할 수 있습니다.

## 5단계: 말투·행동 스킬 Markdown 작성

`skills/persona.md`를 만들고 다음 항목을 짧고 검증 가능한 규칙으로 작성합니다.

- 비서의 역할과 한국어 말투
- 기본 답변 길이와 구조
- 확실하지 않은 내용이나 자료에 없는 내용을 다루는 법
- 모호하거나 중요한 결정이 필요한 경우 사용자에게 질문하는 규칙
- 개인 문서 인용/출처 표시 규칙
- 사용자 허가 없이 파일/앱/외부 서비스에 행동하지 않는 규칙
- 좋은 응답과 피해야 할 응답 예시

Python 대화 코드가 이 문서를 읽어 system 지침으로 전달합니다. 개인 질문에 따라 여러 스킬을 쓸 때는 관련된 문서만 골라 입력에 넣습니다. 사용자가 내용을 쉽게 고칠 수 있도록 Markdown을 원본으로 유지합니다.

**완료 조건:** 스킬 지침을 적용한 응답이 테스트 질문에서 말투와 행동 규칙을 따릅니다.

## 6단계: 파인 튜닝이 필요한지 판단

기본 모델 + 검색 + 스킬 지침으로 고정 평가 질문을 돌립니다. 다음과 같은 실패가 반복될 때 파인 튜닝을 고려합니다.

- 같은 지침을 반복해서 어김
- 특정 응답 형식이나 반복 절차를 일관되게 지키지 못함
- 충분한 검색 근거와 지침을 입력했는데도 같은 종류의 문제를 반복함

문서 지식을 잘못 답하는 문제가 주된 경우에는 파인 튜닝보다 검색 품질, chunk 구조, 프롬프트에 들어간 근거를 먼저 고칩니다. 훈련은 검색 시스템의 최신 문서 갱신을 대신하지 않습니다.

**완료 조건:** 학습으로 바꾸려는 반복 행동이 평가 기록에 구체적으로 적혀 있습니다. 개선할 문제가 없다면 파인 튜닝을 생략해도 프로젝트 목표를 달성한 것으로 봅니다.

## 7단계: 파인 튜닝 데이터 작성

파인 튜닝을 선택한 경우에만 `data/train/`에 JSONL 대화 자료를 작성합니다. 한 줄에 하나의 JSON 객체를 둡니다.

```json
{"messages":[{"role":"user","content":"문서에 없는 내용인데 답을 만들어줘."},{"role":"assistant","content":"확인할 자료에 해당 내용이 없어 단정할 수 없어요. 관련 문서나 정보를 알려주시면 확인할게요."}]}
{"messages":[{"role":"user","content":"이 메모를 정리해줘."},{"role":"assistant","content":"핵심 내용과 다음 할 일을 나눠 정리할게요. 메모를 보내주세요."}]}
```

- 학습 예시는 원하는 행동을 실제로 보여주는 간결하고 일관된 대화로 작성합니다.
- 개인 문서의 정답 내용을 외우게 하는 데이터와 행동 예시는 구분합니다. 개인 사실은 검색 인덱스에 둡니다.
- 중복, 오탈자, 상충 규칙, 공개하면 안 되는 정보는 제거합니다.
- 비슷한 예시가 학습/검증 양쪽에 동시에 들어가지 않도록 주제나 원문 단위로 분리합니다.
- 검증 데이터는 학습에 쓰지 않고, 일정한 평가 질문은 별도 보관합니다.

## 8단계: LoRA/QLoRA 소규모 학습

### 시작 원칙

- 기반 모델의 정확한 이름/버전을 기록합니다.
- QLoRA 4-bit와 LoRA 어댑터를 이용해 전체 가중치 대신 일부 파라미터를 학습합니다.
- batch size 1과 짧은 sequence length(예: 512 tokens)로 시작합니다.
- gradient checkpointing을 검토하고, 첫 실행은 짧은 단계로 제한합니다.
- GPU 메모리 오류가 나면 sequence length/모델 크기를 낮추고, 데이터 양을 늘리기 전에 원인을 확인합니다.
- 학습 전 체크포인트와 설정을 기록하고, 출력은 `outputs/`에 따로 저장합니다.

8GB VRAM은 모든 모델/설정에 충분하지 않습니다. 모델이 로드되어도 역전파 중 메모리 부족이 발생할 수 있습니다. 먼저 작은 설정이 끝까지 학습되는지 확인하고 실제 `nvidia-smi` 사용량을 기준으로 조정합니다.

**완료 조건:** 컨테이너에서 소규모 학습이 종료되고, LoRA 어댑터 및 학습 설정이 저장됩니다.

## 9단계: 모델/검색/스킬을 Python 비서에 연결

대화 한 번의 처리 흐름은 다음과 같이 구성합니다.

1. 사용자 메시지를 받습니다.
2. 질문과 관련된 개인 문서 조각을 검색합니다.
3. 공통 system 지침과 관련 스킬 지침을 구성합니다.
4. 검색 근거를 출처와 함께 입력에 포함합니다.
5. 기반 모델을 불러오고, 파인 튜닝을 선택했다면 기반 모델과 LoRA 어댑터를 함께 적용합니다.
6. 모델의 chat template으로 메시지를 직렬화해 생성합니다.
7. 답변과 참조한 문서 출처를 사용자에게 보여줍니다.

파일 읽기/쓰기나 앱 실행 같은 기능은 언어 모델 학습만으로 제공되지 않습니다. 나중에 그런 기능이 필요하면 각 작업의 권한과 사용자 확인 규칙을 갖춘 별도 도구 코드로 구현합니다.

## 10단계: 품질 평가와 보존

### 같은 질문으로 비교

다음 세 구성을 같은 질문으로 비교합니다.

| 구성 | 확인할 점 |
|---|---|
| 기본 모델 | 한국어 기본 능력과 시작 품질 |
| 기본 모델 + 검색 + 스킬 | 프로젝트 기능을 반영한 품질 |
| 파인 튜닝 모델 + 검색 + 스킬 | 반복 행동이 실제로 개선됐는지, 다른 응답이 나빠지지 않았는지 |

평가 항목은 근거 정확성, 출처 일치, 모르면 질문/유보하는 행동, 말투, 형식 준수, 응답 속도, VRAM 사용량으로 둡니다. 한두 개의 좋은 예시만 보고 판단하지 말고 성공/실패 사례 모두 기록합니다.

### 보존할 정보

- 기반 모델의 출처, 버전, 라이선스
- 학습 데이터 버전과 평가 질문
- 컨테이너/Dockerfile 및 Python 의존성 버전
- LoRA 설정과 학습 로그
- 최고 결과 어댑터와 최종 비교 기록
- 문서 검색 인덱스를 다시 만들 방법

데이터와 모델을 Git에 추가하지 않도록 `.gitignore`를 확인합니다. 중요한 체크포인트는 별도 백업 위치에 복사합니다.

## 완료 기준

- Docker 컨테이너가 RTX 3060 Ti GPU를 인식합니다.
- 선택한 기반 모델이 Python에서 응답합니다.
- 개인 문서 질문에서 관련 근거와 출처가 나옵니다.
- Markdown 스킬 지침이 대화에 적용됩니다.
- 파인 튜닝을 했다면, 고정 질문 비교에서 기대한 반복 행동이 개선됐는지 확인할 수 있습니다.
- 설정과 결과를 다시 재현할 수 있도록 기록했습니다.

## 현재 상태와 다음 순서

- 계획서 및 관련 설명 문서는 작성되어 있습니다.
- 컨테이너 GPU 점검은 사용자가 실행합니다.
- GPU 점검이 성공하면 다음 작업 순서는 **Dockerfile/compose 설정 작성 → PyTorch CUDA 확인 → 작은 모델 기본 추론**입니다.
- 현재 단계에서 모델이나 패키지를 다운로드하거나, WSL/Docker 설정을 변경할 필요는 없습니다.
