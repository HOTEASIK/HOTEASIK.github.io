# Docker/WSL2 실행 환경 계획

## 선택한 경로

Windows의 Docker Desktop에서 **WSL2 backend를 사용하는 Linux 컨테이너**로 Python 학습과 추론을 실행합니다. 프로젝트 의존성을 컨테이너에 고정할 수 있고, Windows Python 환경과 분리해 관리하기 쉽습니다. Docker Desktop의 NVIDIA GPU passthrough는 WSL2 backend를 필요로 합니다. [Docker GPU 지원 안내](https://docs.docker.com/desktop/features/gpu/) · [Docker WSL 안내](https://docs.docker.com/desktop/features/wsl)

RTX 3060 Ti (8GB VRAM)가 컨테이너 안에 보이는지 확인하기 전에는 모델 학습을 진행하지 않습니다. RTX 3060 Ti의 시스템 VRAM이 자동으로 늘어나는 것은 아니며, Docker도 8GB 한도를 바꾸지 않습니다.

## 이 경로에 필요한 조건

- Docker Desktop이 실행 중이고 Linux containers 모드여야 합니다.
- Docker Desktop에서 WSL2 backend가 활성화되어야 합니다.
- Windows와 WSL2 커널, NVIDIA 드라이버가 GPU passthrough를 지원하는 상태여야 합니다.
- Docker 명령이 PowerShell 또는 통합된 WSL 터미널에서 실행되어야 합니다.
- 컨테이너에서 NVIDIA GPU가 보여야 합니다.

Docker 문서가 안내하는 GPU 컨테이너 예시 명령은 다음과 같습니다. 먼저 환경 확인 용도로 실행하고, 출력에서 GPU가 표시되는지 봅니다.

```powershell
docker run --rm --gpus=all nvcr.io/nvidia/k8s/cuda-sample:nbody nbody -gpu -benchmark
```

이 명령은 Docker의 공식 GPU 확인 예시입니다. 실제 프로젝트 Dockerfile의 PyTorch/CUDA 조합은 모델과 패키지 호환성을 정한 뒤 선택합니다. Docker가 `--gpus=all`을 거부하거나 컨테이너에서 GPU가 보이지 않으면, 학습 패키지 설치보다 Docker Desktop/WSL2 GPU 연결을 먼저 해결합니다.

## 예정 프로젝트 구조

```text
work1_개인비서/
  Dockerfile                 # Python/Linux 및 프로젝트 패키지
  compose.yaml               # GPU, 볼륨 마운트, 실행 설정
  requirements.txt           # Python 의존성 버전
  app/                       # Python 추론 및 검색 연결 코드
  training/                  # 데이터 변환 및 LoRA SFT 코드
  skills/                    # 말투/행동 Markdown 지침
  data/private_docs/         # 개인 문서 원본, Git 제외
  data/train/                # 정제된 대화형 JSONL, Git 제외
  models/                    # 내려받은 원본 모델, Git 제외
  outputs/                   # 체크포인트와 평가 결과, Git 제외
```

실제 폴더/코드 파일은 데이터 구조와 개인정보 보관 방식을 합의한 뒤 필요한 만큼만 만듭니다. 특히 `data/`, `models/`, `outputs/`는 저장 공간이 커질 수 있으므로 Git에 추가하지 않도록 `.gitignore`를 설정합니다.

## 진행 단계

1. Docker Desktop/WSL2에서 GPU가 보이는지 확인합니다.
2. 학습 스크립트보다 먼저 작은 컨테이너에서 Python과 PyTorch의 CUDA 인식을 확인합니다.
3. 작은 기반 모델을 내려받고 기본 추론을 확인합니다.
4. Markdown 개인 문서를 검색 인덱스에 넣고 출처가 포함된 검색 결과를 확인합니다.
5. `skills/` 문서를 system 지침으로 넣어 대화 동작을 확인합니다.
6. 파인 튜닝이 필요한 반복 행동 예시만 JSONL로 준비합니다.
7. 짧은 QLoRA 학습을 실행하고 VRAM 사용량, 손실, 고정 질문 평가를 확인합니다.
8. 결과가 나아진 경우에만 학습 규모를 늘립니다.

## 현재 확인 상태

현재 Codex 작업 세션에서 `nvidia-smi`는 RTX 3060 Ti, 8192 MiB를 보고했습니다. 그러나 `wsl --status`는 `E_ACCESSDENIED`를 반환했고, 현재 PowerShell에서 `docker` 명령을 찾지 못했습니다. 사용자는 Docker와 가상환경 사용이 가능하다고 알려주셨으므로 Docker가 설치되어 있을 수 있지만, 이 터미널에서 실행되는지는 아직 확인되지 않았습니다.

이 확인 결과는 Docker 자체가 설치되지 않았다는 뜻이 아닙니다. GPU 컨테이너 실행을 확인하기 전에는 Windows/WSL 설정을 변경하거나 이미지/모델을 내려받지 않았습니다.
