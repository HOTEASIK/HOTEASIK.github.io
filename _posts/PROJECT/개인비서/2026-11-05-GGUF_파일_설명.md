# GGUF 파일이란?

## 간단히 말하면

GGUF는 `llama.cpp` 계열 실행 엔진이 모델 추론에 사용하는 모델 파일 형식입니다. 흔히 `.gguf` 확장자 파일 하나(또는 일부 모델의 여러 분할 파일)로 배포되며, 가중치와 토크나이저/모델 메타데이터를 담을 수 있습니다. 파일에 따라 정밀도를 낮춘 양자화가 적용되어 용량과 메모리 사용량이 줄어들 수 있습니다.

GGUF는 **학습 데이터 파일이 아니며**, Hugging Face 모델 폴더와 같은 것이 아닙니다. `llama.cpp`는 GGUF를 요구하고, 다른 형식은 호환되는 변환 절차가 필요합니다. [llama.cpp 모델 문서](https://github.com/ggml-org/llama.cpp/blob/master/docs/models.md) · [GGUF 사양 안내](https://github.com/ggml-org/ggml/blob/master/docs/gguf.md)

## 파인 튜닝과의 관계

권장 흐름은 Hugging Face 형식의 기반 모델에서 LoRA/QLoRA로 학습하고, Python/Transformers에서 결과를 먼저 확인하는 것입니다. 필요할 때 결과를 GGUF로 내보내어 `llama.cpp` 등 호환 엔진에서 실행합니다.

- 일부 워크플로는 LoRA 어댑터를 변환할 수 있지만, 지원 모델 아키텍처와 변환 도구 버전을 확인해야 합니다.
- 어댑터만 내보내는 방식과 기반 모델에 병합한 뒤 내보내는 방식은 파일 구성과 실행 호환성이 다릅니다.
- 변환 후에는 토크나이저, 대화 템플릿, 종료 토큰, 양자화에 따른 품질을 확인해야 합니다.
- GGUF를 곧바로 Python의 `transformers.AutoModelForCausalLM.from_pretrained()` 입력으로 쓸 수 있다고 가정하지 마세요. 보통 Transformers용 폴더와 GGUF 실행 경로는 서로 다른 로더를 사용합니다.

## 양자화란?

가중치를 더 낮은 비트 수의 표현으로 저장해 크기와 메모리 사용을 줄이는 과정입니다. 줄어드는 정도와 품질 영향은 모델 및 양자화 방식에 따라 다릅니다. “Q4”처럼 이름만 보고 결과를 확정하지 말고, 목표 컴퓨터에서 실제 응답 속도와 답변 품질을 비교해야 합니다.

## 이 프로젝트에서의 권장 시점

1. Hugging Face 체크포인트로 Python 추론이 되는지 확인합니다.
2. 파인 튜닝 전후의 답변 품질을 비교하고 최종 체크포인트를 보존합니다.
3. 별도 실행 엔진/배포가 필요할 때만, 해당 엔진이 지원하는 모델과 변환 도구를 확인합니다.
4. 원본 체크포인트를 덮어쓰지 않고 별도 출력 폴더로 변환합니다.
5. GGUF 실행 결과를 Python 기준 답변과 비교합니다.
